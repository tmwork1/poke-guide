# 委任テンプレート

委任先は `codex` skill を優先する(`.claude/skills/codex/SKILL.md`)。Windows では `--sandbox danger-full-access` + Bash tool の `dangerouslyDisableSandbox: true` が必須。**プロンプトはスクラッチパッドにファイルで書き出してから `PROMPT="$(cat …)"` で渡す。**

**委任するかは規模で判断する。** 原因が既知で1ファイル・数行に閉じるならCoordinatorが直接直す。

---

## 全テンプレート共通で必ず入れる禁止事項

```
## 絶対に守ること

- **`git commit` / `git push` は絶対にしない。** 変更はワーキングツリーに残すだけでよい。
- **`npm run dev` の画面をクリック・入力する検証は絶対にしない。** `/box/[id]` `/team/[id]` は
  入力・クリックで自動保存が走り、実データを破壊した事故が過去にある。検証は `npx astro build` と、
  操作オプションを付けない `npm run probe -- --page <path> --cls`(読むだけ)に限ること。
- **指定していないファイルは編集しない。** 「参考に」と挙げたファイルを書き換えない。
- スタイルは必ず `src/styles/` 配下の対象別CSSファイルに書く。`.astro` の `style` 属性や
  コンポーネント内の新しい `<style>` は禁止(ルート `CLAUDE.md`「スタイル定義」)。
- **見た目を変えない。揺れを消すために要素を小さくしたり、タップ領域を縮めたりしない。**
- `prefers-color-scheme` 分岐を新規に足さない(2026-09-10にダーク一本化済み)。
- 既存コメントに書かれた設計意図(「〜のため変えない」等)を壊さない。
```

## 委任後にCoordinatorがやること

1. `--output-last-message` のファイルを読む(**報告を鵜呑みにしない**)
2. `git status` で**担当外ファイルの差分が無いか必ず確認する**(→ `feedback_codex_reference_file_scope_creep`)
3. `git diff` を読み、「変えない」と書かれた既存コメントを壊していないか確認する(→ `feedback_verify_fix_against_design_intent_comments`)
4. **修正前と同じ probe コマンドで再計測**して、スコアと移動量の両方が改善したことを確認する
5. `npm run shot` で見た目が変わっていないことを確認する
6. `npx astro build` を通す
7. `docs/stabilize/dashboard.md` を更新して Coordinator が commit する
