## 運用上の注意

### エージェントが落ちたとき
APIエラーで停止することがある。**sonnet Agent toolの場合**: `SendMessage` での再開は失敗することがある(`No transcript found`)ので、その場合は再起動する。**codexの場合**: `codex exec resume --last` で再開する(`.claude/skills/codex/SKILL.md`「落ちた・止まったとき」参照)。再開/再起動時は:
1. **後片付けを自分でやる**(残ったテストデータの削除、一時ファイルの削除、`npm run build` が通るかの確認)
2. 新しいエージェントに「**前任者が途中まで実装して中断している。自分でファイルを読んで対応済み/未対応を確認してから始めること**」と伝える
3. **grepは「着手したかどうか」の目安にはなるが、完成/未完成の判定には使えない**(過去のUI改善作業で2回誤判定した実績がある)

### 新規作成に特有の注意
- **マイグレーションを適用した後で設計を変えると、追加のマイグレーションが要る。** だからP1の仕様確定とP2の設計レビューをスキップしない。
- **基盤(スキーマ・型)を並列にしない。** APIとページが違う型を前提に書いて必ず衝突する。
- 大きな構造(ページ全体のレイアウト)は分割せず1体に任せる。関連する小さい要件も同じエージェントにまとめ、「途中で `npm run build` を通しながら進めてください」と添える。
