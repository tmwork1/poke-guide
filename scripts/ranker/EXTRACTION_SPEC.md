# 構築記事からの個体情報 抽出仕様

ポケモンの構築記事から、各個体の **性格 / 特性 / 技 / 努力値 / テラスタイプ** を読み取り、
1記事1つのJSONファイルとして書き出す。

## 手順

1. `tasks/<KEY>.md` を Read する。
2. 本文から個体情報を読み取る。
3. `llm/<KEY>.json` を Write する（下記スキーマ）。

## 出力スキーマ

```json
{
  "key": "<KEY>",
  "has_content": true,
  "members": [
    {
      "roster_index": 1,
      "nature": "ようき",
      "ability": "てきおうりょく",
      "tera_type": null,
      "moves": ["インファイト", "コメットパンチ", "ストーンエッジ", "しんそく"],
      "evs": [2, 27, 9, 0, 0, 28],
      "evs_note": "HB:リザードンのニトロチャージ耐え / S:準速マスカーニャ抜き",
      "confidence": "high"
    }
  ],
  "note": "個体情報が画像のみで本文に無い、等の特記事項"
}
```

## 厳守するルール

**1. 推測で埋めない。** 記事に書かれていない項目は必ず `null`（技は `[]`）。
「このポケモンならふつうこの性格」といった一般常識での補完は**禁止**。
それらしい値を入れるより、`null` のほうが常に正しい。

**2. 6体はタスクファイルの「このチームの6体」が正。**
記事の表記がメガ名（メガルカリオ）でも、韓国語（메가루카리오）でも、略称（ルカ）でも、
必ずリストの何番かを判断して `roster_index`（1〜6）で答える。
どれか判断できない記述は members に入れない。リストに無いポケモン（没個体・仮想敵）は無視する。
情報が1つも取れなかった個体は members から省いてよい（6体そろえる必要はない）。

**3. 努力値はチャンピオンズのスケール（各項目 0〜32・合計66）。**
`evs` は `[HP, 攻撃, 防御, 特攻, 特防, 素早さ]` の6要素の配列。
- 6項目すべてが数値で読み取れて、各値が 0〜32 のときだけ配列で入れる。
- 「H4 A252 S252」のように 32 を超える数値（旧作の252スケール）で書かれていたら、
  換算せずに `evs: null` とし、原文を `evs_note` に残す。
- 「HBぶっぱ」「S準速」のような数値でない調整意図は `evs: null` + `evs_note` に原文を残す。
- 一部の項目しか書かれていない場合も `evs: null` + `evs_note`。

**4. 技・性格・特性・テラスは日本語の正式名称に正規化する。**
- 性格: ようき / いじっぱり / ひかえめ / おくびょう / ずぶとい / わんぱく / しんちょう / おだやか /
  さみしがり / やんちゃ / ゆうかん / のうてんき / のんき / おっとり / うっかりや / れいせい /
  おとなしい / なまいき / せっかち / むじゃき / まじめ
- テラスタイプ: ほのお / みず / くさ ... の18タイプ表記（記事に記載が無ければ null）
- 略称は正式名に直す（例: 「襷」→ 持ち物なので対象外、「珠」→ 対象外、
  「地震」→「じしん」、「羽休め」→「はねやすめ」、「大文字」→「だいもんじ」）。
- 韓国語・英語の記事は日本語の正式名称に訳す。確信が持てない訳は入れず `null` にする。

**5. 持ち物は抽出しない**（公式ランキング側に正確な値があるため）。

**6. confidence の付け方**（個体ごと）
- `high`: 表やリストで項目が明示されている
- `medium`: 本文の散文から読み取れるが書式が崩れている
- `low`: 断片的でかなり解釈が入っている

**7. 本文に個体情報が無い記事**（画像だけ、Xのツイート、YouTube、本文が空 等）は
`{"key": "...", "has_content": false, "members": [], "note": "理由"}` を書く。
これは失敗ではなく正常な結果。無理に埋めないこと。

**8. `git` コマンドは一切実行しない**（commit / push を含む）。ファイルの Read と Write のみ。
