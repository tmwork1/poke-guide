**`docs/plan/ui_rounds/round-21.md` の「積み残し」節を読むこと。** ラウンド19以前の積み残しは `round-19.md` の同名の節(ユーザー判断待ち3件を含む)。

**最優先の未対応は次の2つ:**
1. 🔴 **空ボディの `PUT /api/owned-pokemon/:id` が個体を全消去する**(→ round-21.md「実装中に見つかったバグ」)。**修正方針が3案あり、どれを採るかで意味が変わるのでユーザー判断が要る。**
2. **コントラストの基底不足3件** — `.btn-danger` 2.82:1 / `.card.is-selected` の border 2.50:1 / `/box` の `.delete-button` 2.82:1。いずれも `global.css` の基底修正が要る(ラウンド21ではページscopedの上書きで個別に是正しただけ)。

**このセッションで得た重要な運用上の教訓**(`.claude/skills/ui/references/pitfalls.md` にも記載):
- **エージェントの「復元しました」報告は検証の代わりにならない。** ラウンド21でCoordinatorが自分でDBを突き合わせて初めて、個体の性格が復元されていないことを発見した。

- **ユーザー判断待ちが3件**あるので、再開時はまずそれを確認するのが早い(→ round-19.md)
- 新しい講評から始める場合は、ラウンド16で改訂した観点(→ round-16.md)を使う。**次のメタレビューはラウンド21**(3の倍数)
- jpokeの仕様を確認する必要が出たら **`.claude/skills/jpoke/` の知識ベースを先に読む**(ソース直読みはそこに無い論点だけ。読んだら出典つきで書き戻す)
- `00-foundation.md` の**レイアウト原則とタイポグラフィ原則が現行仕様の唯一の正**。ラウンドログと食い違う場合はそちらが優先

## 新しいラウンドの追記ルール(持続可能性のための運用ルール)

- **1ラウンド = 1ファイル。** `docs/plan/ui_rounds/round-NN.md` を新規作成し、これまでどおりの書式(優先度A/B/C、実施結果の表など)で書く。**このui_plan.md本体には追記しない。**
- ファイル冒頭は次の2行から始める:
  ```markdown
  # UI改善ラウンド NN

  [← 索引](../ui_plan.md)
  ```
- 記録したら、上の「ラウンド履歴」表に1行追加し、「現在の状態」を最新の内容に書き換える。
- 複数ラウンドにまたがる内容(例: 「ラウンド6〜7の実施結果」)は、**その内容が指す最後のラウンド番号のファイル**に書く(この例では round-07.md)。
- 3ラウンドに1回のメタレビュー(SKILL.md Step 7)は、直近3ラウンドの `round-*.md` を直接読ませればよく、行範囲の指定は不要。
