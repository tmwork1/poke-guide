# 未ログイン利用・ゲストモード仕様書

## 1. 目的

ポケガイドを未ログイン状態でも一定範囲まで利用可能にし、ユーザーがログイン前にアプリの操作感・機能・利便性を確認できるようにする。

ログインを利用開始の前提条件とせず、原則として以下の方針とする。

* 閲覧・操作・一時的なデータ作成は未ログインでも可能
* アカウントへの永続保存・複数端末同期など、アカウントに依存する機能のみログイン必須
* ログインを要求する前に、ユーザーが実際のアプリUIを操作できる状態を提供する

## 2. 基本方針

ログイン状態による機能の境界は以下とする。

| 機能            | 未ログイン | ログイン済み |
| ------------- | ----: | -----: |
| バトルデータ閲覧      |     ○ |      ○ |
| 上位チーム閲覧       |     ○ |      ○ |
| すばやさ表         |     ○ |      ○ |
| ダメージ計算        |     ○ |      ○ |
| ボックス閲覧        |     ○ |      ○ |
| ポケモン作成        |     ○ |      ○ |
| ポケモン編集        |     ○ |      ○ |
| ポケモン削除        |     ○ |      ○ |
| チーム作成         |     ○ |      ○ |
| チーム編集         |     ○ |      ○ |
| チーム削除         |     ○ |      ○ |
| ゲストデータの端末内保存  |     ○ |      ○ |
| アカウントへの永続保存   |     × |      ○ |
| 複数端末間の同期      |     × |      ○ |
| アカウント固有データの利用 |     × |      ○ |

## 3. 未ログイン状態

未ログインユーザーは「ゲストモード」として扱う。

ゲストモードでは、ログイン済みユーザーと可能な限り同一のUIを使用する。

ログイン前専用のデモ画面を別途構築するのではなく、実際のアプリ画面をそのまま操作できる状態を基本とする。

## 4. ゲストデータ

### 4.1 保存先

未ログイン状態で作成・編集したデータはブラウザ内に保存する。

保存先は原則として `localStorage` 等のクライアント側ストレージとする。

ゲストデータはサーバー上のユーザーデータとして保存しない。

### 4.2 対象データ

ゲストモードでは少なくとも以下を保存可能とする。

* 作成したポケモン
* ポケモンの設定内容
* 作成したチーム
* チーム構成

### 4.3 データ保持

ブラウザを再読み込み・再起動しても、端末内に保存されたゲストデータは維持する。

以下の場合はデータが失われる可能性がある。

* ブラウザのサイトデータ削除
* `localStorage` 等の削除
* 別ブラウザからのアクセス
* 別端末からのアクセス

必要に応じて、ゲストデータが端末内のみで保存されることをUI上で案内する。

## 5. 初期サンプルデータ

### 5.1 目的

初回アクセス直後からボックスやチームの利用イメージを確認できるようにする。

### 5.2 ボックス

ゲストモードの初回利用時は、複数のサンプルポケモンをボックスに表示する。

サンプルポケモンは通常の登録ポケモンと同じUIで表示する。

ユーザーはサンプルポケモンに対して以下の操作を行える。

* 詳細表示
* 編集
* 複製
* 削除
* チームへの追加

### 5.3 チーム

必要に応じて、初回状態で1〜2個程度のサンプルチームを用意する。

サンプルチームも通常のチームと同様に編集可能とする。

### 5.4 初期化条件

サンプルデータはゲストモードの初回利用時のみ生成する。

ユーザーがサンプルデータを削除した後、ページを再訪するたびに自動復元しない。

## 6. ボックス

未ログイン状態でも通常のボックス画面を表示する。

従来の「利用するにはログインが必要」という全面的な制限画面は廃止する。

未ログイン状態でも以下を可能とする。

* ボックス一覧の閲覧
* ポケモンの新規作成
* ポケモンの編集
* ポケモンの削除
* ポケモンの複製
* 並び替え等の通常操作

保存先のみログイン状態によって切り替える。

* 未ログイン：端末内
* ログイン済み：アカウントデータ

## 7. チーム

未ログイン状態でも通常のチーム管理画面を表示する。

以下を可能とする。

* チーム一覧の閲覧
* チームの新規作成
* チーム編集
* チーム削除
* ボックス内ポケモンの選択
* チームメンバーの入れ替え

ゲストモードで作成されたチームは端末内に保存する。

## 8. その他の機能

以下の機能は原則としてログインを要求しない。

* バトルデータ
* 採用率等の統計情報
* 上位チーム
* すばやさ表
* ダメージ計算
* その他、ユーザー固有データを必要としない閲覧機能

ゲストモードのボックスデータを利用可能な機能については、端末内のゲストデータを参照する。

## 9. ゲストモード表示

未ログイン中であることは表示するが、操作を妨げない程度の控えめな表現とする。

例：

> お試しモード
> ログインするとデータをアカウントに保存できます。

付近にログインボタンを配置する。

ログイン誘導のためにモーダルや全面オーバーレイを頻繁に表示しない。

## 10. ログイン導線

ログインは以下のタイミングで自然に案内する。

* ゲストモード表示部分
* ヘッダー等のログインボタン
* アカウント保存を行おうとした場合
* 複数端末同期等のログイン必須機能を利用しようとした場合

ログインしていなくても通常操作を継続できる場面では、ログインを強制しない。

## 11. ゲストデータのアカウント移行

未ログイン状態でデータが作成されている場合、ログイン成功後にゲストデータをアカウントへ移行できるようにする。

対象：

* ポケモン
* チーム

ログイン成功後、必要に応じて以下の確認を表示する。

> お試し中に作成したデータがあります。
> アカウントに保存しますか？

選択肢：

* 保存する
* 保存しない

「保存する」を選択した場合、ゲストデータをアカウント側のデータへ追加する。

移行完了後は、同一データが再度取り込まれないようにする。

## 12. データ競合

ログイン先アカウントに既存データが存在する場合、ゲストデータによって既存データを自動的に上書きしない。

原則としてゲストデータを追加扱いとする。

ID等がゲストデータとサーバーデータで衝突しないよう、移行時に新しい識別子を割り当てる。

## 13. トップページ

未ログイン時のトップページは、一般的な宣伝用LPとして大規模に作り込む必要はない。

アプリの概要と、実際の機能へ直接進める導線を優先する。

例：

# ポケガイド

ポケモンの個体・チームをまとめて管理。

[試してみる]

「試してみる」からボックス等の主要機能へ遷移する。

遷移後はデモ専用画面ではなく、通常のアプリ画面をゲストモードとして表示する。

## 14. UX方針

ゲストモードでは以下を重視する。

* 本番UIとデモUIを分離しない
* 未ログイン状態でも主要操作を最後まで試せる
* ログイン要求によって操作フローを中断しない
* ログインによるメリットを「利用可能になること」ではなく「保存・同期できること」とする
* サンプルデータによって初回状態を空画面にしない
* サンプルデータも通常データと同じ方法で操作できるようにする

## 15. 基本ユーザーフロー

未ログインユーザーの基本フローは以下とする。

1. ポケガイドへアクセス
2. 「試してみる」を選択
3. ボックスを表示
4. サンプルポケモンを確認
5. ポケモンを編集、または新規作成
6. チームを作成
7. その他の計算・データ機能を利用
8. 必要に応じてログイン
9. ゲストデータをアカウントへ移行
10. 以降はアカウントデータとして利用

## 16. ログイン済みユーザーへの影響

ログイン済みユーザーについては、原則として現在の利用方法を変更しない。

ゲストモード対応に伴って、データアクセス層では以下の違いを吸収する。

* 未ログイン：ローカルデータ
* ログイン済み：サーバー上のアカウントデータ

各画面のUIコンポーネントは可能な限り共通化する。

## 17. 実装上の優先順位

### 優先度：高

* 未ログインでボックスを表示可能にする
* 未ログインでポケモンを作成・編集可能にする
* ゲストデータのローカル保存
* サンプルポケモンの初期生成
* 未ログインでチームを作成・編集可能にする
* ゲストモード表示
* ログイン後のゲストデータ移行

### 優先度：中

* サンプルチーム
* トップページの「試してみる」導線
* ログイン時のデータ移行確認UI
* ゲストデータとアカウントデータの競合処理

### 優先度：低

* 大規模なログイン前LP
* スクリーンショット中心の紹介ページ
* デモ専用の別UI

## 18. 完了条件

以下を満たした場合、ゲストモード対応完了とする。

* 未ログイン状態で主要画面へアクセスできる
* 未ログイン状態でポケモンを作成・編集できる
* 未ログイン状態でチームを作成・編集できる
* 作成したゲストデータがブラウザ再読み込み後も維持される
* 初回アクセス時にサンプルデータが表示される
* ログインを行わなくてもアプリの主要な操作感を確認できる
* ログイン後にゲストデータをアカウントへ移行できる
* ログイン済みユーザーの既存データ・既存操作に影響を与えない
