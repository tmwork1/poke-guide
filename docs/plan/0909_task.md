# 1. 通常モードとゲストモードの乖離

以前、画面遷移直後のボックスカードのレイアウト揺れを対策したが、ゲストモードでは現在も揺れが残っています。

通常モードとゲストモードは基本的に同じUIを使う想定なので、まず以下を調査してください。

* UIコンポーネントやレイアウトが二重実装になっていないか
* guest判定によって別コンポーネント・別CSS・別レンダリング経路を通っていないか
* データ取得方法の違いによって初期描画だけ挙動が分かれていないか
* 通常モード向けの過去の修正がゲストモードに反映されない構造になっていないか

ゲストモードだけを個別修正するのではなく、可能であれば共通コンポーネント・共通処理へ統合し、今後UI修正が片方にだけ適用される状態を防いでください。

# 2. 画面遷移直後のレイアウトゆらぎ

対象：

* `box/` 以下のポケモンプレビューを表示するタブ
* `team/` のポケモンタブ

画面遷移直後に、プレビューやカードのレイアウトが一瞬揺らぎます。

原因を調査し、可能な限りパフォーマンスを落とさずに改善してください。表示遅延などで隠すより、サイズ確定・再描画・データ取得・hydration・CSSなど根本原因への対策を優先してください。

## 対応

1. 現状の遷移時間を計測し、ボトルネックを特定する
2. 改善可能な箇所をCodexに修正させる
3. 修正前後を同条件で計測して効果を確認する
4. ページ遷移方式も抜本的にレビューする

prefetch、キャッシュ、データ取得、レンダリング、View Transition、軽いフェードなども含めて検討してください。

ただし、見かけ上遅さを隠すことより**実際の遷移速度の改善を優先**し、UX改善策もパフォーマンスへの影響が小さいものにしてください。
