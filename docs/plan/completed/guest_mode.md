# 未ログイン利用・ゲストモード仕様

## 1. 目的

未ログインの利用者にも既存のローカルデータを確認・管理できる利用形態を提供する。新しいデータの作成と、ローカルデータをアカウントへ移す機能は提供しない。

## 3. ゲストモードの判定

`Astro.locals.user` がないページをゲストモードとする。ブラウザ側では `document.body.dataset.guestMode` を `isGuestMode()` で参照する。未ログインだからといって一覧・既存データの編集画面へリダイレクトしない。

## 4. データの保持

既存のゲストデータは `localStorage` の `pokeguide.guest.v1` に保持する。ブラウザのストレージを削除した場合や別ブラウザ／別端末では復元できない。読み書き不能な環境ではメモリ内のベストエフォート動作へフォールバックする。

既存データのIDは `guest-` 接頭辞付きUUIDである。これはローカルストア内の参照整合性のために使う。

## 5. 初期サンプルデータ

初回アクセス時のサンプルポケモンおよびサンプルチームの自動生成は廃止した。新規のゲスト利用者には空の一覧を表示する。

過去のバージョンが `localStorage` に残したサンプルデータや実データは削除しない。既存データとして、そのまま閲覧・編集・削除・複製できる。

## 6. ボックス

未ログイン時も、既に `localStorage` に存在するポケモンの一覧、閲覧、編集、削除、複製を継続して利用できる。

新規の空ポケモンを作成することはできない。`/box` の通常追加ボタンと空状態の追加ボタンは、ゲスト時に遷移せずログイン誘導ダイアログを開く。`/box/new` を直接開いた場合も、編集フォームを描画せず次の案内のみを表示する。

> ログインすると、新しいポケモンを作成できます。

案内には `/api/auth/login` への「Googleでログイン」リンクを置く。

## 7. チーム

未ログイン時も、既存ローカルチームの一覧、閲覧、編集、削除を継続して利用できる。既存ポケモンをチームへ編成する操作も許可する。

新規の空チームは作成できない。`/team` の通常追加ボタンと空状態の追加ボタンでは、ゲスト時にログイン誘導ダイアログを開く。`/team/new` を直接開いた場合はチーム編集フォームを表示せず、ログイン案内を表示する。

チーム編集内の「提案された型から新しいポケモンを作る」および「空のポケモンを追加する」導線も、ゲストでは新規作成を行わず、同じログイン誘導ダイアログを開く。

## 8. ゲスト非対応機能

対戦相手メモとチーム提案はログインが必要である。ゲストで利用できない理由は、アカウントに紐づく保存・集計を必要とするためである。各画面ではログインが必要であることを明示する。

## 9. ボックス一覧のログイン導線

ゲストがポケモン追加ボタンを押した場合は、ネイティブの `<dialog>` を `showModal()` で開く。ページ遷移はしない。ダイアログには作成可能になる機能の説明、`/api/auth/login` へのGoogleログインリンク、閉じるボタンを置く。

## 10. チーム一覧のログイン導線

ゲストがチーム追加ボタンを押した場合も、ページ遷移はせずネイティブの `<dialog>` を開く。文言は「ログインすると、新しいチームを作成できます。」とし、ボックスと同じGoogleログイン導線を使う。

## 11. ゲストデータのアカウント移行

ゲストデータをアカウントへ移行する機能は廃止した。`POST /api/guest-migration` は提供しない。ログイン後の移行確認ダイアログ、移行用レート制限、移行にだけ使用していたクライアント／サーバー関数も存在しない。

Supabaseの `guest_local_id` 列およびそれを追加した既存マイグレーションは、過去データとの互換性のため残す。今回の機能縮小ではDBスキーマを変更しない。

## 12. セキュリティと境界

ゲストストアはブラウザローカルにだけ存在する。認証済みAPIは従来どおり認証とユーザーIDの照合を行い、ゲストデータを受け取ってサーバーへ保存する経路は持たない。

## 13. トップページ

未ログイン時のトップページはアプリの機能を案内する。ゲストデータの移行やサンプルデータ作成を前提とした表示は行わない。

## 14. UX方針

- 未ログインでも、閲覧可能な機能は通常の画面として提供する。
- 作成を禁止する操作では、エラーや強制リダイレクトではなくログイン誘導ダイアログを表示する。
- 既存ローカルデータに対する閲覧・編集・削除・複製の挙動は変更しない。
- ゲストデータは端末ローカルに留まり、ログイン後も自動・手動を問わず移行しない。

## 15. 基本ユーザーフロー

1. 未ログインでボックスまたはチーム一覧を開く。
2. 既存のローカルデータがあれば一覧へ表示する。なければ空状態を表示する。
3. ゲストは既存データを操作できる。
4. 新規作成ボタンを押すとログイン誘導ダイアログが開く。
5. ログイン済み利用者は従来どおり新規編集画面へ進む。

## 16. 実装方針

`src/lib/data/pokemon-repo.ts` と `src/lib/data/team-repo.ts` は、ゲスト時には既存ローカルデータの一覧・更新・削除だけを扱う。新規作成用アダプタはゲスト時に拒否し、UI以外の導線からも作成できないようにする。

`src/pages/box/[id].astro` と `src/pages/team/[id].astro` は、`isNewMode && !user` の場合に編集UIを初期化しない。既存IDを指定したゲスト編集では従来のローカルストアhydrationを利用する。

## 18. 完了条件

- 未ログインで既存ローカルのポケモン・チームを閲覧、編集、削除、複製できる。
- 未ログインではポケモン・チームを新規作成できず、全ての作成導線でログイン誘導が表示される。
- `/box/new` と `/team/new` の直接アクセスでは編集フォームを表示しない。
- 初回ゲストアクセスでサンプルデータを生成しない。
- `/api/guest-migration`、移行確認ダイアログ、移行用レート制限が存在しない。
- 型チェックまたはビルドが成功し、削除済みコードへの参照が残らない。
