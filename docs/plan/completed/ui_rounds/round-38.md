## ラウンド38 の要件(2026-07-30 ユーザー指示第20弾)

**ラウンド34〜37と同じworktree `poke-commons-ui-round-34`(ブランチ `ui/round-34`)で続けて作業する。**

### ユーザーの言葉(原文)

> ボックス画面
> - テラスタル画像が見切れているので、アイテム画像も一緒に左にずらす
>
> 個体編集画面 ヘッダー
> - 全てのダメージカードを折りたたむ・展開するボタンをヘッダーに移動。単一ボタンで交互に切り替える。
>
> 個体編集画面 左サイド
> - 技の順番をドラッグアンドドロップで入れ替えられるようにしたい
>
> 個体編集画面 ダメージカード
> - テラスタル選択ボックスのサイズが他より大きい。他と揃える。
> - 攻撃のときの技候補には、自分が覚えている4つの技を最上位に表示する
> - 折りたたみの前後でアイコンの表示位置が変わらないように、折りたたみ前のアイコン群を左上に移動し、レイアウトを再調整する
> - 個別の技カードの計算結果はカラー表示せず、累計だけ色分けする
> - 折りたたみ・展開ボタンは >> を90度回転させたデザインにする。ボタンに枠は表示しない
> - 展開状態から情報量が減りすぎている。絵や省略表記を駆使してなるべく情報量を落とさないようにして
> - 2個目以降の技追加では、一つ前のカードの詳細設定を引き継ぐようにする
>
> 個体編集画面 右サイド
> - アイコン修正 すなあらし：竜巻イラスト、サイコフィールド:👁のようなイラスト、ミストフィールド：斑点で霧を表現するイラスト

**訂正(同ターン内で追送)**: 「ボックス画面のアイテムとテラスタル画像は左右ではなく上下に配置する。引き続き画像がニックネーム領域に被らないように配置する。」→ 38-B1はこちらを正とする(下記に反映済み)。

### 38-B1: ボックス一覧のアイテム/テラスバッジ配置(box/index.astro)

- 現状: `.card-badge-row`(`.card-item-badge` + `.card-tera-badge` を内包)はラウンド35で**横並び(row)**に変更済み(`src/pages/box/index.astro` 471行目付近 `.box-grid .card-pokemon .card-badge-row`)。
- 今回の要件(訂正後): **横並びをやめて縦(column、上下)に戻す**。ただし**テラスタル画像が見切れている**(要実測: `.card-badge-row`の位置とカード右端/下端の関係を`getBoundingClientRect()`で確認し、はみ出し量を特定する)。**ニックネーム表示領域(`.card-nickname`等)と重ならない位置**に配置し直すこと。
- 対応: `.card-badge-row`を`flex-direction: column`に戻しつつ、見切れ・ニックネームとの干渉が起きない座標(top/right、または左方向へのオフセット)を実測して決める。実装者の判断で構わないが、**変更後に必ずスクリーンショットで「見切れていないか」「ニックネームと重ならないか」の両方を目視確認**すること。

### 38-H1: 折りたたみ全操作ボタンをヘッダーへ移動(box/[id].astro + DamageCalcSection.astro/damage-calc.ts)

- 現状: ラウンド36(36-3)で `#damage-rows-toolbar`(`DamageCalcSection.astro` 41行目付近、`#damage-collapse-all-button`+`#damage-expand-all-button`の2ボタン)をダメージカード一覧の直上に新設済み。
- 今回の要件: この機能を**ページ共通ヘッダー(トップバー)に移動**し、**2ボタンではなく単一ボタンで「折りたたむ⇄展開する」を交互に切り替える**トグル式にする。
- 実装方針: `src/pages/box/[id].astro` は既に `<Fragment slot="topbar-actions">`(削除ボタンが入っている箇所、111行目付近)でAppLayoutの共通トップバーにボタンを差し込む仕組みを持っている(**`AppLayout.astro` 自体は編集禁止**、`box/[id].astro`側のFragment内に追加ボタンを置くこと)。ここに新しいボタン(例: `#damage-collapse-toggle-button`)を追加し、`DamageCalcSection.astro`/`damage-calc.ts` 側の折りたたみ全操作ロジック(既存の`damage-collapse-all-button`/`damage-expand-all-button`のクリックハンドラ)を、この新ボタンから呼べるように統合する。
- 既存の`#damage-rows-toolbar`(2ボタン版)は**このヘッダー移動に伴い撤去してよい**(重複UIを残さない)。
- ボタンの状態(「現在すべて折りたたみ済みか」等)に応じてラベル/アイコンを切り替える(例: 折りたたみ中カードが1枚もなければ「すべて折りたたむ」、1枚でも展開中なら「すべて折りたたむ」、全部折りたたみ済みなら「すべて展開する」、といった実装者判断のロジックでよいが、**押した結果が直感的であること**を確認する)。

### 38-D1: ダメージカードのテラス選択ボックスのサイズ統一

- 現状: `DamageCalcSection.astro` 522行目付近 `#opponent-notes-section .damage-row-build-grid .damage-row-tera-field select` に個別のサイズ指定がある。ラウンド34(34-D2)で「左サイドの寸法に統一」した経緯があるが、**再度サイズがずれている**とのユーザー指摘。
- 左サイドの基準は `LeftPanel.astro` の `#tera`(隠しselect)ではなく、**表示用ウィジェット `.tera-select-wrap`/`#tera-dropdown-button`**(207行目・910行目付近)のサイズ。この実測値と`.damage-row-tera-field select`の現在値を`getBoundingClientRect()`で比較し、差分を解消すること。

### 38-D2: 攻撃側の技候補で「覚えている技」を最上位に表示

- 現状把握: 技候補(`<input list="...">`のdatalist、またはラウンド37で追加した技選択ウィンドウの一覧)のソート順を確認する。
- 要件: ダメージカードで攻撃側の技を選ぶ際、**そのポケモンが実際に覚えている4つの技(左パネルの技1〜4)を候補の最上位に表示**する(残りは既存の並び順のまま、または任意)。`loadLearnsetMap()`等の既存データソースは使わず、**左パネルで現在入力されている技1〜4の値**(そのポケモン固有の実際の選択)を優先表示する点に注意(種族の覚え技全体ではない)。

### 38-D3: 折りたたみ前後でアイコン位置が変わらないようにレイアウト再設計

- 現状(ラウンド36実装): 展開状態では`.damage-sprite-box`はカード左側の攻守セグメント行の隣(左寄り)に配置されている(288行目・306行目・360行目のコメント参照)。折りたたみ状態(`[data-collapsed="true"]`、2308行目〜)では`.damage-sprite-box`だけ残し、他の展開時要素(`.damage-row-build-left`/`.damage-ev-grid`/`.damage-row-columns-wrap`/`.damage-add-column-slot`)を隠す実装。
- ユーザー指摘: 折りたたみ前後でアイコンの画面上の位置(座標)が変わって見える。**要件は「展開状態のアイコン群を左上に移動し、折りたたみ時と同じ位置になるようレイアウトを再調整する」**。
- 対応: 展開状態のレイアウトを変更し、`.damage-sprite-box`(+隣接する攻守トグル等の「アイコン群」)をカードの**左上**に固定配置し、折りたたみ時の`.damage-row-collapsed-summary`内のアイコン位置と一致させる。実測(`getBoundingClientRect()`)で折りたたみ前後の`.damage-sprite-box`の座標(ビューポート座標)がほぼ一致する(数px以内)ことを確認すること。

### 38-D4: 個別の技カードの計算結果は色分けせず、累計のみ色分け

- 現状: 各技カード(`.damage-column`)ごとの結果表示(`.damage-column-result`、確1/確2等の判定バッジ)に確定数に応じた色(`.severity-bar`系のクラス)が付いている。累計結果(`.damage-row-total-result`等)にも同様の色分けがある。
- 要件: **個別の技カードの結果表示からは色を除去**(通常のテキスト色に統一)し、**累計結果だけ従来どおり色分け**を残す。対象クラスは実装者が`DamageCalcSection.astro`のCSS/DOM構造を読んで特定すること(個別技カード側の結果要素と、累計側の結果要素を確実に区別する)。

### 38-D5: 折りたたみ・展開ボタンのデザイン変更

- 現状(ラウンド36実装): 折りたたみトグルボタンはカード右下に配置済み(具体的な現在の見た目・アイコンは実装者が確認)。
- 要件: **「>>」を90度回転させたデザイン**(視覚的には上下方向の「≫」、展開時は下向き・折りたたみ時は上向き、または実装者判断で分かりやすい向き)にし、**ボタンの枠線(border)は表示しない**。

### 38-D6: 折りたたみ状態の情報量を増やす

- 現状: 折りたたみ時は`.damage-row-collapsed-summary`に名前・攻守方向・累計結果だけを表示(2270行目〜のコメント参照)。
- ユーザー指摘: 展開状態と比べて情報量が減りすぎている。
- 要件: **折りたたみ時の高さ制約(現状の折りたたみ後高さ、ラウンド36実測で102.75px程度)を保ったまま**、絵文字/アイコン/省略表記等を活用してできるだけ多くの情報(例: 使用技名の省略列挙、タイプアイコン、テラス状態等)を1行(または折りたたみ後の高さに収まる範囲)で表現する。実装者の裁量だが、**折りたたみ後の高さが以前より明らかに増えないこと**(ラウンド36の目標=`.damage-sprite-box`の高さ以内)を実測で確認する。

### 38-D7: 2個目以降の技追加時に前カードの詳細設定を引き継ぐ

- 現状: 「技を追加」ボタン(`damage-add-column-button`、1612行目付近)で新しい技カラム(`DamageColumnState`)を追加する際、`createEmptyColumn()`(402行目)で空の状態を作っている。
- 要件: 2個目以降の技を追加する際、**直前に追加された技カラムの「詳細設定」**(ランク補正・状態異常・急所・じゅうでん等、右パネルの攻撃側/防御側設定に相当する`DamageColumnState`のフィールド)を**引き継いだ状態で新規カラムを作る**。技名・PP等の技固有情報は引き継がない(空のまま)。`createEmptyColumn()`に、直前カラムの状態を受け取って詳細設定だけコピーする引数を追加する形が自然(実装者判断)。

### 38-R1: 天候/フィールドアイコンの差し替え

- 現状: `src/lib/box-id/damage-calc.ts` 219〜228行目付近の`DAMAGE_WEATHERS`/フィールド定義に、天候・フィールドごとの単純なインラインSVGアイコンが定義されている(すなあらし=水平の渦巻き線2本、サイコフィールド=8方向の星型スパークル、ミストフィールド=波線3本)。**同じ配列がテラス選択ではなく天候/フィールドボタンとして`DamageCalcSection.astro`(攻撃側)と`RightPanel.astro`/`right-panel.ts`(防御側の天候/フィールドボタン、スクリーンショットで確認済み)の両方から参照されている**ため、**この1箇所を直すだけで両方に反映される**。
- 差し替え内容:
  - すなあらし: 竜巻(トルネード)を連想させるイラストに変更。
  - サイコフィールド: 👁(目)を連想させるイラストに変更。
  - ミストフィールド: 斑点(ドット)で霧を表現するイラストに変更。
- 他の天候/フィールド(はれ/あめ/ゆき/エレキ/グラス)のアイコンは変更しない。SVGは既存と同様「単色線画・`currentColor`で色を継承・18×18目安」のスタイルに合わせること。

## 維持すべき点(壊さないこと)

- **12px下限**(20-G3)・**アイコン規格20px**(個別に拡大縮小された箇所を除く)。
- **育成ルール(IV=31固定 / 努力値0〜32スケール / Lv50固定)は仕様。**
- `global.css`・`AppLayout.astro`は編集しない。
- ラウンド34〜37でこれらのファイルに加えた変更(アイコンサイズ、間隔、折りたたみ機能、技選択ウィンドウ等)を壊さないこと。
- **ラウンド37で発見された技選択ウィンドウの重なりバグ**(round-37.md「Coordinator検証結果」参照)は**別エージェントが先に修正する**ため、38-L1担当エージェントはその修正後の状態から着手すること(先に着手すると同一ファイルの競合が起きる)。

## 検証手順(実装者が行うこと)

1. `npm run shot`でライト・ダーク両方を撮影し、Read toolで目視確認する(box一覧・box/[id]の両方、該当箇所)。
2. 数値目標がある項目(38-D1のテラス選択サイズ、38-D3のアイコン座標一致、38-D6の折りたたみ高さ)は`getBoundingClientRect()`で実測する。
3. 38-H1・38-D7は実際にPlaywright等でボタン操作・技追加操作を行い、期待どおりの状態遷移になることを確認する(スクリーンショットだけでは不十分)。
4. `npx astro build`成功・`git diff --stat`で担当ファイル以外に差分が無いことを確認する。
5. DBに個体を作った場合は必ずDELETEで元に戻す。
