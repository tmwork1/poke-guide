## レビュー観点の改訂(ラウンド16時点、fableメタアドバイザーの提案をCoordinatorが精査して反映)

**メタアドバイザーが「直近3ラウンドのうち講評ラウンドはラウンド15の1回だけ(13・14は既存指摘の消化)なので、『使われていない観点』の判定は1標本に基づく。したがって削除は最小限にとどめ、既存固定項目への統合を優先する」と自ら前提を明示してきた。** この自制は妥当なのでそのまま採用した。以下を `agent-prompts.md` に反映:

- **UI【固定1】を「過剰と不足の両方向」に拡張。** 従来は「余りすぎ」しか見ておらず、**対になる「足りない(省略が起きる)」が観点に無かった**。ラウンド13の技名省略21%は実装後にCoordinatorが発見しており、レビュー時点で拾えるべきだった。列数・セル幅の変更提案には最長実データでの必要幅の実測を添えることも必須にした。
- **UI【固定3】の欠陥種リストを「列挙」から「`pitfalls.md` を正とする参照」に変更。** 列挙を増やし続けると陳腐化する。`.card-hint` の負マージン罠(ラウンド13で追加)がテンプレート上は列挙外だった。
- **UI【固定5】から画面名の固定(`/box` と `/box/[id]`)を外した。** ラウンド15の対象は別の4画面で、レビュアーは意図を汲んで一般化してくれたが、次も汲む保証はない。あわせて**サイズ差が「ページ内の階層」で正当化される場合がある**ので `00-foundation.md` のタイポグラフィ原則を確認させる一文を追加(今回のB-7の判断が再提起されないため)。
- **UX【固定2】を「状態・記号の誤読」に拡張し、凡例チェックを吸収。** ★の凡例をUXとプレイヤー視点が**完全に重複して指摘**したため、境界を明文化した: **凡例が存在するか=UX、記号が表す意味の正誤=プレイヤー視点。** 両テンプレートの冒頭にも同じ分担を1文ずつ入れた。
  - **ただしA-1型の重複は許容のまま残した。** 期待値の件はUXが「利便性(C)」・プレイヤー視点が「正確性(A、実データ裏取り)」という**別種の証拠**で同じ問題に触れ、それがCoordinatorの格上げ判断を可能にした。**排除すべきは同一内容の重複だけ。**
- **プレイヤー視点に新固定「表示値の再計算」を追加。** ラウンド15最大の成果(期待値の誤り発見)は、レビュアーが**画面の数値を自分で再計算して食い違いを見つけた**ことから出たが、これはどの固定項目にも書かれておらず**偶発的な行動に依存していた**。「除外条件が境界データで破れないかも見る」(`ふくろだたき` の `power: 1`)まで含めて明文化した。
- **代わりにプレイヤー視点【固定2】(並び順)を「条件付き回転枠」に降格。** ラウンド15で1件も使われなかったが、これは対象4画面が**参照系**だったためで、観点自体が無効なのではない。**編集・入力を伴う画面(`/box` 系)を見るラウンドでは必須**という条件付きにした(削除ではない)。
- **プレイヤー視点【固定3】を「実データの集計」まで踏み込ませた。** ラウンド13の技名省略・ラウンド14のlearnset 0件・ラウンド15の検証候補は、いずれも**実データを集計して初めて具体名が出た**。「長い名前」のような推測ではなく実名を挙げさせる。あわせて「分布の端がバグに見えるが仕様の場合は、**ユーザーが誤解しない表現になっているかという指摘に変換する**」を追加(ラウンド15のB-8がまさにこの形)。
- **3テンプレート共通の制約に2件追加**(観点リストの枠を消費しない): (1) **提案文でファイル名・フィールド名を名指しするなら実在を確認してから書く**(`detail/pokemon.json` に `imageId` が無かった件)、(2) **環境依存の対処(`accent-color` 等)を提案するなら効かなかった場合の代替案を併記する**(`accent-color` だけでは直らなかったが代替案が書かれていたため手戻りゼロだった好例の規範化)。
- **UIの制約にのみ**「座標・幅を提案に書くなら `.panel-content` 1080px の内側に収まることを確認する」を追加(x>1100 の提案が確定仕様に抵触した件)。

**変えなかったもの**: 固定枠+回転枠の構造そのもの(改訂後初の講評でプレイヤー視点が優先度A 3件を出し、UI・UXの固定枠も設計どおり機能した。1標本で構造をいじる理由がない)、UX【固定1】【固定3】【固定4】、UI【固定2】【固定4】、プレイヤー【固定1】(指摘ゼロだったが「選択肢がマスターデータと過不足なく一致している」という**検証**として機能しており、壊れていないことの確認に価値がある)。

sonnetサブエージェント2体で実装。**下記はCoordinatorが自分で計測して確認した値。**

| 項目 | 結果(Coordinator実測) |
|---|---|
| **B-2** `/search` 結果の多段化 | **4列化**(列x=295/566/838/1109)。「リザードン」4件で結果セクション 261px→**185px**、**「ア」209件ヒットで 2687px→946px(-65%)、ページ全体 3169px→1429px(-55%)**。**1件のときは1列のまま**で不自然な列割れなし |
| **B-6** タイプアイコンの規格3種混在 | `/moves` 識別ブロックを `/pokemon` と同じ「アイコン+タイプ名の角丸ピル」に統合(`border-radius: 999px`、背景 `--color-surface-alt`)。**タイプ名の二重表示も解消**。`わるあがき` は画像0枚で「タイプなし」テキストのみのピルにフォールバック |
| **B-9** テラスタル時の相性変化 | 非変化技のみに表示(`まもる` では出ない)。**既存の「複合タイプは掛け合わせ」注記に1文追記して1段落にまとめた**(注記が3行以上に増えて読み流されるのを避けるため。実装者の判断をCoordinatorが承認) |

- **退行なし**: 期待値の2段表示(スケイルショットのみ `true`、単発技・変化技では出ない = 正しい出し分け)、タイプ相性ボックスの左端 x=276 で一貫(じしん5バッジ幅441px / ドラゴンクロー1バッジ幅260px)、`わるあがき` の「常に等倍」表示。
- ビルド成功 / `npm test` **199件全pass** / `/search` `/moves` `/pokemon` `/box` を 1920・1440・1280・900・390px で**横スクロールなし** / コンソールエラー0件。
- **`/search` の多段化に `column-width`(multi-column)を採用し `grid` を採らなかった理由**(実装者の判断、Coordinator承認): 検索結果は図鑑番号順・五十音順に**既にソート済み**で、multi-columnの列優先(縦→次の列)はこの順序を保つ(辞書・百科事典の紙面と同じ読み順)。`grid` の行優先だと隣接する項目が**列数分ずれる**(4列なら4件)ため、かえって順序が読みにくくなる。
- **検証時の注意**: 実装者が変更前の実測値を取るのに `git stash` を使ったため、Coordinatorが `git stash list` が空であること・作業ツリーが想定どおりであることを確認した。
