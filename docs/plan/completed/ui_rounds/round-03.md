## ラウンド3の指摘(2026-07-26 opusアドバイザー講評: 個体編集 `/box/[id]`)

カード3枚・技列2〜3列の実使用状態(1920×1080)で実測して得た指摘。

### 総括: 414pxの原因はフォントではない
**「フォントを大きくしたから414pxに膨らんだ」という因果は成立しない。** 実測414pxを計算で分解した結果、主因は **`global.css` の `input/select { min-height: 2.35rem }`(=37.6px)が `#opponent-notes-section` 内で一度も打ち消されていないこと**。相手ビルド箱の入力は `font-size: 0.82rem` / `padding: 0.28em` で組まれており、**内容高さ24.6pxが37.6pxに引き伸ばされ、1行あたり13pxが純粋な空気**になっている。旧アプリ `battle_assistant.jpg` のセレクトは実測約20px。**密度差の正体はここであり、文字サイズではない。前ラウンドのフォント拡大は正しい判断なので巻き戻さないこと。**

| ブロック | 現在 | 必要高さ | 無駄 |
|---|---|---|---|
| 相手ビルド箱 padding+border | 16.4 | 16.4 | 0 |
| 攻守切り替え行 | 30.0 | 30.0 | 0 |
| 相手名行(入力37.6 vs スプライト32) | 37.6 | 32.0 | 5.6 |
| 性格/特性/持ち物/テラス 4行 | 160.0 | 108.0 | **52.0** |

| 「加算後(打点の合計)」ラベル+チップ | 49.0 | 33.9 | 15.1 |
| `.damage-row` padding+border+body余白 | 16.4 | 16.4 | 0 |
| `.damage-row-footer`(保存済み) | 22.4 | 0 | 22.4 |

`.damage-column` は `align-items: stretch` でビルド箱に追従するだけなので、**技列の「大きな空白」は原因ではなく結果**。ビルド箱を縮めれば自動的に消える。

### 優先度A(必ず直す)
- **A-1 `min-height: 2.35rem` を打ち消す(フォント非変更で−74px)**。`#opponent-notes-section` 内の `.damage-row-build select` / `input[type=text]`、`.damage-ev-grid input[type=number]`、`.damage-column input` に `min-height: 0` を当てる。タップ対象28pxの要件は `.damage-row-icon-button`(30px)/`.damage-column-detail-button`(26px)側の話でテキスト入力には不要。
- **A-2 280pxまでの積み上げ**: (a)A-1で−74→340px / (b)`.damage-row-footer` 撤去(A-4)で−22→318 / (c)`.damage-row-total-label`「加算後(打点の合計)」撤去(チップ本文が「累計351〜414…」と書いており完全に冗長)で−15→303 / (d)持ち物とテラスタイプを1行2列にして−27→276 / (e)`.damage-row-build` padding 0.45→0.35rem・grid gap 0.2→0.15rem で−5→**271px**。271pxなら1080pxに3枚が完全に収まる(118+3×271+2×8=947)。**(d)のみ `DamageCard.png`(1項目1行)からの逸脱**なので、まず(a)(b)(c)(e)を入れて実測し、303pxで満足なら(d)は見送ってよい(3枚で1041px、ギリギリ収まる)。狭幅時は `@container (max-width: 820px)` でビルド箱が100%幅になるので2列化は破綻しない。
- **A-3 結果チップがライトモードでWCAG AA割れ(この画面で最も重い問題)**。`global.css` の `.severity-bar` が文字色と背景に同トークンの濃淡ペアを使っており、**ライトで lethal 2.45:1 / risky 2.72:1 / safe 2.84:1**(13.1px太字なので4.5:1必要)。**ダークは4.6〜5.3:1で問題なし**。つまり直すべきはライト側。→ 背景・左バーは既存トークンのまま、**ライト時の文字色だけ**既存色の暗い明度違いに: lethal `#b23a26`(5.2:1) / risky `#8a5806`(5.3:1) / safe `#2b6b5c`(5.5:1)。`/damage-calc` など他ページも同じチップを使うので**`global.css` 側で直すのが本筋**。
- **A-4 「保存済み」が定常状態で4個浮いている**(カード3枚ぶん+左カラム)。`.damage-row-footer` は22.4px×3の高さと視線を消費する変化しない情報。→ **DOMは残したまま**(クラス名をJS/E2Eが参照する可能性)、保存済みのときだけ `footer.hidden = true`、保存中/失敗/未保存のときだけ表示。左カラムの「保存済み」はページヘッダ右上へ移し、**ページ全体で保存状態は常に1箇所**に。
- **A-5 列追加の「＋」が最終列から285〜500px離れて孤立**。`.damage-row-columns-wrap { flex: 1 1 0 }` が余白を全部飲むため。→ 第3弾の制約(＋はwrapの外、`flex-basis: 0` は変更不可)を守ったまま **`max-width: max-content` を追加**するだけ。列が少ないと内容幅で止まり＋が最終列の隣に来る。列が多いと上限が効かず従来どおり横スクロールし＋はスクロール領域の外に残る。**1920/1440/1280/1024/900/700/390px で必ず実測確認**(`max-content` × `overflow-x:auto` はブラウザ差が出やすい)。効かない場合の代替は `.damage-row-body { justify-content: flex-start }` + ＋スロットに `margin-right: auto`。※カード自身を縮める `align-items: flex-start` は第4弾で回帰が出て撤回済みなので再提案しない。
- **A-6 ⚙詳細ダイアログの見出しが「アイアンテール(1番目)の詳細設定」だが中身は行共通の設定**。天気/フィールド/壁/急所/ランク/状態異常/テラスタルはすべて第3弾の知見どおり**攻撃列全体で共通**で、その技専用の項目は1つも無い。**「アイアンテールにだけリフレクターを掛けた」と誤解させ、加算ダメージの結果を根本的に読み違えさせる。** → (1)見出しを「この行の計算条件(相手: ○○)」に変え、直下に「この条件は、この行のすべての技列に共通で適用されます」(0.8rem muted)を置く。(2)⚙をビルド箱の1行目(🗑の隣)にも置く。(3)上部の2つのセレクトが**ラベル無しで「なし」「なし」**と並んでおり判別不能 → `天気`/`フィールド` のラベルを付ける。(4)`場`/`攻撃側(この個体)`/`防御側(相手)` の3見出しに階層を統一し、`急所固定` は攻撃側へ移す。(5)**既定以外の条件が設定されていてもカード上に表示が無く、素のカードと数値だけ違う=バグに見える** → ⚙に `data-modified` で primary 実線の枠、努力値グリッド直下に0.7remの条件チップ行(`雨 / リフレクター / 急所`、既定のみなら非表示)。既存状態の表示なので機能追加ではない。
- **A-7 実数値の色 `#1d6fd1` ハードコード3箇所**(L167 `.stat-value[data-mod=down]` / L210 `.stat-mod-arrow[data-mod=down]` / L675 `.damage-stat-value[data-mod=down]`)。ラウンド2で「タスクC側で同修正」と申し送られたが未対応。**ライトで上昇色2.81:1・ダークで下降色3.30:1と、両モードで片方ずつ落ちる鏡像**。→ `/box/index.astro` で確立済みのパターンを移植: ライト `--stat-up: #c9432c`(4.8:1) / `--stat-down: #1d6fd1`、ダーク `--stat-up: var(--color-danger)`(7.2:1) / `--stat-down: #6fb6f7`(7.5:1)。`/box` と同値にして一覧と編集で色を一致させる(現状は不一致)。
- **A-8 左カラムのラベル方式混在で入力欄の左端が2本ある**。種族/ニックネーム/性格/特性=横並びラベル(入力左端 x≈380)、持ち物/テラス/技=上付きラベル(x≈302)で**78pxずれた2本の縦線**。しかも上付きは1項目あたり約20px高い。→ `Pokemon.png` も全項目インラインなので**全項目を横並びラベルに統一**。`grid-template-columns: 5.5em minmax(0,1fr) auto`(第3列で持ち物画像・テラス画像・技の↗を受ける)。**約120pxの縦を回収**でき、メモ欄が吸収する。

### 優先度B
- B-1 「⚔ この個体が攻撃」がボタンに見えない(中央寄せghostで見出しに読める)。結果を最も変える操作なので、右端に `⇄`・テキスト左寄せ・非ホバー時から枠線+面。「受け」のときだけ枠線を primary にして既定でない状態を示す。
- B-2 技列の `×` が箱の中空(技名直下)に取り残され、その下に200px以上の空白。→ `[技名][⚙][×]` の1行にまとめる。
- B-3 技列に「何発目か」が書かれておらず横連結=加算というモデルが伝わらない。カード1は同じ技名2列+同じチップ文字列が3つ並ぶ。→ 各列に `1発目` `2発目` を0.68rem mutedで。
- B-4 累計で撃破済みになった以降の列が1列目と同格。→ **数値は変えず**(第3弾の「列は独立判定」は正しい)`opacity: 0.55` + `1発目で撃破済` の0.68remキャプション。
- B-5 空状態が点線パネル2枚重ねで、主CTAが下の小さいほう。説明文3行の最終行が「できます。」1語。→ 1枚に統合し、**実体のあるprimaryボタン**を中央に。2文目は削る。`max-width: 720px` で左寄せ(1900px幅いっぱいの空パネルをやめる)。
- B-6 スプライトとタイプバッジがヘッダとフォームで二重(縦150px以内)。→ **ヘッダをテキストのみ**に(公式絵は `Pokemon.png` がフォーム内に指定しているのでフォーム側を残す)。約40px回収。**併せて `/box` ラウンド2 A-6 と同じ「第1タイプしか出ていない」バグがここにもある**(メガリザードンXが FIRE のみ、ハバタクカミが GHOST のみ)。`types` を全件ループする。moves4ではテラスの FAIRY バッジが隣に並び本来のタイプと区別が付かない状態。
- B-7 **「努力値合計 48」を削除**。チャンピオンズルールは合計上限が無いので何の判断にも使えず、「510の残り」を連想させる誤った示唆を与える。
- B-8 **「攻撃調整」「耐久調整」(準備中)を撤去**。努力値を触り終えて次の行動を探す位置に押せないボタンがあり、サイドバーと合わせて画面内に準備中マーカーが4つ。「作業台」ではなく「工事中のプロトタイプ」の印象を作っている。約44px回収。
- B-9 「この個体を削除」が左パネルで最も目立つ(唯一の高彩度要素、ライトで2.81:1)。→ A-4で「保存済み」をヘッダへ移したうえで、削除は muted の ghost にし**ホバー時のみ danger** に転じる。確認ダイアログの有無も要確認。
- B-10 能力値ヘッダ行の桁が列と合っていない(`努力値(0〜32)` がスライダーの上にあり数値入力の上には何も無い)。→ ヘッダ行と各能力行を**同一の grid template** に(例 `4.5em 3.2em 1fr 3.4em 3.6em`)。`努力値` は `grid-column: span 2` でスライダー+入力を跨がせる。
- B-11 未入力欄が「壊れたフォーム」に見える。**A-1で高さが解決すれば大半は消える**。追加でやるなら `:placeholder-shown` を破線+透明背景にして「空きスロット」を能動的に表現。性格/テラス=select、特性/持ち物=input で形状が混在している点も揃える。
- B-12 左パネルの実数値が Pyodide 依存で、CDN不通時に6個すべて `(未計算)` になる。`/box` 一覧は同じ実数値を**純JSで計算している**ので編集画面だけエンジン依存なのは不整合。→ 左パネルも純JS計算に揃える(IV=31/Lv50固定で式は自明)。ダメージだけがエンジン待ちになるのが正しい。エラーバナーもURL露出をやめ「ダメージ計算エンジンの読み込みに失敗しました」+再読み込みボタンに。
- B-13 「← ボックスへ戻る」がヘッダ右端(期待と逆、サイドバーとも重複)。→ `ボックス / メガリザードンX` のパンくずとして左寄せに移し、**空いた右上をA-4の保存状態インジケータに充てる**。

### 優先度C(要判断)
- C-1 相手名を行の先頭に(`[スプライト][相手名][⇄][🗑]` の1行統合でさらに−30px)。カードを縦に走査するとき最初に拾うのが全カード共通の「この個体が攻撃」になっている。図からの逸脱かつ攻守の可読性が下がるので要判断。
- C-2 ダイアログのランクが `0` のセレクト10個。`+1`/`-1` と符号を出し0以外は太字+primary。
- C-3 `.damage-rows-list { gap: 0.5rem }` はカード枠・内箱枠・フッター罫線が同じ濃さで多層に並び切れ目が読みにくい。A-4でフッター罫線が消えるので改善するが 8→12px も検討価値あり。
- C-4 結果チップの主役化(`grid-template-columns: auto 1fr` で左に `確1`(1.0rem/700)、右に数値(0.76rem))。3枚並べたとき結論だけを縦に読める。**クラス名と要素は維持**、テキスト生成ロジック変更を伴うのでJS影響確認が必要。
- C-5 攻/受で色の意味が反転する(`確1`=赤 は攻撃なら良い結果、受けなら悪い結果)。C-4を採れば色は補助に格下げできるので個別対応は不要。
- C-6 ダイアログの `閉じる` が左下。右寄せか右上の `×` に。

### 維持すべき点(壊さないこと)
**フォントサイズの底上げは正しい**(`.damage-column-result` 0.82rem / `.damage-row-total-result` 0.85rem / `.pokemon-name-row input` 0.92rem-700 は維持)。ビルド箱と技列箱の**下端が完全に揃っている**構造(`align-items: stretch` + `.damage-row-columns { min-height: 100% }` + `.damage-row-body` の `padding-bottom`)は壊しやすいので注意。努力値/実数値の7列グリッド+`tnum`。＋ボタンの破線→ホバーで primary 実線+薄塗り(位置だけが問題)。ビルド箱・技列箱に `--color-surface-alt`、カードに `--color-surface` という2段の面。攻守切り替えに追随した文言の言い換え。スライダーの薄トラック+primary進捗。**ダークの結果チップは4.6〜5.3:1でAA準拠**(直すのはライト側)。
