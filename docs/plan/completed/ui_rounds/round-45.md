## ラウンド45の要件(2026-07-30 ユーザー指示第29弾)

ユーザーの言葉: 「ui ダメージカードの圧縮表示だけ、他と比べて圧倒的に完成度が低い。改善して」

対象は `/box/[id]` のダメージ計算カード(相手ごとの1行)の**折りたたみ(圧縮)表示**のみ。展開表示・他画面は対象外。

### Coordinatorが着手前に測った現状(1920×1080、`/box/c8680844-dd43-42a4-bdf1-f3de11fe3267`、「すべて折りたたむ」クリック後、Playwright実測)

1枚目カード(カイリュー、攻撃・確2):
- `.card-damage`: height=116.06px
- `.damage-row-build`(左のビルド箱): x=748.98, **width=340px固定**(42-D4「圧縮後も左右のビルド/ダメージの幅の配分を維持する」による確定仕様)
- `.damage-sprite-box`: 80×80、`.damage-row-collapsed-summary`(名前+攻守バッジ+実数値6つ): width=115.2px
  → アイコン(80)+gap(6.4)+この115.2pxで**340pxのうち実際に使っているのは約202pxだけ**。**残り約138pxが技列側の開始位置(x=1098.6)まで何もない空白のまま続いている。**
- `.damage-row-collapse-toggle-button`(右下の折りたたみ切替chevron): y=166.09、カード下端(bottom基準)固定。中身(アイコン+summary、align-items:center)は縦中央寄せなのに対しchevronだけ下端に張り付き、周囲に大きな余白が残る。

原因: `.damage-row-collapsed-summary`に`flex-grow`が無く、中身(実数値6つが2行固定グリッド)の自然幅ぶんしか広がらない。展開時に同位置へ入る`.damage-row-build-left`は`flex:1 1 auto`で残り幅いっぱいに伸びるのに対し、圧縮時だけこの挙動が無い。

## Step2: UIレビュアー・プレイヤー視点レビュアーの講評(sonnet、2026-07-30)

ユーザー指示だけのラウンドのため、UI/UXの網羅講評ではなく**この画面固有の完成度問題に絞って**UIレビュアー・プレイヤー視点レビュアーの2体を起動した(UXレビュアー・統一感レビュアーは今回省略。統一感は実装後に変更領域限定の軽量パスとしてStep6で確認する)。

### UIレビュアーの指摘(優先度A/B/C、Coordinator統合後の番号で記載)
- 左ブロック内約138pxの空白(上記実測と同じ結論。`.damage-row-collapsed-summary`に`flex:1 1 auto`が無いのが原因)
- 折りたたみchevronがカード下端に張り付き、圧縮時のコンテンツ中心(縦中央)とズレて浮いて見える
- 実数値の性格補正(上昇/下降)が圧縮表示では色のみで表現され、展開表示にある▲/▼記号が消えている(WCAG 1.4.1、色のみへの依存)
- (要検証)メガカメックスのカードだけ詳細設定行("はれ・グラスフィールド・防御側どく・特攻+6・特防+6")が2行に折り返って見える疑い。42-D5の「1行+ellipsis」契約と食い違う可能性

### プレイヤー視点レビュアーの指摘(検算: カイリュー・ハバタクカミの実数値・ダメージ範囲はjpokeの計算式と完全一致、エンジン側の数値に問題なし)
- 「攻撃」「防御」バッジ(圧縮時は色付きピル1個だけの読み取り専用表示)は、%がどちらのHPを基準にしているかを示していない。攻撃=相手のHPを分母(与ダメ)、防御=pinned individualのHPを分母(被ダメ)だが、展開時のような両方見えるタブ構造が無いため誤読しやすい
- 技列が複数あるとき(例: カイリューの「スケイルショット(2発)+フレアドライブ」)、合計行「確2」が何を数えているか(技セット周回数かヒット数か)が圧縮表示だけでは伝わらない
- 詳細設定チップのうち状態異常だけ「防御側」等の側prefixが付き、ランクチップ(特攻+6等)には付かず表記が不統一
- 性格▲/▼記号消失は上と同一指摘(UIレビュアーと重複、統合済み)
- (優先度C)技名の「(N発)」がユーザー仮置きの最小値か固定ヒット数かの区別がつかない → 技データとの紐付けが要る大きめの変更なので今回は見送り
- (検証不能)列番号付き詳細設定(技列2つ以上でランク等が列ごとに異なる場合の表記)は、渡したスクショに実例が無く未検証

## Step2.5: Coordinator統合・裁定

- UI/プレイヤー視点の両レビュアーが独立に指摘した「▲/▼記号消失」は1件に統合。
- 「確N合計の意味」「バッジの%基準」はドメイン正確性の問題であり見た目の完成度そのものではないが、圧縮表示の情報量を削った結果として顕在化した問題であり、かつ**文言変更のみで対応可能(新規UI要素の追加はしない)**と判断できるため、Priority Aの空白・chevron・記号と同じラウンドで対応する。新規要素の追加が要る大掛かりな対応(基準ポケモンのアイコン表示等)は見送り、テキストのみの対応に限定する。
- 「確N合計」の注記は、totalBlock(`.damage-row-total`)が展開/圧縮で共有要素のため、圧縮時のみの条件分岐が必要。実装コストが見た目の空白修正より重いため、Priority Bとし「対応できればでよい、無理に大きな変更をしない」と実装者に明記する。
- 「詳細設定チップの側prefix統一」「メガカメックスの折り返し確認」はPriority B。
- 「(N発)仮置き値」「列番号詳細の追加検証」はPriority C・今回スコープ外。次のユーザー判断待ちキュー・次回講評で扱う。

### 優先度A(必ず直す)
- **A-1 左ブロックの約138px空白**(指摘者: UI): 【問題】上記実測どおり。【提案】
  1. `#opponent-notes-section .damage-row-collapsed-summary`に`flex: 1 1 auto;`を追加。
  2. `.damage-row-collapsed-stats`をCSS Gridの3列(`grid-template-columns: repeat(3, 1fr)`)にし、`.damage-row-collapsed-stats-line`に`display: contents;`を指定して2行(H/A/B・C/D/S)を3列グリッドへ直接参加させる(H↑C、A↑D、B↑Sが縦に揃う)。クラス名・マークアップは変更しない。
  3. 余裕ができた分、`.damage-row-collapsed-stat`のfont-sizeを0.82rem→0.88rem程度に上げてよい(実測して窮屈にならない範囲で)。
- **A-2 折りたたみchevronの縦位置**(指摘者: UI): 【問題】上記実測どおり(bottom基準でカード下端に張り付き、コンテンツ中心とズレる)。【提案】圧縮状態限定で縦中央寄せにする。
  ```css
  #opponent-notes-section .card-damage[data-collapsed="true"] .damage-row-collapse-toggle-button {
    top: 50%;
    bottom: auto;
    transform: translateY(-50%);
  }
  ```
  展開時のbottom基準はそのまま維持。
- **A-3 性格補正▲/▼記号の追加**(指摘者: UI・プレイヤー視点、重複統合): 【問題】色のみで上昇/下降を表現しており、展開表示にある▲/▼記号が圧縮表示に無い。【提案】新色は作らず、`.damage-row-collapsed-stat-key`(または値の前後)に展開表示と同じ▲/▼記号を文字として追加する。色トークン(`--stat-up`/`--stat-down`)はそのまま流用。
- **A-4 「攻撃/防御」バッジの文言明確化**(指摘者: プレイヤー視点): 【問題】圧縮時のバッジ(`.damage-row-collapsed-direction`、読み取り専用)が「攻撃」「防御」の2語だけで、%がどちらのHP基準かを示さない。【提案】**新規UI要素は追加せず、テキストのみ変更する。** 候補: 「攻撃」→「与ダメ」、「防御」→「被ダメ」(与ダメ=相手HP基準、被ダメ=自分HP基準であることが1単語で伝わる)。ただし展開時の**インタラクティブな**セグメントコントロール(`.damage-row-direction-option`、「攻撃」「防御」)は変更しない(そちらは別の確定仕様・別要素)。**変更対象は圧縮時の読み取り専用バッジのテキストのみ**(`damage-calc.ts`の`collapsedDirectionEl.textContent`まわり)。最終的な文言は実装者判断でよいが、「相手の役割」ではなく「%の基準」が伝わることを優先すること。

### 優先度B(直せるとよい)
- **B-1 詳細設定チップの側prefix統一**(指摘者: プレイヤー視点): 状態異常チップには「防御側」等の側prefixが付くが、ランクチップ(特攻+6等)には付かず、同じ行内で表記ルールが混在している。全チップに側prefixを付けるか、状態異常も省略するか、どちらかに揃える。実装コストが高ければ今回は見送ってよい(C相当に格下げ可、実装者判断)。
- **B-2 メガカメックスカードの詳細設定行の折り返し確認**(指摘者: UI): 「はれ・グラスフィールド・防御側どく・特攻+6・特防+6」が2行になっていないか実機で確認し、なっていれば`.damage-row-collapsed-detail-line`のellipsis設定(nowrap/overflow/text-overflow)が効いているか調べる。
- **B-3 「確N」合計の意味の補足**(指摘者: プレイヤー視点): 技列が2つ以上あるときの合計行に、何を数えているか伝わる一言(例: 技名段の技が2つ以上あるときだけ結果段に軽い注記)を足せないか検討する。**totalBlock(`.damage-row-total`)は展開/圧縮で共有要素なので、圧縮時のみの対応が難しければ無理に実装しない(見送りは可、その場合は積み残しに記録)。**

### 優先度C(今回は対応しない・次回以降)
- 技名の「(N発)」がユーザー仮置きの最小値か固定ヒット数かの区別がつかない問題(技データとの紐付けが要る大きめの変更)
- 列番号付き詳細設定(技列2つ以上でランク等が列ごとに異なる場合)の表記が誤読なく伝わるかの追加検証(今回のスクショに実例が無かった)

### 維持すべき点(壊さないこと)
- アイテム/テラスタルのアイコン表示(42-D4準拠、スプライト右下)
- 技名(1段目・太字)→詳細設定(2段目・muted)→結果バー(3段目、`.damage-row-total-result`流用)の3段構成(42-D5)
- 削除ボタン(×、右上)の位置・サイズは展開/圧縮で共通クラス
- 詳細設定行が全既定値のときは段自体を出さない省略ルール
- 10発以上は確定数ラベル非表示(42-D3)、ヒット数1の技には「(1発)」を付けない
- ライト/ダーク間で新たな差は生じていない(2レビュアーとも確認済み)

### 統一感レビュアーの軽量パス(変更領域限定)と対応

実装後、変更領域(圧縮表示)限定で統一感レビュアーを起動(講評ではなく規格表と逸脱一覧)。指摘のうちCoordinatorが規格違反(このラウンドで新たに生まれた既存規格からの逸脱)と裁定した3件を追加修正:
- **実数値のfont-weight**: 展開700・圧縮は未指定(既定400)だった → `.damage-row-collapsed-stat-value`に`font-weight:700`を追加して統一
- **「(技の合計)」注記のfont-size**: 実装者の仮置き値`0.62em`(親基準で約9.58px)が、このプロジェクトのmuted系注記の確立規格(`.damage-condition-chip`等の0.76rem=12.16px)を下回っていた → `0.76rem`に修正
- **3列gridのcolumn-gap単位**: `0.5em`(祖先のfont-size変化に追随してしまう入れ子リスク、20-G3と同型)→ `0.5rem`に修正(実測値8pxは変えない)

以下はCoordinatorが「意図的な差異」と裁定し、**修正しない**:
- ▲/▼記号の付与位置(展開=見出し文字側/圧縮=実数値側)と記号-数値間の余白(展開2.75px/圧縮0px): 圧縮表示はkey+valueを詰めた1行表現のため、値に記号を直接連結する方がこの文脈では合理的。展開の見出し側配置をそのまま移植する必然性は無いと判断
- ランクチップの側prefix有無が展開(無し)/圧縮(B-1で追加)で異なる: これはB-1の要件そのもの(圧縮表示内の不統一を正すためにあえて展開と別の表記にした)であり、規格違反ではなく意図した変更
- 与ダメ/被ダメバッジの角丸(6px)がアプリ標準の`.badge`ピル(999px)と異なる、条件表示の形状(ピル vs プレーンテキスト)が展開/圧縮で異なる: いずれもラウンド36・42由来の既存仕様で、今回のラウンドが生んだ逸脱ではないため対象外(次回ユーザー判断待ちの棚卸し候補として記録)
