# UI改善ラウンド 05

[← 索引](../ui_plan.md)

## ラウンド5の要件(2026-07-26 ユーザー指示 第2弾)

### ボックス画面 `/box`
- **アイテム・技を表示する。** ラウンド4で189px正方形にした際、持ち物・技を表示から落としたが、これを戻す。正方形の制約と両立させること(カードを多少大きくする、レイアウトを詰める等は実装者判断。ただし「1/3の面積・正方形」という方針自体は維持する)。

### 個体編集画面 編集カード
- **入力ボックスのラベルをやめ、placeholder に「特性」などの文言を表示する。** ラウンド3 A-8 で横並びラベルに統一したが、これを撤回して placeholder 方式に戻す。**`aria-label` は必ず残すこと**(スクリーンリーダー対応)。
- **タイプアイコンが圧縮されて意味不明。英字はいらないので、左側のマークだけ丸くトリミングした画像を新規作成して使う。**
  - 現状はPokeAPIの横長リボン画像(アイコン+英字)をCSS(`object-fit: cover; object-position: left center`)で切り出しているが、タイプごとに余白が違い**フェアリー等でアイコンが中央からずれて英字が混じる**ことを実測で確認。→ **切り出し済みの画像をビルド時に生成して `public/` に置き、それを参照する方式に変える。**
- **ステータスラベルをクリックしても上昇下降補正を切り替えられない。**
  - 実測: クリックイベント自体は発火しており、防御をクリックすると「防御↑」に変わる。しかし **(1) 押せることを示す見た目が無い (2) ある能力を↑にすると別の能力の↓が黙って消える (3) 2回目のクリックで全補正が消える** という挙動で、実質操作できない。→ **↑と↓を別々の当たり判定にする等、操作方法から作り直す。**
- **「実数値」ラベルの左あたりに `66 - (努力値合計)` を表示**し、あと何ポイント余っているかを確認できるようにする。(※ラウンド3 B-7 で「合計上限が無いので努力値合計を削除」としたが、**チャンピオンズルールの上限は66であるとユーザーが提示したので撤回**。残ポイント表示として復活させる。)

### 個体編集画面 ダメージカード
- **特性などの入力ボックスが無駄に大きく、相手ポケモンのアイコンが小さすぎる。** 入力欄をさらに詰め、相手の公式絵を大きくする。
- **相手ビルドのカードと技カードが同じ高さのせいで技カードの空きスペースが目立つ(再掲)。** ラウンド4で `align-self: flex-start` により技列を内容高さに縮めたが、ユーザーから再度指摘があった。**現状を実機で確認したうえで、まだ空きが目立つなら構成そのものを作り直すこと。**
- **詳細設定でONした要素をカードに表示する。**(ラウンド3 A-6(5)で条件チップを入れたが、対象や視認性が不十分な可能性。ONの項目が漏れなく出ることを確認・改善する)

### 個体編集画面 ダメージ詳細設定(構造変更)
- **⚙クリックでポップアップ(`<dialog>`)を開く方式をやめ、カードをクリックすると右サイドバーに詳細設定を表示する方式にする。** カードの面積による制限を受けなくなり、レイアウトの自由度が生まれる。
  - ページが「左=編集フォーム / 中央=ダメージ計算カード / 右=詳細設定サイドバー」の3カラム構成になる。
  - どのカードが選択中かが分かること。未選択時のサイドバーの見せ方も設計すること。
  - `<dialog>` を廃止する場合も `.damage-column-detail-button` 等のクラス名・要素は残すこと(JS/E2E依存)。

  > **この時点(ラウンド5)の方針であることに注意。** ここでの「カードをクリックすると」の主語はこの時点では**カード全体(相手ビルドの箱を含む)**だったが、ラウンド6〜7でさらに一歩進んだ。ラウンド6で「サイドバーを開くのは⚙クリックではなく箱そのものをクリック」に変わり、ラウンド7(方針転換)で**技列の箱をクリックしたときだけ**サイドバーが開き、**相手ビルドの箱のクリックは何も起こさない**という仕様に確定した(相手ビルドの箱は特性・アイテム等の入力欄そのものであり、サイドバーで開くものが無いため)。また `.damage-column-detail-button` は当時「残す」判断だったが、ラウンド6で⚙ボタン自体が全廃されたため、このクラス名は**要素の無いクラス名として温存**されている(JS/E2E依存のみが残置理由)。詳細は「ラウンド6〜7の実施結果」を参照。
- **天候・フィールドはアイコンで選択式にする**(セレクトをやめる)。
- **壁は種類が不要。on/off の切り替えだけで計算できる。** リフレクター/ひかりのかべ/オーロラベールの区別をやめ、1つのトグルにする(物理・特殊のどちらが飛ぶかは技側で決まるため)。
- **能力ランクは攻撃側・防御側でそれぞれ1つずつ入力があれば計算できる。** 現在の「攻撃側5能力 + 防御側5能力 = セレクト10個」をやめ、攻守それぞれ1つの入力にする。
  - **要検証**: エンジン(`pyodide-engine.ts` の `PokemonSpec.boosts`)は能力ごとのランクを受け取る実装。攻撃側は「使う技が物理か特殊か」で A/C のどちらに載せるか、防御側は同様に B/D のどちらに載せるかを**技から自動判定して振り分ける**必要がある。素早さランクは計算に影響しないので落としてよい。実装前にエンジン側の契約を必ず確認すること。

## ラウンド5の実施結果(2026-07-26)

### 実施済み
| 対象 | 結果 |
|---|---|
| `/box` | カードを **218×218px の正方形**に。持ち物を公式絵右下の22px丸バッジ(画像のみ)、技を実数値グリッド下の2×2グリッドで復活。検索対象は不変 |
| タイプアイコン | PokeAPIの横長リボンから**マーク部分だけを切り出した96px正方形PNGを生成**(19タイプ×通常/テラス=38ファイル、約307KiB)。`scripts/type-icons/generate_type_icons.py`(`npm run generate:type-icons`)で再生成可能。切り出し位置は画像内容から自動検出(白系前景のrun-length解析)。`typeIconUrl()` / `teraTypeIconUrl()` を `src/lib/sprite-urls.ts` に追加 |
| `/box/[id]` | ラベル→placeholder、タイプアイコン差し替え、▲▼独立ボタンによる性格切替、残りポイント表示、相手アイコン72px、**詳細設定の右サイドバー化(3カラム)**、天候/フィールドのアイコン選択、壁のon/offトグル、能力ランクの攻守1つずつ |

**実測(1920×1080)**: 3カラムは 左440px(x=276) / 中央779px(x=738) / 右360px(x=1540)。1600px以上で3カラム常時表示(sticky)、1600px未満は右からのオーバーレイ。ダメージ計算カードは1枚 **396〜430px**。

**計算の妥当性検証**: 壁OFF 155〜185 → 物理技+壁ON 75〜90(リフレクター自動選択)、特殊技 33〜39 → 16〜19(ひかりのかべ自動選択)。攻撃側ランク+2で 155〜185 → 180〜216、防御側ランク+2で 80〜95。

**後方互換**: 壁は旧データのリフレクター/ひかりのかべ/オーロラベールのいずれか1つでも立っていれば `wallEnabled=true` と解釈。能力ランクは旧配列から atk→spa(攻撃側)、def→spd(防御側)の順で最初の非ゼロ値を採用。エンジン(`pyodide-engine.ts`)は**変更していない**(UI側で配列を組み立てるだけで対応可能だった)。

### 実装中に見つかったバグ
- `/box`: `.card-item-badge { display: flex }` が `[hidden] { display: none }` に詳細度で勝ち、**持ち物なしの個体で空の白丸バッジが出続けていた**(この罠は今セッションで2回目)。
- `/box`: モバイル390pxで `minmax` を広げたら1列に落ちる回帰を実測で検知し、2列を維持するよう戻した。

### データ事故(記録)
検証スクリプトがステータスラベルをクリックした際、**自動保存が走ってメガリザードンXの性格が「いじっぱり」→「まじめ」に書き換わった**。APIで復旧済み。この事故自体が要件3(クリックUIの分かりにくさ)を裏付けている。**以後、自動保存のある画面で状態を変える検証をするときは、元の値をAPIで控えてから行うこと。**

### 積み残し・要判断
1. **ダメージ計算カードの密度が後退している。** ラウンド3で303px(3枚が1080px内)まで縮めたが、ラウンド5の2段組化(相手ビルドを上段全幅・技列を下段)で **396〜430px** に戻り、**1画面に2枚強しか入らない**。「技列の空きスペースを消す」というユーザー指示は達成されたが、「複数体を並べて同時に見る」という画面の目的とはトレードオフになっている。**どちらを優先するかユーザーに確認が必要。**
2. 相手ビルド箱の3列化は `@container` の閾値480px固定で、技列が非常に多い(横スクロールが伸びる)ケースは未検証。
3. サイドバーの天候/フィールドアイコンは手描きSVGで、デザインの作り込みの余地あり。
4. ラウンド4からの積み残し: 持ち物欄の長い値の見切れ、`:placeholder-shown` の破線表現、結果チップの主役化(ラウンド3 C-4)。
5. `/box`: テラスタイプを正方形カードから落としたまま(公式絵から読み取れない情報なので要判断)。

### 再開方法
このUI改善ループは `.claude/skills/ui/` にスキルとして切り出してある。**`/loop ui` で起動・再開できる**(1回の呼び出し=1ラウンド、状態はこの計画書に永続化)。踏んだ罠は `.claude/skills/ui/references/pitfalls.md` に集約。
