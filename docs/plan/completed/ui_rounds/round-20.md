### 20-G1 アイテム・タイプ・テラスタル画像が小さすぎる

> 「アイテム・タイプ・テラスタル画像が小さすぎる」

**現状の実測(全ページ横断)**:

|---|---|---|
| `box/index.astro:379-380` | `.card-item-badge`(持ち物) | **22×22px** |
| `box/[id].astro:2208` | `#item-image`(持ち物) | **28×28px** |
| `box/[id].astro:872` | `.type-badge-inline .type-badge-img`(テラス) | **15×15px** |
| `box/[id].astro:844-847` | `.type-badge-img`(種族タイプ・単一) | **16×16px** |
| `box/[id].astro:867` | `.type-badge-multi .type-badge-img`(複合時) | **14×14px** |
| `box/[id].astro:1263-1268` | `#species-type-badge .type-badge-img` | **14×14px** |
| `box/[id].astro:1244-1249` | `.damage-type-badge-img`(ダメージ計算カード内) | **18×18px** |
| `pokemon/[name].astro:473` | タイプアイコン(識別ブロック) | 28×28px |
| `moves/[name].astro:307-311` | `.move-identity-type-chip img` | 40×40px |

**元画像には余力がある**: `public/type-icons/{1-19}.png` と `public/type-icons/tera/{1-19}.png` は**実測96×96px**。拡大しても劣化しない。

**提案(サイズ規格をトークン化する)**。`global.css` に3段階の規格を定義し、各ページはこれを参照する:

| トークン | 値 | 用途 |
|---|---|---|
| `--icon-size-sm` | **20px** | 密なグリッド内(ダメージ計算カードの相手ビルド箱、`/pokemon` の技一覧行) |
| `--icon-size-md` | **28px** | 一覧カード・編集フォームの標準(ボックスカードの持ち物/テラス、左パネルの種族タイプ/持ち物/テラス) |
| `--icon-size-lg` | **40px** | ページの主役(`/moves` の識別チップ、`/pokemon` の識別ブロック) |

**適用**: 上表の 14〜18px はすべて `--icon-size-sm`(20px)以上へ、22〜28px の一覧・フォーム系は `--icon-size-md`(28px)へ。`moves/[name].astro` の 40px は `--icon-size-lg` に置き換えるだけで**見た目は変わらない**(規格に取り込むだけ)。

**注意**: **持ち物画像だけは PokeAPI のドット絵(32×32相当)を都度フェッチしている**(`sprite-urls.ts:72` `itemImageUrl()`)。28pxまでは実寸内だが、**40pxにすると元絵が粗く見える**。持ち物は `--icon-size-md`(28px)を上限とし、`image-rendering: pixelated` は付けない(他のアイコンと質感が割れるため)。

### 20-G2 カードホバーで動くのが鬱陶しい

> 「カードホバーで動くのが鬱陶しい。軽くハイライトする程度にする。」

**現状**: `global.css:332-336` の `.card:hover, .card:focus-within { box-shadow: var(--shadow-md); transform: translateY(-2px); }`。**`transform` を使う hover はプロジェクト全体でここ1箇所だけ**(`src/**` を grep 済み)。`.card` は `/box` のポケモンカードと `/box/[id]` のダメージ計算カードの両方に効くので、**この1箇所を直せば全ページに波及する**。

**提案**:
- `transform: translateY(-2px)` を**削除**する。
- 代わりに `border-color: var(--color-primary)` + `background: color-mix(...)` 程度の**静止したハイライト**にする。`box-shadow` は `--shadow-sm` → `--shadow-md` の変化を残してよい(位置は動かない)。
- `transition` から `transform` を外す。
- `prefers-reduced-motion` の分岐(`global.css:342-350`)は `transform: none` を書いているだけなので、`transform` 自体が無くなれば**この分岐は不要になる**。残骸を残さず消すこと。
- **`.is-selected` の `border-color: --color-primary` と衝突しないこと。** hover のハイライトは選択中の見た目を上書きしてはいけない(選択が分からなくなる)。hover 側は `background` の変化を主にし、border は選択中でないときだけ変える。

### 20-G3 文字が小さい(下限12px)

> 「文字が小さい。UIにおける推奨サイズを下回らないようにする。」

**ユーザー確定(2026-07-27)**: **下限は12px。ボックス一覧カードは拡大して収める。**

**受け入れ条件**: **画面に描画されるすべてのテキストの computed font-size が 12px 以上**。`getComputedStyle` で実測して確認する。

**現状の違反箇所(grep 実測。rootは16px)**:

| ファイル:行 | 値 | 実px |
|---|---|---|
| `components/AppSidebar.astro:175` | `0.65rem` | 10.4px |
| `box/index.astro:538` | `0.64em` | ≈10.2px |
| `box/index.astro:545` | `0.74em` | ≈11.8px |
| `box/index.astro:555, 560` | `0.7em`(親がem指定なので入れ子でさらに縮む) | **≈8.3px** |
| `box/index.astro:584` | `0.64em` | ≈10.2px |
| `box/[id].astro:464, 540, 971, 1960, 1979, 2007, 2037` | `0.72rem` | 11.5px |
| `box/[id].astro:1323, 1418, 1436, 1612, 1929` | `0.66rem` | 10.6px |
| `box/[id].astro:1330, 1597, 1993` | `0.68rem` | 10.9px |
| `box/[id].astro:1357` | `0.62rem` | **9.9px** |
| `box/[id].astro:509` | `11px` | 11px |
| `box/[id].astro:558` | `10px` | 10px |
| `global.css:849` `.badge` | `0.78em` | 親が13.6pxのとき **10.6px** |

**12px以上で違反していないもの**(触らない): `0.76rem`(12.16px)、`0.78rem`(12.5px)、`--font-size-xs: 0.75rem`(12px)、`--font-size-sm: 0.85rem`(13.6px)。

**方針**:
- **`em` の入れ子をやめて `rem` に統一する。** `box/index.astro` の `0.7em` が8.3pxまで落ちているのは親も `em` 指定だからで、`rem` にすれば事故らない(→ `pitfalls.md` の「em の入れ子事故」は `box/[id].astro:1347` にも前例あり)。
- `.badge`(`global.css:849`)は `0.78em` → `var(--font-size-xs)`(12px固定)にする。
- **`00-foundation.md` のタイポグラフィ原則(数値グリッドの階層差)は撤回しない。** あの原則は「16.8px と 24px と 12.16px と 11.8px を無理に1つに揃えるな」という話で、**下限を12pxに切り上げること自体とは矛盾しない**。ただし表中の「11.8px(`/box` 一覧カードの `.card-stat-real-value`)」だけは**12px以上に改める**(下記 20-B3 でカード幅を広げて吸収する)。実装後に `00-foundation.md` の当該行を更新すること。

## ボックス画面 `/box`

### 20-B1 アイテム画像の右にテラスタイプ画像も表示

> 「アイテム画像の右にテラスタイプ画像も表示」

**現状**: テラスタイプ画像は**カードのどこにも無い**。`buildCardTooltip()`(`box/index.astro:770-784`)が `<a>` の `title` 属性に文字列として入れているだけ。ラウンド4で「タイプ/テラスバッジの常時表示を撤回」した経緯があるが、**今回のユーザー指示が優先**する(撤回するのはテラスのみ。通常タイプバッジは戻さない)。

**提案**:
- 持ち物バッジ `.card-item-badge`(`box/index.astro:988`、公式絵の右下に絶対配置)を**ラッパー `.card-badge-row` に入れ、その中で持ち物 → テラスの順に横並び**にする。
- テラス画像のURLは `sprite-urls.ts:111` の `teraTypeIconUrl(typeNameJa)` を使う(既存関数。`box/index.astro` は現在 import していないので追加する)。
- サイズは 20-G1 の `--icon-size-md`(28px)。
- **テラス未設定の個体では出さない。**

**必ず踏む罠(3つとも `pitfalls.md` に実例あり)**:
1. **`[hidden]` は詳細度で負ける。** 新設する `.card-tera-badge` に `display: flex` を書くなら `.card-tera-badge[hidden] { display: none }` を**必ずセットで書く**。`.card-item-badge` は同じ事故を2回起こしてから `box/index.astro:400-402` で対策済み。ラッパー `.card-badge-row` も、中身が両方無いときに**空の白丸が残らないか**確認すること。
2. **Astro の scoped style は JS 生成要素に効かない。** `box/index.astro` はカードを `document.createElement()` で生成しているため、**新しいCSSは必ず `<style is:global>`(269行〜)側に書く**。通常の `<style>` に書くと一切効かない。
3. **非同期の描画関数を `void` で投げっぱなしにしない。** 既存の `applyItemBadge()` は `void` で並行実行されている(`box/index.astro:994`)。テラスを足すと**DOM挿入順が実行順に依存して「持ち物の左にテラスが来る」事故**が起きる(ラウンドでの実例あり)。**挿入順を await で直列化するか、両方の `<span>` を最初から静的な順序でDOMに置いて src だけ後から入れる**(後者を推奨。点滅も防げるので初期値を `hidden = true` にする)。

### 20-B2 技を中段、ステータスを下段に配置

> 「技を中段、ステータスを下段に配置」

**現状の順序**(`box/index.astro:1002-1050`、`.card-body` 内):
1. `.card-name`(名前)
2. `.card-stat-grid`(実数値6列グリッド)
3. `.card-moves-grid`(技2×2)

→ **要望と実数値/技が逆。** 2と3を入れ替えて `名前 → 技 → ステータス` にする。

**注意**: `.card-moves-grid` には**技0件でも高さを揃えるための `min-height`**(`box/index.astro:581`)がある。順序を入れ替えると、この高さ確保が「最下段の余白」ではなく「中段の空白」になるので、**技0件の個体で中段にぽっかり穴が空かないか**を実際に見て確認すること(該当個体: メガフシギバナ `42ccb527-...`)。

### 20-B3 カードの拡大(20-G3 の受け皿)

**現状**: `box/index.astro:154` `grid-template-columns: repeat(auto-fill, minmax(210px, 1fr))`、カードは `aspect-ratio: 1/1` の正方形(`324, 354`行)。

**提案**: `minmax(210px, 1fr)` → **`minmax(240px, 1fr)`**。1920px で 1行7枚 → **6枚**になる。狭い幅のブレークポイント(`166`行 `minmax(150px, 1fr)`)も **`minmax(170px, 1fr)`** に上げる。

**受け入れ条件**: 240pxの正方形の中に「公式絵 + 名前 + 技2×2 + 実数値6列」が**すべて12px以上で、はみ出さず・省略されず**収まること。収まらない場合は `aspect-ratio: 1/1` を捨てて縦長にしてよい(**その場合はカードの高さを全枚数で揃えること**。ラウンド4で「高さがバラバラで散らかって見える」と指摘された経緯がある)。判断したら理由を報告に書くこと。

## 個体編集 `/box/[id]` — ヘッダー

### 20-H1 ニックネーム表示を削除

> 「ニックネーム表示を削除」

**調査結果: ヘッダーのタイトルは既に種族名のみ**(`box/[id].astro:87` `pageTitle = pokemon ? pokemon.species_name : "個体編集"`。ラウンド11-1で対応済み)。**それでもユーザーが「まだ出ている」と言っているので、実装者はまず実画面を見て、ニックネームがどこに出ているかを特定すること。** 候補:
- `updateHeaderIdentity` 系スクリプト(`box/[id].astro:2963-2984`)が実行時にタイトルを書き換えている可能性
- トップバーの `topbar-status` スロット(`100-111`行)
- `document.title`

**特定できたらそこを消す。特定できなければ「ヘッダーにニックネームは出ていない」と実測つきで報告し、この項目は完了扱いにしてよい**(勝手に他の場所のニックネームを消さないこと)。

**左パネルのニックネーム入力欄 `#nickname`(`2182`行)は絶対に消さない。** `textInputIds`(`3299`行)と `buildPayload`(`3118`行)が参照しており、消すと**保存時にニックネームが空で上書きされて消える**(`PUT /api/owned-pokemon/:id` は全項目上書き契約)。

### 20-H2 ログイン情報をサイドバーの一番下に移動

> 「ログイン情報はサイドバーの一番下に移動」

**現状**: `AppLayout.astro` が**2箇所に重複してマークアップ**している。モバイル用 `.app-topbar-account-mobile`(92-107行)とデスクトップ用 `.app-topbar-account-desktop`(134-149行)。表示切替はCSSのみ(297-320行)。

**提案**:
- **両方とも削除**し、`AppSidebar.astro` の `</nav>` 直後・`</aside>` 直前(79-80行)に1箇所だけ置く。
- `.app-sidebar` は現在 `position: fixed` だが **flex ではない**(`global.css:1054-1068`)。下端に貼り付けるには `display: flex; flex-direction: column` にして、追加ブロックに `margin-top: auto` を付ける。
- **この変更は全ページに影響する。** `/share/[slug]`(未ログインの第三者が見る公開ページ)ではサイドバーの出方が違うので、**ログイン情報が漏れていないことを必ず確認する**。
  - **判定方法に注意**: `page.content()` の文字列一致で調べると **`<style>` 内のセレクタ名にヒットして誤検知する**(ラウンド15の実例、`pitfalls.md`)。必ず `page.locator('.app-sidebar-account').count()` のように**DOMとして数える**こと。
- **`.app-topbar-account-desktop { display: none }` を `global.css` に書いてはいけない。** scoped style に詳細度で負けて、**モバイルでログイン表示が2箇所出て101pxの横スクロールが発生した実例**がある(`pitfalls.md`)。今回は要素ごと消すので該当しないが、残骸のCSSも一緒に消すこと。

**受け入れた副作用(ユーザー指示なので許容)**: モバイルではサイドバーがドロワーなので、**ログイン情報は「サイドバーを開かないと見えない」**ようになる。ログアウト導線も同様。

### 20-L4 ステータス補正の上下ボタンを三角形そのものに小型化

> 「ステータス補正の上下ボタンは三角形をボタン本体として小型化する。」

**現状**: `#nature-up-{key}` / `#nature-down-{key}`(`2317-2333`行)。**Unicode文字 "▲"/"▼" を表示する四角いボタン**で、`background` と `border` を持つ(CSS `502-517`行)。サイズ **22×20px**(460px以下では 18×17px、`558`行)。

**提案**:
- `background` / `border` / `border-radius` を撤去し、**CSSの三角形(`border-style` トリック)またはSVGそのものをボタン本体**にする。当たり判定は視覚的な三角形より少し広く取ってよい(`padding` で確保する)。
- 目標サイズ: 三角形の実寸 **10×6px** 前後、クリック可能領域は **14×12px** 程度。現在の22×20pxから縮む。
- 状態表現は `aria-pressed="true"` のときに**塗り色**で示す(現行の `521-529`行が上昇=赤系 / 下降=青系にしているのを踏襲。**新色は作らない**)。
- **`#nature-up-{key}` / `#nature-down-{key}` の ID は絶対に変えない。** `3336-3345`行と `3167-3170`行が `getElementById` で参照している。`aria-pressed` / `aria-label` / `title` も維持する。
- HP用の `.stat-nature-placeholder`(`2311, 2313`行)も同じ寸法に追随させること(位置合わせ用)。
- **20-G3 の12px下限はこのボタンには適用しない**(文字を表示しなくなるため。三角形は図形であってテキストではない)。

**検証時の必須注意**: このボタンをクリックすると**性格が変わって自動保存される**。ラウンド17で「メガリザードンXの性格がいじっぱり→まじめに書き換わり、気づかず次ラウンドの基準値になりかけた」**実際の事故がこのボタンで起きている**(`pitfalls.md` 冒頭)。検証前に `GET /api/owned-pokemon/:id` で全フィールドを控え、検証後に `PUT` で必ず戻すこと。

### 20-L5 メモ欄の高さ増加

> 「メモ欄の高さ増加」

**現状**: `#edit-form .memo-input { min-height: 4.4em; max-height: 10em; }`(`757`行)。ラウンドの経緯として「以前は200px近くまで膨らんでいたのを 10em に抑えた」というコメント(`750-756`行)がある。**今回はその上限を引き上げる方向なので、コメントも更新すること**(古い経緯だけ残すと次のエージェントが「また膨らんでいる」と誤診する)。

## 個体編集 `/box/[id]` — ダメージ計算

### 20-D1 確N=... の説明書きを削除

> 「確N=...の説明書きを削除」

**現状**: `<p class="damage-verdict-legend">確N=乱数最小でもN発で確定 / 乱N=N発目から確率で撃破 / 未撃破=このN発では倒せない</p>`(`2412-2414`行)。CSS `966-973`行。**ラウンド17の指摘A-5で追加したもの**。

**提案**: DOM ごと削除してよい(JS/E2E の参照は無い)。CSS も消す。**ラウンド17 A-5 の判断を撤回する**と計画書に明記済み(この節がその記録)。なお 20-D4 で「未撃破」という語自体が無くなるため、凡例の必要性はさらに下がる。

### 20-D2 「この個体が攻撃/受け」を「攻撃/防御」に

> 「この個体が攻撃・受け: 冗長。攻撃 / 防御で伝わる。直感的なUIにする。」

**⚠️ 知識ベースへの書き戻しが必須。** `.claude/skills/jpoke/` に volatile の記述が**1件も無かった**(grep 0件)。ui skill のルール「**知識ベースに無いことを調べてソースを読んだら、その回のうちに追記してから終わること**」に従い、`.claude/skills/jpoke/references/damage-calc.md`(または `integration.md`)に上記の**API・分類表・「効かないイベント」の一覧を出典つきで追記する**。これをやらないと次のラウンドで同じ調査を最初からやり直すことになる。

### ⚠️ 計画書の前提が実測で覆された件(重要)

**20-R3 で「攻撃側/防御側のそれぞれに全10件を置く」と指示したが、これは誤りだった。**
