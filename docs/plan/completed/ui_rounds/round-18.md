**現時点で値のずれは無い**(変換式 `8n-4`・ヌケニン特例 `base===1 → 1` とも4箇所で一致。同一個体の実数値が `/box`・`/box/[id]`・`/share` で 153/200/131/135/105/136 と揃うことも確認済み)。

**それでも統合する理由**: このアプリは**同じポケモンの実数値を4つの画面で見せる**。4箇所が独立に育つ構造では、片方だけ直す変更が入った瞬間に**画面ごとに違う数値が出る**。それはこのアプリの存在意義そのものを壊す種類の欠陥で、しかも「どの画面が正しいのか」がユーザーには判別できない。**壊れてから直すのでは遅い。**

### Coordinatorの制約: これは振る舞いを変えないリファクタリングである

- **表示される数値が1つも変わらないこと**が唯一の成功条件。**実装者には、統合の前後で4画面の実数値を実測して完全一致することを証明させる。**
- **同じラウンドでOHKO表示の修正(下記)を混ぜない。** リファクタリングと機能変更を同時に入れると、値が変わったときにどちらが原因か切り分けられなくなる。

### 次ラウンド(19)に回すもの

- **【新規・最優先】威力が固定値でない攻撃技14件すべてが `/box/[id]` で「ダメージ0・10発以上・0%」と表示される。** ラウンド17でOHKO技(じわれ)について見つかった問題を**Coordinatorが調査した結果、OHKO 4件だけでなく14件に及ぶことが判明した。**

  **調査結果(Coordinatorが実データとjpokeのソースで確認)**:
  - `public/master-data/detail/moves.json` で **`power: null` かつ変化技でない技は14件**: `いかりのまえば` / `いのちがけ` / **`カウンター`** / `がむしゃら` / `じわれ` / `ぜったいれいど` / **`ちきゅうなげ`** / `つのドリル` / **`ナイトヘッド`** / `はきだす` / `ハサミギロチン` / `ほうふく` / **`ミラーコート`** / `メタルバースト`
  - `ohko` フラグは `vendor/jpoke/src/jpoke/handlers/ability.py`(がんじょうによる無効化など)では扱われるが、**`core/lethal.py` と `core/damage.py` には `ohko` の参照が0件**。つまり `/box/[id]` が使う `calc_lethal` の経路では**OHKO技も固定ダメージ技も特別扱いされず、威力nullがそのままダメージ0になる。**
  - **これはOHKO技だけの話ではない。** カウンター・ミラーコート・ちきゅうなげ・ナイトヘッド・いのちがけ・がむしゃら・メタルバースト等、**対戦で普通に使われる技が「まったくダメージが出ない技」として表示される**。プレイヤーが「この技は無意味」と誤解しうる。
  - **`/moves/[name]` では既に正しく扱えている**: 同じ `power == null` の条件で期待値を出さず、「この技は威力が固定値ではなく特殊な計算式(相手の残りHPや受けたダメージ量など)で決まるため、期待値は算出できません」と理由を表示する。**同じ語彙を `/box/[id]` に移植すればよい。**
  - **したがって次ラウンドの方針**: `/box/[id]` のダメージ計算で、選択された技の威力が `null` のときは「確N/乱N/未撃破」ではなく**算出できない理由を表示する**。OHKO技はさらに「一撃必殺(命中30%)」であることが分かるとなお良いが、**まず「0ダメージだと誤解させない」ことが先。**
- **優先度Cの棚卸し**(→ round-17.md「優先度C・要判断」、round-16.md、round-15.md)。小粒な項目が溜まってきている。
