### 36-1: 折りたたみ状態の設計(要実装者の判断・下記を満たせば実装方法は自由)

- **状態はDBに保存しない**(ユーザー指示に永続化の言及が無い。ページ再読み込みでは既定=展開状態に戻ってよい)。折りたたみ状態はJS側のメモリ内状態(例: 各行オブジェクトに`collapsed: boolean`を持たせる、または`.card-damage`に`data-collapsed="true"`を付与するだけでよい)で管理する。
- **折りたたみ中は入力欄を編集不可にする**(「編集できないかわりに」という要件どおり)。実装方法の候補: 折りたたみ時に名前/特性/持ち物/テラス/技/ヒット数/EV等の入力欄を`disabled`にする、または折りたたみ用のコンパクト表示(読み取り専用の`<span>`等)に一時的に差し替える。**既存の`renderRow`/各種update関数を壊さないこと**(展開に戻したときに元の入力値・自動保存が正しく機能することを必ず確認する)。
- **折りたたみ時に隠す要素**: `.damage-row-build-left`の入力欄群、`.damage-ev-grid`(このままでは高さ予算(147.66px)に収まらないため)、`.damage-row-techniques-row`内の個別`.damage-column`群、`.damage-add-column-slot`。
- **折りたたみ時に代わりに出す要素**:
  - ポケモンアイコン(`.damage-sprite-box`。高さの基準なのでこのまま、または少し縮めてもよいが「アイコンの高さに全て収める」という制約の基準そのもの)
  - 攻撃/防御の向き(現在の`.damage-row-direction-toggle`の代わりに、読み取り専用の小さいラベル/アイコンでよい)
  - 相手ポケモン名(読み取り専用テキスト。入力欄の値をそのまま表示する)
  - アイテム/テラスのバッジ(既存の`.damage-item-badge`等を流用してよい)
  - **累計結果を「ひとつの技カード」として集約表示**: 既存の`.damage-row-total`(`.damage-row-total-result`、確定数+ダメージ範囲)をそのまま流用し、個別の`.damage-column`をすべて隠して**この1つだけ**を技カードの位置に見せる、という実装が最も既存コードと整合的(新しい集計ロジックを書く必要がない。DOM構造上、結果は既にjpokeの加算計算済みの値がここに入っている)。
- **高さの制約**: 折りたたんだ`.card-damage`全体の高さが、実測した「現在のポケモンアイコンの高さ」(147.66px、または実装時の実測値)以下になること。1行に収まらない場合は、アイコン+名前+攻守+バッジを横一列(flex-direction:row)に並べ、その右に集約結果を続けるレイアウトにする(「縦に折りたたむ」は「カードの縦方向の専有面積を削る」という意味で捉えてよい。実際の要素配置は横一列で構わない)。
- 実装後、`getBoundingClientRect()`で折りたたみ後の`.card-damage`の高さを実測し、目標値以下であることを確認すること。

### 36-2: 削除ボタンを右上へ、折りたたみ/展開の切り替えボタンを右下へ

- 新規に折りたたみ/展開の切り替えボタン(アイコンボタン、既存の`.damage-row-icon-button`規格・28px円形を流用)を追加し、**`position: absolute; bottom: var(--space-2); right: var(--space-2);`**(=削除ボタンが今まで使っていた位置)に配置する。アイコンは開閉が分かるもの(例: シェブロン▲/▼、または既存のUIで使っている折りたたみ表現があればそれに揃える。新規に絵を起こす場合は既存のアイコンボタンと同じ線画トーンにする)。
- `.damage-row-columns-wrap`/`.damage-row-total-result`/`.damage-add-column-slot`が持つ`max-width: calc(100% - 40px)`(ラウンド32-D3/34-D3で右下のボタン用に確保した40px)は、**削除ボタンではなく新しい折りたたみボタンのための余白として引き続き必要**(そのまま維持してよい)。

### 36-3: 「すべて折りたたむ・展開する」ボタンをヘッダーバーに追加

⚠️ **このセクション(`#opponent-notes-section`)には現在、意図的に見出し・パネル枠が無い**(ラウンド3 B-12「ダメージ計算カードは"ダメージ計算"パネルの中に入れず、見出し・説明文も置かない」という確立済みの設計方針。`DamageCalcSection.astro` 22〜26行目のコメント参照)。
- この方針と両立させるため、**装飾的な見出し文字列は追加せず、機能のためだけの薄いツールバー行**を`#damage-rows-list`の直前(`#damage-calc-engine-status`の後、36行目付近)に新設する。中身は「すべて折りたたむ」「すべて展開する」の2ボタンのみ(または1つのトグルボタンで「すべて折りたたむ/すべて展開する」を切り替える形でもよい。実装者の判断)。
- ボタンの見た目は既存のボタン規格(`.btn-ghost`等、new色は作らない)に揃える。
- 動作: 「すべて折りたたむ」で現在表示中の全行(`.card-damage`)を折りたたみ状態にし、「すべて展開する」で全行を展開状態に戻す。個々の行の折りたたみボタン(36-2)との状態整合を取ること(全展開ボタンを押した後、個別に1行だけ再度折りたたむ、といった操作が破綻しないこと)。
- 相手が0件(空状態、`.damage-empty-state`)のときはこのツールバー行自体を意味が無いので隠すか、実装者の判断で自然な形にする。

## 維持すべき点(壊さないここと)

- **壊してはいけないクラス名**(pitfalls.md): `.damage-column` / `.damage-row-total-result` / `.damage-column-result` / `.damage-row-total-label` / `.damage-column-hitcount-row` / `.damage-column-detail-button` / `.damage-row-columns-wrap` / `.damage-row-build` / `.damage-row-body` / `.damage-row-footer` / `#opponent-notes-section`(JS/E2Eテストが依存)。**折りたたみ機能はこれらの要素を「非表示にする」だけで、削除・改名はしないこと。**
- **自動保存の契約を壊さない**: 折りたたみ中に入力欄をdisabledにしても、保存済みの値(DB上の値)はそのまま保持されること。展開に戻したときに元の値が正しく表示され、その後の編集で正常に自動保存されることを確認する。
- **育成ルール(IV=31固定 / 努力値0〜32スケール / Lv50固定)は仕様。**
- `global.css`は編集しない。
- ラウンド35(35-D1: 個別結果表示の枠削除、35-R1: 攻撃側・防御側の文字サイズ)の変更を壊さないこと(同じファイルの近い箇所を触るため、`git diff`で意図しない箇所への影響が無いか確認する)。
