# UI改善ラウンド 44

[← 索引](../ui_plan.md)

## ラウンド44 の要件(2026-07-30 ユーザー指示第27弾)

ユーザーの言葉: 「UIの領域ごとのフォントの統一感、という観点でレビュー・改善して。例えば、ダメージカードの種族名とテラスタイプだけやや太字になっている。」

指示を受け、`/box`(一覧)・`/box/[id]`(左パネル・ダメージ計算カード・右パネル)の**フォント太さ(font-weight)を中心に**UI/UX/プレイヤー視点/統一感の4レビュアー(すべてsonnet)講評を実施した。専用worktree `poke-commons-ui-round-44` / ブランチ `ui/round-44`(ローカルHEAD `fa5b61e` から分岐)。

### Coordinatorが実装コードを先に実測した事実(4レビュアーへ渡した起点データ)

ダメージ計算カードの相手ビルド箱(同一font-size 13.76px前提):
- 相手名(種族名)入力欄 `.pokemon-name-row input[type="text"]`(`DamageCalcSection.astro:381`) → **font-weight: 700**
- 特性・持ち物の入力欄/select `.damage-row-build-grid select/input`(`DamageCalcSection.astro:503-514`) → 明示指定なし → 既定 **400**
- テラスタイプ選択ボタン `.tera-dropdown-button`(`DamageCalcSection.astro:551`、`<button>`要素) → **font-weight: 600**(43-D4で「書式の対象外として維持」と明記)
- `global.css` の `button` 基底ルール(ラウンド32導入)は全`<button>`要素を **font-weight: 600** にしている → テラスの600は「テラスだから強調」ではなく「`<button>`タグだから」という実装形式の副産物である疑いが強い。

### 4レビュアー講評の統合(Coordinator: 重複排除・裁定)

**UI/UX/プレイヤー視点/統一感の4レビュアーが独立に、ほぼ同一の結論に収束した**(統一感レビュアーの実測がこの一致を裏付けている):

> ダメージカードのテラスタイプ選択ボタンが太字(600)に見えるのは、テラスという情報の重要度を意図した強調ではなく、「`<button>`要素は全部600になる」というグローバルなボタン基底ルールの副作用である。同じ箱の中で特性・持ち物(400)と並べたときに、意味のない太さの差として目に入る。

統一感レビュアーの網羅監査により、**同じ構造の問題が左パネルにも存在する**ことが判明した: 左パネルの `#tera-dropdown-button` と `#item-dropdown-button` はいずれも `<button>` 要素で、font-weightを明示していないため基底の600を継承している。左パネルは34-L4で「種族名・ニックネーム・性格・特性・持ち物をすべて400にフラット化する」という方針を確定させたが、**この2つのボタン型フィールドだけがフラット化から漏れていた**(値としての一貫性はテラス同士で600・600と一致して見えるため、これまで誰も気づかなかった)。

一方、**種族名(相手名)の700は意図的な階層として維持する**(4レビュアー中3体が明言): box一覧カードの `.card-name`(700)・ダメージカードの相手名(700)はいずれも「複数を並べて見比べる文脈での主識別子」という一貫した役割を持ち、UI/UXレビュアーとも「無理に統一する必要はない」と判断している。左パネルの種族名・ニックネームが400なのは「編集画面には比較対象がなく、全項目が同格の入力欄である」という34-L4の既存方針によるもので、これも意図的な差として維持する。

### 優先度A(必ず直す)

- **A-1 ダメージカードのテラス選択ボタンのfont-weightを特性・持ち物に揃える**(指摘者: UI/UX/プレイヤー視点/統一感、全4体が一致): 【問題】`#opponent-notes-section .tera-dropdown-button`(`DamageCalcSection.astro:551`)が明示的にfont-weight:600を維持しており、同じ箱の特性・持ち物(400)より太く見える。43-D4でサイズ・高さは特性selectに統一済みなのに太さだけ取り残されている。 → 【提案】`font-weight: 600` を削除し `font-weight: 400` を明示指定する。43-D4のサイズ統一(font-size/padding/line-height/min-height)はそのまま維持。
- **A-2 左パネルのテラス選択ボタンにも同じ是正を適用する**(指摘者: 統一感レビュアー実測 + UIレビュアー): 【問題】`#edit-form .tera-dropdown-button`(`LeftPanel.astro:1057-1074`)がfont-weight未指定でbutton基底の600を暗黙継承しており、34-L4の「入力欄はすべて400」方針から漏れている。 → 【提案】`font-weight: 400` を明示指定する。
- **A-3 左パネルの持ち物選択ボタンにも同じ是正を適用する**(指摘者: 統一感レビュアー実測): 【問題】`#edit-form .item-dropdown-button`(`LeftPanel.astro:1142-1158`)も同じ理由でfont-weight未指定 → 基底600を継承。テラスと同じ「ボタン型の値選択フィールド」でありながら、隣接する種族名・特性(400)より太い。 → 【提案】`font-weight: 400` を明示指定する。

### 優先度B(直せるとよい)

- **B-1 ダメージカード技名の展開時/折りたたみ時の太さ矛盾**(指摘者: プレイヤー視点): 【問題】展開時の技名入力欄(`.damage-column input[type="text"]`、`DamageCalcSection.astro:1358-1367`)はfont-weight 400だが、折りたたみ時のサマリー(`.damage-row-collapsed-move-list`、42-D5で新設)では技名を700で表示しており、同一カードの状態違いで技名の重み付けが矛盾している。 → 【提案】実装者は該当箇所を確認のうえ、折りたたみサマリーが「省スペースでの見出し表示」という別役割であることを踏まえて据え置くか、展開時も500〜600程度に上げるかを判断すること(A-1〜A-3ほど確信度は高くないため、実装時に現物を見て判断でよい)。

### 優先度C(好みの範囲・要判断、今回は対応しない)

- box一覧カードの特性(`.card-ability-name`=600)・技チップ(`.card-move-chip`=600)が、左パネル・ダメージカードの同種フィールド(400)より太い。UIレビュアーの判断: box一覧は読み取り専用の静的チップ表示、左パネル/ダメージカードは編集可能な`<select>`/`<input>`という**表示形式(役割)の違い**があり、無理に揃える必要はない。
- 削除(×)ボタンの太さがbox一覧400・ダメージカード600(button基底継承)・global基底.delete-button定義700の3値に分かれている(指摘者: 統一感レビュアー)。今回のフォント統一感の主題(名前・特性・持ち物・テラスの値表示)とは別軸のアイコンボタン文言のため、次ラウンド以降で扱う。
- 持ち物バッジ画像の実寸がダメージカード33px・左パネル31pxで2px差(指摘者: 統一感レビュアー)。フォントではなく画像アセットの実測差のため対象外。
- 右パネルの見出し `.damage-detail-section-heading` が基底700・攻撃側/防御側コンテキストで600に文脈上書きされている(指摘者: 統一感レビュアー)。汎用見出しと副見出しという役割差の可能性があり、意図的階層差として保留。

### 確認済み・維持すべき点(次のラウンドで再提起しないこと)

- 種族名(相手名/ニックネーム)の700強調は、box一覧カード・ダメージカードとも「複数を比較する文脈での主識別子」として意図的であり、統一しない。
- 左パネルの種族名・ニックネーム・特性・持ち物(テキスト表示部分)が400でフラットなのは34-L4の確定方針であり、一部だけ再度太字化しない。
- 00-foundation.mdの数値グリッド本体値サイズ階層(左パネル16.8px/ダメージカード13.76px/box一覧11.8px相当)は既存確定仕様であり、今回のfont-weight是正の対象外(サイズは変更しない)。
- 41-D1(ダメージカードのテラス視覚表現をアイコンなし・テキストのみに簡素化)、43-D4(テラスボタンのサイズを特性selectに統一)、43-D7(圧縮展開»のfont-weight 700→600撤回)はいずれも今回の方針と矛盾せず、維持する。
