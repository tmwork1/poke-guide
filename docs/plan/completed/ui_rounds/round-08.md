## ラウンド8の指摘(2026-07-26 opusアドバイザー講評: `/box/[id]` + `/box`)

カード3枚(技列3つ/2つ/1つ)の実使用状態を1920×1080で実測して得た指摘。**A-5 はメインエージェント側でも独立に真因まで再現確認済み**(computed style を実測)。

### 総括: 残っている問題は3種類

1. **高さの内訳がまだ最適化されていない**(`scrollHeight` 1205px、3枚が1画面に入らない)。主因は「相手ビルド箱の名前行が公式絵72pxで1行まるごと占有していること」と「押せない破線ボックス48px」。**ここを直すと相手アイコンを拡大しながら同時に高さが縮む**(ユーザーの2大要望が両立する)。
2. **ライトモードのコントラストがまた同じ形で落ちている。** ラウンド3で結果チップを直したが、今度は `--color-text-muted` on `--color-surface-alt` が **4.26:1** でAA割れ。ダークは5.89:1で問題なし。**「ライトだけ落ちる」というこのプロジェクト固有の再発パターン。**
3. **幅390pxの破綻は装飾の問題ではなく、Astro scoped style の詳細度バグ**(`.card-item-badge` / `.damage-row-footer` に続く**3例目**)。

### 実測した高さの内訳(1920×1080、カード3枚)

| | 現在 | A-1〜A-3適用後(見積) |
|---|---|---|
| カード1(技列3) | 380 | **329** |
| カード2(技列2) | 319 | **302** |
| カード3(技列1) | 319 | **272** |
| カード計+gap | 1034 | **919** |
| ページ `scrollHeight` | **1205** | **約1090** |

`.damage-row-build` は300×**302pxで3枚とも固定**。`.damage-row-columns-wrap` は 316/249/**125px** と内容で伸縮する。**つまりカード高さを決めているのは常に相手ビルド箱**であり、技列が1つのカードでは右カラムに約190pxの空白が残る。ユーザーが2度指摘した「技列側の空きスペース」は、技列が多いケースでのみ解消していた。

### 優先度A(必ず直す)

- **A-1 相手ビルド箱の名前行が公式絵72pxで1行を占有している** → 再構成で **−43px/枚**、同時に相手アイコンを **72→96px** に拡大できる。
  【問題】相手名 input(29px)の右に72pxの公式絵が置かれ、特性・持ち物・テラスの3入力はその**下**から始まっている。名前行の高さは72pxで、inputとの差 **43pxが純粋な空気**。名前行72.0 + 特性/持ち物/テラス3行67.8 = **142.2px** が `.damage-row-build` 302px の47%を占める。**「相手アイコンが小さい」と「技列側の空白」は同じ1箇所が原因。**
  【提案】スプライトを名前行から出し、「名前input+3入力」の縦スタックと**横に並べる**。左スタック 29+2.4+67.8=**99.2px**、右のスプライトは99.2pxまでタダで伸ばせるので **96px箱 / 88px画像**にする(現在72/64、**+33%**)。
  - JS `renderRow` 内で `nameRow` と `selectsRow` を新設 `.damage-row-build-fields`(縦flex)にまとめ、それと `spriteBox` を新設 `.damage-row-build-main`(横flex)に入れる。`nameRow.appendChild(spriteBox)` は `buildMain.appendChild(spriteBox)` に変える。
  - `.pokemon-name-row` / `.damage-row-build` / `.damage-row-body` は**改名も削除もしない**(親が変わるだけ)。新設2クラスは保護リスト外。
  - `.damage-sprite-box` 72→96px、`img.sprite-icon` 64→88px。**JS側の `width`/`height` 属性と `spriteFallback.style.cssText` も必ず追随させること**(CSSだけ変えると食い違う)。
  - 幅の検算: 箱の内寸 300−padding19.2−border2 = 278.8px。96+gap6 を引いて入力欄は **176.8px** 残る。「わざわいのうつわ」(約97px)+padding≒106pxなので12字でも収まる。既存の `overflow:hidden / text-overflow: ellipsis / title` は維持。
  - **併せて `.damage-item-badge`**(現在 `bottom:-6px; left:-6px` でスプライト箱の左下=名前inputとの継ぎ目に浮いている)を `bottom:-4px; right:-4px` に移し、`/box` の `.card-item-badge` と同じ 22px円形+`1px solid var(--color-border)`+`var(--shadow-sm)` に揃える。テラスバッジは右上なので衝突しない。

- **A-2 「技列は最大3つまでです」の破線ボックスが48px居座り、コントラスト1.68:1で読めない** → 撤去で **−48px**。
  【問題】`.damage-add-column-button:disabled { opacity: 0.4 }` により muted `#6b7280` が surface-alt 上で実効 `#c0c3ca` = **1.68:1**。文字として機能していないのに48px+gapを消費し、**これがカード1を380pxにしている唯一の原因**(13 + max(302, 316+6+48=370) = 383)。
  【提案】上限到達時は**スロットごとCSSで隠す**(DOMは残す)。`renderColumns` の上限判定で `addSlot.dataset.max = "true"` を立て、`.damage-add-column-slot[data-max="true"] { display: none }`。※代替案(右寄せ20pxキャプションに落とす)を採る場合も **`opacity: 0.4` は必ず外すこと**。

- **A-3 「+ 技を追加」を右カラムの下端に固定+圧縮** → 空白が「末尾の穴」から「意図的な余白」に変わり **−14px/枚**。
  【問題】カード3は技列125px・相手ビルド箱302pxで**右カラム下端に約190pxの空白**。検討した3案のうち、**相手ビルド箱を技列に合わせて縮める案は173pxまで削る必要があり公式絵拡大の要望と正面衝突するため不可**。**技列を `flex: 1 1 auto` で伸ばす案は箱の中に190pxの空白ができるだけで悪化する**。
  【提案】右カラムに**下端のアンカー**を置く。`.damage-row-techniques-row` に `justify-content: space-between`(または `.damage-add-column-slot` に `margin-top: auto`)。右カラムの上端(技列)と下端(追加ボタン)が相手ビルド箱の上下端と揃い、「片方だけ短い」という読みが消える。併せて `.damage-add-column-button` の `padding: 0.5em 0.6em → 0.28em 0.6em`、`font-size` 0.78rem 相当で48→約34px。**フォントを下げるのはこのボタン1個だけで、数値・技名には一切触らない。**

- **A-4 左カラムのヘッダと数値グリッドの列がずれている。真因は `em` の基準font-sizeの食い違い。**
  【問題】`.stat-table-header` は `font-size: 0.78rem` で `grid-template-columns: 6.8em 3.2em 1fr 3.4em 3.6em`、`.stat-row` は font-size 指定なし(1rem)で**同じ `em` 指定**。`em` は自身のfont-size基準なので実寸が別物になる: 1列目 85.0px vs 108.8px(**ずれ23.8px**)、種族値列 39.9 vs 51.2、努力値入力列 42.4 vs 54.4、実数値列 44.9 vs 57.6。
  【提案】両方を **`6.8rem 3.2rem minmax(0, 1fr) 3.4rem 3.6rem`** に変える(行側の実寸は変わらない)。併せて **`#ev-remaining`(残り18)を `.stat-table-header-real` から `.stat-table-header-ev` 側へ移し**、`justify-content: space-between` で左「努力値(0〜32)」・右「残り18」に。**残ポイントが努力値入力欄の真上に来て意味も合う**。`.stat-table-header-real` の `flex-direction: column` を外して1行「実数値」だけにする(ヘッダ2行→1行で **−17px**)。

- **A-5 幅390pxの破綻3件。うち1件は Astro scoped style の詳細度バグ**(メインエージェント側で computed style を実測し再現確認済み)。
  【問題・実測値】`.app-topbar-account-desktop` の computed `display` が **`flex`**。`global.css` の `.app-topbar-account-desktop { display: none }`(詳細度 0,1,0)が、`AppLayout.astro` の scoped `.app-topbar-account { display: flex }`(scopedで `[data-astro-cid-*]` が付き **0,2,0**)に**負けている**。結果:
  - ログイン表示が上下2箇所に重複 → `scrollWidth 491` vs `clientWidth 390` の**横スクロール**(はみ出し要素も両アカウントブロックと特定済み)
  - 「この個体を削除」が **46×169px**(`white-space: normal` のまま1文字ずつ縦に折り返し)。**w900でも3行に折れており、モバイル限定の問題ではない**
  - ページタイトルが**幅2px**に潰れて消滅、トップバーだけで高さ **259px**
  【提案】
  1. `global.css` の `.app-topbar-account-desktop / -mobile` の `display` 切り替えを **`AppLayout.astro` の `<style>` ブロック内へ移設する**(同じscoped詳細度になり正しく効く)。**※`global.css` 側に `.app-topbar-account.app-topbar-account-desktop` と書いても、scopedスタイルは global.css より後ろに注入されるため同詳細度で負ける。移設が唯一の正解。**
  2. `#delete-button { white-space: nowrap }`
  3. `@media (max-width: 899px) { .app-topbar-account-email { display: none } .app-topbar-row-main { flex-wrap: wrap; row-gap: var(--space-2) } }`
  【見積】390px時のページヘッダ **約190px → 約104px**、横スクロール解消、縦書き解消、w900の3行折り返しも同時解消。

- **A-6 コントラスト: ライトで4.26:1、ダークで枠線1.18:1。**
  【問題・ライト】`--color-text-muted #6b7280` は `--color-surface #ffffff` で 4.49:1、**`--color-surface-alt #f8f9fc`(=`.card` の背景)で 4.26:1 → AA割れ**。該当: `.card-move-chip`(技名, 10.2px, 4.26) / `.card-stat-col-label`(H〜S, 9.3px, 4.26) / `.damage-add-column-button`(4.26) / 同 `:disabled`(**1.68**) / `.damage-ev-row-label`・`.damage-ev-col-label`(4.49) / `.damage-column-order-label`(4.49)。いずれも小さい文字なので大字例外は使えない。**ダークは同じmutedがsurface-alt上で5.89:1で問題なし** = ラウンド3の結果チップと完全に同じパターン。
  【問題・ダーク】`--color-border #2d313d` vs `.card` 背景 `--color-surface-alt #22252f` = **1.18:1**。相手ビルド箱・技列箱の輪郭がほぼ見えず、**カード全体が1枚の黒い塊に見えて「2つの箱が並んでいる」という構造が伝わらない**(ライトは白背景+影で分離が読めるが、ダークは影が効かない)。
  【提案】新色は作らず既存中立色の明度違いで対応。
  - ライト: `--color-text-muted: #6b7280 → #5b6472`(白上 5.98:1 / surface-alt上 5.68:1)。**ダーク側は触らない**(既に5.89:1)。
  - ダーク: ページscopedで内箱の枠線だけ `#5a6377`(カード背景に対し **2.73:1**、現状1.18:1)。**`--color-border` 自体は変えないこと**(全ページの罫線が太く見える)。

- **A-7 能力値ラベルの ▲▼ が 14×13px しかない。**
  【問題】`.stat-nature-btn { width: 1.3em; height: 1.2em; font-size: 0.68em }` の `em` は**自身のfont-size(0.68em=10.88px)基準**なので実寸 **14.1×13.1px**。WCAG 2.5.8(24×24)を大きく割り、このプロジェクト自身の「タップ対象28px」基準にも反する。さらに枠線 `--color-border #e3e6ee` は白背景に対し **1.20:1** で事実上見えていない。**ラウンド5の「押せることを示す見た目が無い」という指摘は、ボタン化されても寸法と枠線の問題として残っている。**
  【提案】状態表示(▲/▼独立・`aria-pressed`・塗り)は**そのまま維持**し、寸法と枠だけ直す。`width: 22px; height: 20px; font-size: 11px`(px指定にして `em` の入れ子事故を断つ)。行高は入力欄29pxが binding なので**高さコストは0**。`background: var(--color-surface-alt)` を追加、`.stat-row:hover .stat-nature-btn { border-color: var(--color-primary) }` を追加。460px以下の縮小指定もpxに合わせる(18×17px)。**押下時の塗り(`--stat-up #c9432c` 4.86:1 / `--stat-down #1d6fd1` 4.95:1)は両方AA通過済み。触らないこと。**

- **A-8 `/box` の218px正方形カードで、技0件と4件のカードの内部位置が揃わない。**
  【問題】36体状態で、同じ行の中で名前行のyが **281px(技4)/ 289px(技2)/ 300px(技0)** と最大19pxばらつく。原因は `.card-pokemon { justify-content: center }` + 技0件時に `.card-moves-grid` のDOM自体を作らないこと。**36枚を縦に走査するときに実数値の行が波打ち、H/A/B/C/D/Sの列も行ごとに上下する。**「目当ての1体を探す」という画面の目的に対して最も効く欠陥。
  【提案】`pitfalls.md` の「高さを揃えたいなら `min-height` で箱を確保し、中身のDOMは出さない」に沿う。`justify-content: center` を外して `display: grid; grid-template-rows: 1fr auto; align-items: center; justify-items: center`(公式絵=可変行、`.card-body`=固定行)。`.card-moves-grid` に `min-height: calc(2 * 1.2 * 0.64em + 0.05rem)`(≈25px)。**技0件でも `movesGrid` を必ず append する(子要素は作らない)**。空でも `border-top` の区切り線が出ることで「技未登録」が逆に読み取れるようになる。**カード218px正方形・1画面27枚は不変。**

### 優先度B

- **B-1 右サイドバーの面積配分**: 1920pxの内訳は サイドバー256 + 左440 + 中央779 + 右360 = 1835px。中央779pxは相手ビルド箱300+技列448で埋まっており、**サイドバーを削って中央に回す価値は薄い**(技列448pxは技名が読み切れる十分な幅)。問題は未選択時に **360×950px ≒ 34万px²** が3行の説明文だけになること(左カラムも440×315px空いており、合計47万px²)。→ 幅は変えず、**ページ読み込み時に先頭カードの1発目の技列を自動選択する**。**選択が自動保存を引かないことを必ず実測で確認すること**(引くならこの項目は見送る)。空状態の文言は1行に短縮。
- **B-2 サイドバーの天候アイコン8個が2行+ラベル2行割れ**: `.damage-detail-icon-btn { width: 4.4em; font-size: 0.68rem }` = **47.9px**。「すなあらし」は5字×10.9px≒54pxで確実に折り返す。8×47.9+7×6.4 = 428px > 利用幅約320px で 6+2 の不格好な2行。→ `.damage-detail-icon-group` を `display: grid; grid-template-columns: repeat(4, minmax(0, 1fr))` に(1枠約75px)。`width: 4.4em` は削除。8個が **4×2** にきれいに並ぶ。**高さは変わらないか微減。**
- **B-3 結論の拾い読みと数値の重複**: 結論が2つのx座標(相手ビルド箱の左下=累計 / 技列の右)に散り、yも不定。**縦に走査して結論だけを拾えない。** さらにカード2では1発目の `確1 351〜414 (270〜319%)` と累計チップの `確1 累計351〜414 (270〜319%)` が**完全に同じ数値**(技列が1つのとき累計は定義上1発目と一致する)。→ `.damage-row-total-result` をカード下端の全幅バーにすると3枚の結論が縦に読める。**ただしこれは `docs/ui_proposal/ダメージ計算カード.png` の「加算後のダメ・致死率は左ボックス内・区切り線の下」という構造からの逸脱。ユーザー判断が要るのでラウンド8では実施しない。**
- **B-4 相手ビルド箱がクリック非反応であることが画面から分からない**(ラウンド7の積み残し)。→ `.damage-column { cursor: pointer }` / `.damage-row-build { cursor: default }` を明示し、`.damage-column:hover { border-color: var(--color-primary) }` を足す。
- **B-5 ダークで `/box` の持ち物バッジのリングが消える**: `.card-item-badge` の border `#2d313d` がカード背景 `#22252f` 上で **1.18:1**。アイテム画像だけが空中に浮いて見える。A-6のダーク枠線と同じ `#5a6377` を当てる。
- **B-6 サイドバーの説明文が長すぎる**: 技選択時のsubtitleが4行、壁のヒントが3行で、**設定項目より説明のほうが縦に長い**。それぞれ1行に短縮(約60px回収)。

### 優先度C(要判断・ラウンド8では実施しない)

- C-1 左カラム下部の空白(440×315px)。ワイヤーフレーム `個体編集_全体レイアウト.png` では帯が全高なので**空くこと自体は設計どおり**。
- C-2 サイドバーが1600px未満でオーバーレイに落ちる件。1440で3カラムにすると中央384pxで技列が破綻するので**閾値1600pxは正しい。変えない。**
- C-3 縦走査時の第1情報が全カード共通の「⚔ この個体が攻撃」(ラウンド3 C-1の再掲)。据え置き。
- C-4 `.damage-column` の結果チップ2段を1行化(技列3つで54px)。**ラウンド3 C-4「結果チップの主役化」を弱める方向なので最終手段。**
- C-5 `/box` にテラスタイプが無い(ラウンド4からの積み残し)。入れるなら公式絵の左下(持ち物は右下)。

### 維持すべき点(壊さないこと)

**技列の縦積み+技ごとの独立設定**(技名が448px幅で読み切れ、条件チップで波及しないモデルが見えている。旧アプリ `battle_assistant.jpg` の密度にほぼ並んだ) / **`1発目で撃破済` + `opacity: 0.55` の減光**(数値を変えずに「もう関係ない」を伝える) / **結果チップの主役化**(`確N` 太字先頭、ダークは4.6〜5.3:1でAA準拠。**直すのは常にライト側**) / **`.card-damage.is-selected` + `.damage-column.is-selected` の2階層の選択マーク** / **`min-height: 2.35rem` の打ち消し**(戻すと1行13px×全入力で瞬時に414px級に戻る。**触らないこと**) / `tnum` の桁揃え / 努力値・実数値の「行ラベル+7列グリッド」 / `/box` と `/box/[id]` で実数値の上昇=赤▲・下降=青▼が一致していること / **タイプアイコンの事前生成PNG**(CSS切り出しには戻さない) / `/box` の218px正方形・1画面27枚 / `.card-item-badge[hidden]` の詳細度対策。

## ラウンド8の実施結果(2026-07-26)

3体のsonnetサブエージェントにファイル単位で担当を割って並列実装した(`box/[id].astro` / `box/index.astro` / `global.css`+`AppLayout.astro`)。**下記の実測値はすべてメインエージェントが自分で撮り直して測ったもの**であり、エージェントの自己申告値ではない。

### 実施済み

| 対象 | 結果(メインエージェント実測) |
|---|---|
| `/box/[id]` A-1 | 相手ビルド箱を `.damage-row-build-main`(横flex)/`.damage-row-build-fields`(縦flex)に再構成。**相手の公式絵 64→88px(+37%)** と同時に**箱の基準高さ 302→260px**。「アイコンを大きくする」と「高さを削る」がトレードオフではなく両立した |

### 実装中に見つかったバグ(UI改修とは別の実バグ)

- **`.app-topbar-account-desktop` の詳細度負け(A-5、これが390px破綻の実体)**。`global.css` の `.app-topbar-account-desktop { display: none }`(0,1,0)が、`AppLayout.astro` の scoped `.app-topbar-account { display: flex }`(Astroが `[data-astro-cid-*]` を付けて実質 0,2,0)に負けていた。**`global.css` 側で詳細度を上げても直らない**(scopedスタイルは global.css より後ろに注入されるため同詳細度で後勝ちする)。**scoped側へ移設するのが唯一の解**。
- **幅900px境界での横スクロール**(実装エージェントが検証中に発見)。`.app-topbar-account { flex-shrink: 0 }` によりアカウント情報が縮まず、ページ固有アクションのある画面で `scrollWidth 928 / clientWidth 900` になっていた。`flex-shrink: 0` を外し `min-width: 0` に。
- **`.card-moves-grid` の `min-height` 計算漏れ**(実装エージェントが実測で発見)。プロジェクトが `box-sizing: border-box` なので、コンテンツ2行分だけの `min-height` では `padding-top: 0.2rem` + `border-top: 1px` のぶんコンテンツ高さが不足し、技4件のカードだけ4px伸びて再びずれていた。padding と border を加算した式に修正。

### メインエージェントが検証で見つけて自分で直した回帰(2件、いずれも今ラウンドの実装が作り込んだもの)

1. **持ち物なしの相手で「空の白丸バッジ」が出る。** A-1でバッジに白背景+枠+影を与えたため、これまで不可視だった空バッジが露出した。`applyItemImage()` は **img だけを隠しバッジ(親)を隠していなかった**。→ バッジごと `hidden` にし、`.damage-item-badge[hidden] { display: none }` を併記、生成時の既定を `hidden = true` に。**`pitfalls.md` の「`[hidden]` は詳細度で負ける」の4例目**(`.damage-row-footer` / `.card-item-badge` ×2 に続く)。
2. **1600px未満の全幅で、読み込み直後に詳細設定がモーダルとして開き画面全体を覆う。** B-1(先頭技列の自動選択)を幅の条件なしで実行していたため。サイドバーは1600px以上でのみ常設で、それ未満はバックドロップ付きオーバーレイになる。**1599 / 1440 / 1280 / 900 / 390px すべてで再現**し、閉じるまで本体を操作できない状態だった。→ 自動選択を `window.matchMedia("(min-width: 1600px)")` でガード。修正後、1600px未満では `is-open` が付かず選択0件、技列クリックでは従来どおり開くことを実測確認。

### 積み残し(次に着手する項目)

1. **技列が1つのカードで右カラム下端に約120pxの空白が残る**(A-3で「末尾の穴」から「下端が揃った余白」に変わったが、消えてはいない)。相手ビルド箱を技列に合わせて縮めると公式絵88pxと衝突するため、構成そのものを変えない限り解けない。
2. **`scrollHeight` 1101px**。カード3枚は1080px内に収まるが「+ ダメージ計算を追加」行が21px溢れる。また**カード高さはデータ依存**(「1発目で撃破済」の注記が付くと技列が+17px)なので、火力の高い相手を登録すると3枚合計がさらに伸びる。
3. **幅390pxで `scrollWidth` が1px多い**(391 vs 390)。原因要素は特定できておらず、境界ボックスが `clientWidth` を超える要素は検出されない。ヘアラインなので実害は小さい。
4. **幅390pxのトップバーが164px**(見積の104pxには届いていない)。削除ボタンが nowrap になった結果、幅不足でアクションが2段目に折り返るため。さらに詰めるなら削除ボタンのアイコン化などの判断が要る。
5. **ページ読み込み直後に `PUT` が3件飛ぶ**(実装エージェントがB-1の検証中に観測)。Pyodide初期化完了時の全行再計算が常に保存を伴う既存挙動で、今ラウンドの変更とは無関係。**UI改修とは別に、実バグとして扱うか要判断。**
6. **B-3(結果チップをカード下端の全幅バーに統合)は未実施。** `docs/ui_proposal/ダメージ計算カード.png` の構造からの逸脱になるためユーザー判断待ち。技列が1つのカードでは累計チップと1発目の結果チップが**完全に同じ数値**を表示している重複も未解消。
7. ラウンド5からの積み残し: 相手ビルド箱の3列化(`@container` 480px固定)が技列の多いケースで未検証 / サイドバーの天候アイコンが手描きSVG / 持ち物欄の長い値の見切れ / `:placeholder-shown` の破線表現。
