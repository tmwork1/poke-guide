## Step2.5: 4レビュアーの講評統合(Coordinator)

4体全員(UI/UX/プレイヤー視点/統一感)が独立に、上記1の白文字問題を最優先(A)として確認。UX・UIレビュアーは追加で**圧縮表示だけでなく展開表示の`.damage-ev-col-label`(`:906-916`)も同じ`color:#fff`固定であること**を実測で発見・裏付けした(Coordinatorの事前調査では圧縮側3箇所のみ把握していたが、展開側1箇所を合わせ計4クラス5ルールが対象と判明)。UIレビュアーはさらに、round-48で「次回まとめて検討」と積み残されていた`--color-primary`のライト低コントラスト(2.50:1)が、状態異常セレクトだけでなくランク入力欄の`.is-nonzero`強調にも同型で存在することを指摘し、既存の`--color-primary-strong`トークン(ラウンド13/17でリンク・ラジオに適用済み、ライト実測4.62:1)への置き換えという具体的かつ低リスクな解決策を示した。

性格補正の記号(▲▼ vs +/-)については3レビュアー(UX/プレイヤー視点/統一感)が「媒体の違い(装飾可能なHTML vs 装飾不可のOSネイティブtitle)に基づく妥当な使い分け」と判断し、統一の緊急性は低いという結論で一致した。Coordinatorもこれを採用し、今回は変更しない(優先度Cとして記録のみ)。

統一感レビュアーが新たに発見した`.item-image-badge`(31px)/`.damage-item-badge`(33px)のドリフト(両ファイルのコメントは「同じ最終サイズ」と明記しているにも関わらず値が2px乖離)、`.pin-toggle`の12px下限割れ(11.52px、根拠コメントなし)、`LeftPanel.astro`の`.stat-table-header`/`.stat-row`の列paddingの不一致(1.6pxの整列ズレ)は、いずれも実測根拠が明確で修正リスクが低いためBとして採用する。

右パネルの天候/フィールドラベル(0.75rem)と攻撃側/防御側ラベル(0.78rem)の差は、**round-35 A-1で「この1点で意図的に差が生まれる」と明記済みの確定仕様**であるため、UIレビュアーのB提案(12px下限からの引き上げ)は不採用とし、据え置く(再提起しない)。

### 優先度A(必ず直す)

- **A-1 白文字(`color:#fff`固定)によるライトテーマでの視認不能を解消する**: 【問題】以下4クラス・5CSSルールが`color:#fff`固定で、ライトテーマの背景(`--color-surface-alt`)に対しコントラスト約1.05:1(実質不可視)。ダークでは同じ色で約15.3:1と問題ないため、これまでダークだけで検証され見逃されてきたと考えられる。
  - `DamageCalcSection.astro:916` `.damage-ev-col-label`(展開表示、相手ビルドのH/A/B/C/D/S列見出し・無補正時)
  - `DamageCalcSection.astro:2668-2671` `.damage-row-collapsed-ability`(圧縮表示、特性名)
  - `DamageCalcSection.astro:2750-2752` `.damage-row-collapsed-tera-name`(圧縮表示、テラスタイプ名)
  - `DamageCalcSection.astro:2824-2831` `.damage-row-collapsed-stat-key`(圧縮表示、H/A/B/C/D/S列見出し・無補正時)
  【提案】4箇所とも `color: #fff` → `color: var(--color-text-muted)` に戻す。このトークンは同一画面内(努力値/実数値の行ラベル`:897`、特性・持ち物のmuted表示等)で既に実測・使用実績があり(ライト`#5b6472`≒5.98:1、ダーク`#9aa1b0`)、新規のコントラスト検証は不要。**round-47で上げたfont-weight(600)はそのまま維持してよい**(色だけを戻す。太さの変更は今回のスコープ外)。性格補正時の色上書き(`[data-mod="up"/"down"]`、`--stat-up`/`--stat-down`)はこの基底ルールより後方にあるため、この変更後も引き続き優先され壊れない。

- **A-2 `--color-primary`を強調色に使っている2箇所のライト低コントラストを是正する**: 【問題】以下2箇所が非既定値の強調に`--color-primary`(#27acd9)を文字色・枠色として使っており、ライトで実測コントラスト約2.50:1(WCAG AA 4.5:1未達)。round-48.mdに「今回新規に持ち込んだ劣化ではない、次回まとめて検討する」と記録されていた積み残し。
  - `DamageCalcSection.astro` `.damage-detail-rank-field input.is-nonzero`(ランク入力欄、非ゼロ時の強調)
  - `DamageCalcSection.astro` `.damage-detail-ailment-select:not(.is-ailment-unselected)`(状態異常セレクト、選択中の強調、ラウンド48 A-6bで新設)
  【提案】このプロジェクトには既に同型の問題(チェックボックス/ラジオの`--color-primary`がライトで約2.63:1)を解決した実績があり(`global.css:593-621`、ラウンド13/17)、そこで確立した「背景は据え置き、文字・枠だけ`--color-primary-strong`(#1a7ea1)に差し替える」パターンをそのまま適用する。
  ```css
  #damage-detail-panel-body .damage-detail-rank-field input.is-nonzero {
    color: var(--color-primary-strong);
    border-color: var(--color-primary-strong);
  }
  #damage-detail-panel-body .damage-detail-ailment-select:not(.is-ailment-unselected) {
    color: var(--color-primary-strong);
    border-color: var(--color-primary-strong);
  }
  ```
  `--color-primary-strong`はダークでは`var(--color-primary)`にエイリアスされる設計のため、**ダーク側の見た目は変化しない**(round-13/17と同じ理屈)。font-weightは変更しない。

### 優先度B(直せるとよい)

- **B-1 `/box`一覧カードの★/☆ピル文字が12px下限を割っている**: 【問題】`box/index.astro:648`付近 `.pin-toggle`が`font-size: 0.72rem`(11.52px)で、このプロジェクトの明示的な12px下限規約(20-G3以降、複数箇所で維持)を割っている。同じファイル内の`.card-move-chip`(10px、ラウンド42-B2で実測根拠付きの明示的例外)とは異なり、この値には根拠コメントが無い。
  【提案】`font-size: 0.75rem`(12px)に引き上げる。★/☆ピル自体の寸法(36×36pxの三角トリム領域)には余裕があるため、レイアウトへの影響は軽微なはず。実装後、実機で三角領域からのはみ出しが無いことを確認する。

- **B-2 持ち物バッジのサイズが左パネルとダメージカードで2pxドリフトしている**: 【問題】`LeftPanel.astro:1694-1701` `.item-image-badge`は31px(ラウンド39 39-L1で再縮小)だが、`DamageCalcSection.astro:836-845` `.damage-item-badge`は33pxのまま(ラウンド34 34-D1のコメントは「左パネルの`.item-image-badge`と同じ最終サイズ」と明記しているが、その後の39-L1の変更に追随していない)。
  【提案】ドキュメント上の統一意図(「同じ最終サイズ」)を尊重し、`.damage-item-badge`を33px→31pxに揃える。実装後、テラスバッジ等の隣接要素との重なり位置がずれないか実機確認する。

- **B-3 左パネルの能力値テーブルで見出し行とデータ行の列が1.6pxずれている**: 【問題】`LeftPanel.astro:563-576` `.stat-table-header`が`padding: 0 0.1rem 0.35rem`(左右0.1rem=1.6px)を持つ一方、`:624-631` `.stat-row`にはpaddingが無いため、同じ`grid-template-columns`を共有していても列境界が1.6pxずれる(全6行×2列、種族値・実数値列で確認)。色に依存しない構造的ズレのためライト・ダーク共通。
  【提案】`.stat-table-header`の左右paddingを外し(`padding: 0 0 0.35rem`)、`.stat-row`側に合わせる。下パディング(見出しとデータ行の間隔)は変更しない。実装後、見出しとデータの列中心が0pxで一致することを実測確認する。

### 優先度C(好みの範囲・据え置き。今回は変更しない)

- 性格補正の記号表記(`/box`カードホバーtitleの`+`/`-` vs それ以外の`▲`/`▼`): 3レビュアー(UX/プレイヤー視点/統一感)が「プレーンテキストのOSネイティブtitleとリッチな画面表示という媒体の違いに基づく妥当な使い分け」と判断。統一の緊急性は低いためユーザー判断待ちとして記録するに留め、実装はしない。
- テラスタイプ小アイコンのサイズが4種(`/box`一覧24px・左パネル20px・展開ダメージカード20px[非表示]・圧縮ダメージカード16px)に分かれている: 各ラウンドの個別ユーザー指示による意図的階層差の可能性が高く、今回は据え置く。
- 右パネルの天候/フィールドラベル(0.75rem)と攻撃側/防御側ラベル(0.78rem)の差: **round-35 A-1で意図的差と明記済みの確定仕様のため、今回は変更しない**(UIレビュアーのB提案は不採用)。
- 状態異常selectの空値ラベル「なし」(テラス/持ち物の「テラスタルなし」「持ち物なし」という複合語パターンと形が異なる件): ネイティブselectの選択肢文言とボタン型UIのプレースホルダーという部品種別の違いによるものと考えられ、断定的な逸脱とはしない。

### 維持すべき点(壊さないこと)

- 圧縮カードのラベル行/実数値行の縦間隔(`row-gap: 0` + `line-height: 1.15`、round-47 A-6対応)は適正。A-1の色変更時にline-height/row-gapは触らない。
- 性格補正時の色分け(`[data-mod="up"/"down"]`、`--stat-up`/`--stat-down`)、攻撃/防御バッジの色分け、確定数3色化(確1〜確4)は展開・圧縮とも一貫しており、色だけに依存しない設計(▲▼併記)になっている。維持する。
- `.card-move-chip`の10px(12px下限の明示的例外、ラウンド42-B2)は再提起しない。
- チャンピオンズルール由来の数値表示は仕様。
