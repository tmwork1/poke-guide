## 全体

### 23-G1 アイテム画像の丸枠を廃止し、画像を直接表示する
> 「アイテム画像の丸枠を廃止し直接廃止する」(文意: **直接表示する**)

**現状(調査で確定)**: 白丸の枠(`border-radius: 50%` + `background` + `border: 1px solid` + `box-shadow` + `padding: 2px`)を持つバッジが**3箇所**。いずれも `[hidden]` の個別上書き付き。

| クラス | 場所 | 現在のサイズ |
|---|---|---|
| `.card-item-badge` | `box/index.astro`(基本ルール 428-440、`[hidden]` 471-474) | 42px |
| `.item-image-badge` | `box/[id].astro:945-961`(左パネル) | 56px |
| `.damage-item-badge` | `box/[id].astro:1436-1459`(`#opponent-notes-section`) | 55px |

**提案**: 3箇所とも `border-radius` / `background` / `border` / `box-shadow` / `padding` を撤去し、**画像を直接置く**。
- **⚠️ 枠を消しても「画像が無いときに `<img>` 自体を隠す」ロジック(`applyItemImage()` / `hideBadge()`)は引き続き必要。** 枠が無くなれば「空の白丸が残る」問題は構造的に起きなくなるが、**alt テキストや壊れ画像アイコンが出ないこと**を確認すること。
- **⚠️ 背景に直接置くとコントラストが変わる。** ドット絵の輪郭が背景に溶けないか、**ライト・ダーク両方で拡大クロップして目視すること。**

### 23-G2 テラスタル画像の使用を全廃し、通常のタイプ画像(丸アイコン)に統一

**提案**: `applyTeraImage()` を `typeIconUrl` に切り替える。
- 切り替えると **`teraTypeIconUrl()` の呼び出し元がゼロ**になる。関数・`public/type-icons/tera/` の19画像・`tests/sprite-urls.test.ts` の該当テストを**削除するかは判断**して報告すること。**削除するならテストも同時に消す**(残すと落ちる)。**残すなら「なぜ未使用のまま残すか」をコメントに書く。**

### 23-G3 メガシンカポケモンを選択したらアイテムを対応するメガストーンに自動設定する
> 「メガシンカポケモンを選択したらアイテムも対応するメガストーンに自動設定する」

**これは機能追加。調査で実装可能と判明した。**

**データの所在(調査で確定)**:
- `vendor/jpoke/src/jpoke/data/megaevol.py` の **`MEGA_STONES: dict[ItemName, tuple[進化前種族名, メガ後種族名]]`**。`_build_mega_stones()` が `ps-champ-ja/pokedex.json` の `requiredItem` / `forme` / `num` から構築する。`item.py` がこれを import して `ITEMS` にメガストーンを登録しており、**実運用でも一次情報源として使われている**。
- **実データで検証済み(83件)**。例: `"リザードナイトX" -> ("リザードン", "メガリザードンX")`。
- **`public/master-data/` には未出力。** `scripts/build-master-data/extract_autocomplete.py` は `megaevol` を import していない。

**🔴 命名規則で導出してはいけない(実測で確定)**:
「メガXXX → XXXナイト」という規則を83件に適用したところ **30件(36%)が不一致**。
- 長音の省略: `メガゲンガー` → **`ゲンガナイト`**(規則なら `ゲンガーナイト`)、`メガスターミー` → **`スターミナイト`**
- サフィックスの位置: `メガリザードンX` → **`リザードナイトX`**(規則なら `リザードンXナイト`)、`メガアブソルZ` → `アブソルナイトZ`

**🔴 「メガ」プレフィックスでの判定も危険**: `メガニウム`(Meganium)・`メガヤンマ`(Yanmega)は名前が「メガ」で始まるが**メガシンカではない**。判定は `MEGA_STONES` / `MEGA_POKEMONS` に含まれるかで行う。

**スコープ外(理由を明記して再提起を止める)**:
- **`メガレックウザ`**: `requiredItem=""` で**メガストーンを必要としない**(技「ガリョウテンセイ」が条件)。自動設定の対象外。
- **`メガニャオニクス(オス)/(メス)`**: 両方とも `ニャオニクスナイト`。`megaevol.py` の**逆引き**構築では曖昧になるため `MEGA_STONES` から漏れるが、**今回必要なのは前向き(種族→アイテム)なので曖昧性は無い。** 対応表を前向きに作れば両方カバーできる。
- **原始回帰(`ゲンシカイオーガ` / `ゲンシグラードン`)**: `forme="Primal"` で `"Mega"` を含まないため `MEGA_STONES` に無い。**ユーザーの指示は「メガシンカポケモン」なので今回は対象外とする。** あいいろのたま/べにいろのたまは「ストーン」でもない。**必要なら次ラウンドで追加する。**

**実装方針**:
1. `scripts/build-master-data/extract_autocomplete.py` に `from jpoke.data.megaevol import MEGA_STONES` を追加し、**前向きの対応表**(`メガ後種族名 → メガストーン名`)を `public/master-data/autocomplete/mega-stones.json` として出力する。**ニャオニクスのオス/メスも前向きなら入るので、`MEGA_STONES` の逆引きではなく `pokedex.json` の `forme`+`requiredItem` から直接作る方が漏れない。** どちらで作ったか報告すること。
2. `src/lib/pokemon-master-data.ts` に `loadMegaStoneMap()` を追加(既存の `loadAbilitiesMap` / `loadMoveTypeMap` と同じ流儀)。
3. `box/[id].astro` の**種族が確定したとき**に、対応表にあれば持ち物を自動設定する。
   - **⚠️ ユーザーが既に別の持ち物を入れている場合に黙って上書きしないこと。** 「空のときだけ自動設定する」のが安全。**判断して報告すること。**
   - **⚠️ 左パネルと相手ビルド箱の両方に効かせるか**を判断すること(相手ビルドにも種族と持ち物がある)。
   - **⚠️ Pyodide経由で `megaevol` を都度importしない。** 選択時に即反映させたいUIには重すぎる(調査エージェントの指摘)。**ビルド時生成した静的JSONを使う。**

### 23-L2 性格を特性の下に「入力不可の入力ボックス」として配置
> 「性格は、特性の下に入力ボックスを配置する。ただし入力不可にしておき自動決定の仕組みを続投。」

**⚠️ ラウンド21の 21-L4 を変更する。** 21-L4 では「技欄の上に読み取り専用テキスト」とし、**「`<input readonly>` や `<select disabled>` にしない。操作できる部品に見えると『なぜ押せないのか』という疑問を生む」**と明記していた。**ユーザーは逆を指示しているので、ユーザー指示が勝つ。**

**現状**: `<p class="nature-readout">`(2595-2598行目、技グリッドの直前)。更新は `refreshNatureButtons()` 内(3677-3678行目)。

**提案**: **特性の直下**に移し、`<input readonly>` にする。
- **`readonly` にする**(`disabled` ではない)。`disabled` はフォーム送信から外れ、色も薄くなりすぎる。`readonly` なら見た目は他の入力欄と揃い、値も読める。
- **なぜ編集できないかが伝わるようにする**(`title` か、能力値の▲▼から決まる旨の短い注記)。21-L4 の懸念はこれで緩和する。
- **自動決定の仕組み(`currentLeftNature()` / `refreshNatureButtons()`)は一切変えない。**

### 23-L3 テラスタイプを文字セレクトボックスに戻し、技と同様に文字の左にタイプアイコンを表示
> 「テラスタイプは文字セレクトボックスに戻し、技と同様に文字の左側にタイプアイコンを表示」

**🔴 ラウンド21の 21-L6 を撤回する。** 21-L6 で「テラスなしを未選択(placeholder)で代用し、画像選択ボックス化」を実装したばかりだが、**ユーザーが元の `<select>` に戻すよう指示している。**

**現状(調査で確定)**: `buildTeraSelectGroup()`(3536-3565行目)が `.tera-select-btn` のトグル群を生成。**元の `<select id="tera">` は `hidden` 属性付きでDOMに残存**(2580行目)しており、**保存経路・値の実体はそのまま `#tera` の value を使っている。**

**提案**: **`#tera` の `hidden` を外して表に戻し、トグル群(`buildTeraSelectGroup` / `syncTeraSelectGroup` / `.tera-select-btn`)を削除する。**
- **`<select>` は中に画像を入れられない。** 「文字の左にタイプアイコン」は、**技入力と同じ手法**(`updateMoveTypeIcon()` が `.move-type-icon` に `<img>` を差し込み、入力欄の左に絶対配置 + `padding-left`)を踏襲する。**技側の実装をそのまま参考にすること。**
- **「テラスなし」の選択肢を戻す**(21-L6 で placeholder 代用にしたが、`<select>` は placeholder を持てないため)。
- **⚠️ 技側で踏んだ罠**: `padding-left` が既存の `padding` ショートハンド(クラス数が多く詳細度が高い)に負け、**アイコンが文字の先頭に重なった**。computed style を実測すること。

### 23-L4 技の選択ボックスの枠色をタイプごとに変えない
> 「技の選択ボックスの枠色をタイプごとに変えず、他のUIとそろえる。」

**現状**: `updateMoveTypeColor()`(3298-3309行目)が `input.style.borderColor = color` を設定(21-L8 で背景色は撤去済み、枠線だけ残っていた)。

**提案**: **枠色の設定を撤去し、他の入力欄と同じ枠色にする。** タイプは**左のアイコン(`updateMoveTypeIcon`)で伝わる**のでこれで足りる。
- **`updateMoveTypeColor()` が他に何もしていないなら関数ごと削除する。** `TYPE_COLORS`(`src/lib/type-colors.ts`)の参照が `box/[id].astro` から消える場合、**`/box` の技チップがまだ使っているので `type-colors.ts` 自体は消さないこと。**

### 23-L5 ステータス関連のラベルと数値をすべて中央揃え
> 「ステータス関連のラベルと数値をすべて中央揃えにする。」

**現状(調査で確定)**: `.stat-table` の grid は `5rem(ラベル) 2.6rem(種族値) minmax(0,1fr)(スライダー) 3.2rem(努力値数値) 3.4rem(実数値)`。
- 行ラベル(`.stat-row-label`)・種族値(`.stat-row-base`、564行目): **text-align 指定なし = 左寄せ**
- 実数値のみ `.stat-row-real { text-align: right }`(565行目)、ヘッダも `.stat-table-header > span:last-child { text-align: right }`(466行目)
- 努力値ヘッダは `.stat-table-header-ev` が `justify-content: space-between`(左「努力値」/右「残りN」)

**提案**: **ラベル行・種族値・努力値数値・実数値を中央揃えに統一**する。
- **⚠️ 数値は `tabular-nums`(`.tnum`)を維持すること。** 桁が揃わないのが「粗く見える」主因。中央揃えにすると桁ズレが目立ちやすくなるので**特に重要**。
- **「努力値」と「残りN」の行**をどうするかは判断が要る。ここだけ `space-between` なので、中央揃えにすると意味が変わる。**実際に見て判断し、理由を報告すること。**

### ⚠️ Coordinatorが検証中に発生させ、自分で復元したデータ事故

**メガストーン自動設定機能を検証する際、既存フィクスチャ「ディンルー」(技0件個体)の種族名選択欄を直接操作してテストしたところ、自動保存で `species_name` が `メガリザードンX` に書き換わってしまった。** `pitfalls.md` の「自動保存があるので、検証クリックがデータを壊す」を把握していながら、**最初の検証で使い捨て個体ではなく既存フィクスチャを使ってしまった**のが原因。

直後に `GET` で発覚し、`PUT /api/owned-pokemon/:id` で `species_name` 以外の全フィールド(`level: 50` / `nature: "なまいき"` / `item_name: "たべのこし"` / `evs: [32,0,16,0,16,0]` など)を維持したまま `species_name: "ディンルー"` のみ復元、`GET` で一致を再確認した。**2回目以降のテストは使い捨て個体(`POST` → 検証 → `DELETE`)に切り替えて事故を防いだ。**

**教訓(pitfalls.mdに追記推奨)**: 「変更したら戻す」より確実なのは**最初から使い捨て個体を作ってテストすること**。既存フィクスチャの入力欄を直接操作するテストは、たとえ「元に戻すつもり」でも自動保存のタイミングで一瞬でも不正な値がDBに残るリスクがある。
