### 43-B1: アイテム名テキストを削除し、特性を中央配置(box一覧)

- 現状: `.card-item-row`(`box/index.astro`)は特性名(`.card-ability-name`)とアイテム名(`.card-item-name`)を左右半分ずつ(`flex: 1 1 0`)に分けて、それぞれの半分の中で中央揃え(35-B2)している。**アイテムのアイコン自体は別の場所(`.card-badge-row`のitemBadge)に既に表示されている**ため、この行のアイテム名テキストは補助的な二重表示にあたる。
- 要件: **アイテム名テキストを削除し、特性名を(行全体の)中央に配置する。**
- 対応: `.card-item-name`要素の生成・appendを削除する(JS側、`renderCard()`内)。`.card-item-row`のレイアウトを、特性名1つだけが行全体の中央に来るよう変更する(`justify-content: center`、または特性名要素の`flex: 1 1 0` を外して`width: 100%; text-align: center`にする等)。

### 43-H1: 「すべて折りたたむ・すべて展開」ボタンに>>記号を追加(左端)

- 現状: `#damage-collapse-toggle-button`(ヘッダー内、41-H1で移設済み)はテキストのみ「すべて折りたたむ」⇄「すべて展開する」を交互表示する。
- 要件: **ボタンの左端に>>記号(既存の折りたたみシェブロン`»`と統一した記号)を追加する。**
- 対応: ボタンのラベル更新ロジック(`updateCollapseToggleButtonLabel()`)で、テキストの前に`»`(または既存の折りたたみボタンと同じグリフ)を追加する。状態(折りたたみ中/展開中)に応じて向きを変える(既存の個別カードの折りたたみボタンと同じ回転ロジックが使えるなら流用する、判断は実装者に委ねる)。

### 43-L1: 性格ボックスのホバーでテキストを出さず、編集不可カーソルにする

- 現状: `#nature-readout-value`(`LeftPanel.astro`)は`readonly`の`<input>`で、`title="能力値のA/B/C/D/Sラベルの▲▼から自動的に決まります。ここでは編集できません。"`を持つ(ホバーでブラウザ標準のツールチップが出る)。
- 要件: **ホバー時にテキスト表示(ツールチップ)を出さず、代わりにマウスカーソルを「編集不可」のマーク(`cursor: not-allowed`)にする。**
- 対応: `title`属性を削除する(`aria-label`はスクリーンリーダー用に維持し、削除しない)。CSSで`#nature-readout-value { cursor: not-allowed; }`を追加する(`.field-control`基底の`cursor`指定を上書きする形になっても構わない)。

### 43-D1: "まだダメージ計算がありません" を削除

- 現状(ラウンド42-D1適用後の想定): `buildEmptyState()`(`damage-calc.ts`)の見出し(`.damage-empty-state-title`、テキスト「まだダメージ計算がありません」)。ラウンド42-D1でヒント文(`.damage-empty-state-hint`)は既に削除されている想定のため、**この見出しが削除されると空状態はCTAボタン(「+ ダメージ計算を追加」)だけになる**。
- 要件: この見出しテキストを削除する。
- 対応: `title`要素(`.damage-empty-state-title`)の生成・appendを削除する。CTAボタンのみが残る形にする。

### 43-D2: 相手ポケモン画像が右寄りに見える。中央になるよう左へ移動

- 現状: `.damage-sprite-box`(相手ビルドの箱内、スプライト画像+アイテム/タイプバッジを内包する領域)の配置。ユーザーの目視では画像が箱の中で右に寄って見える。
- 要件: **画像が箱の中で中央に来るよう左に移動する。**
- 対応: `.damage-sprite-box`自体、またはその中の`<img>`の`margin`/`justify-content`/`align-items`等を実測(`getBoundingClientRect()`で画像とその親コンテナの中心座標を比較)した上で、中央に来るよう調整する。**バッジ(アイテム/タイプ)がスプライトに重ねて絶対配置されている場合、バッジの分だけ画像の見た目の重心がずれている可能性がある**(バッジ自体を動かすのか、画像側を動かすのか、実測して原因を特定してから対応すること)。

### 43-D3: ダメージ結果の確定数3以上(確3・10発以上のケースを含む)は薄青で表示

- **前提**: ラウンド41(41-D4)で`.damage-row-total-result[data-severity="safe"]`(累計結果)を薄青系(`--color-primary-soft`/`--color-primary`/`--color-primary-strong`)に変更済み。ラウンド42(42-D3)で「10発以上」のケースは確定数の**ラベル文字だけ**を非表示にする(背景色=safeの薄青自体は維持する想定)。
- ユーザーは今回「確3、乱3も薄青で」と改めて指定している。**「乱3」に相当するラベルは現在のコード(`describeSeriesVerdict`/`describeStandaloneLethal`)には存在しない**(ラウンド21-D7で「乱M (x%) →確N」の中間表示は廃止済みで、現在は「確N」または「10発以上」の2種類のみ)。おそらく「10発以上」のような、確殺に至らない・不確実性のあるケースを指して「乱」と表現していると推測されるが、断定はせず、**実装者は次を実測で確認すること**:
  1. 累計結果(`.damage-row-total-result`)で確3・確4・10発以上のケースがすべて薄青(41-D4のトークン)で表示されていること(41-D4・42-D3の実装後の状態を再確認する)。
  2. **個別技カードの結果(`.damage-column-result`)には現在色分けが一切無い**(38-D4「個別の技カードの計算結果はカラー表示せず、累計だけ色分けする」)。今回の指示が個別技カードにも確3以上の薄青着色を求めているのか、累計結果の再確認だけで足りるのかは**指示文からは判断できない**。**Coordinatorの判断: 「ダメージ結果」は文脈上、これまで色分けの対象だった累計結果を指すと解釈し、個別技カードの無色化(38-D4)は維持する。** ユーザーが個別技カードへの着色も意図している場合は、次回の指示で明示されるはずなので、その場合に対応する。
- 対応: 上記1を実測で確認し、もし累計結果で確3/確4/10発以上のいずれかが薄青になっていないケースがあれば(42-D3の実装によって意図せずsafeのセマンティックが崩れていないか等)修正する。**新規のCSS変更が不要であれば「確認のみで完了」としてよい。**

### 43-D4: 相手ビルドのテラスタイプの書式を特性入力ボックスに揃える

- 現状(ラウンド41-D1・42適用後の想定): `#opponent-notes-section`のテラス選択(`.tera-dropdown-button`、アイコンを外しテキストのみにする41-D1対応済み)の書式(フォントサイズ・高さ・padding)が、同じ相手ビルドの箱にある特性の入力欄(`<select>`、特性名を選ぶ欄)より大きく見える。
- 要件: **テラスタイプの書式(フォントサイズ・高さ等)を特性入力ボックスに揃える。**
- 対応: 特性`<select>`の`getComputedStyle()`(font-size・height・padding)を実測し、`#opponent-notes-section .tera-dropdown-button`(41-D1で簡素化した後のテキストのみのボタン)の対応する値をこれに一致させる。

### 43-D5: 削除・圧縮展開ボタンの丸枠が中央からずれている

- 現状: `.damage-row-icon-button`(28px円形、削除ボタン`.damage-row-delete-button`と折りたたみトグル`.damage-row-collapse-toggle-button`が共有する基底クラス)。ユーザー指摘: 丸い枠(背景の円)の中で、中の記号(×・»)が中央からずれて見える。
- 要件: **丸枠の中心と記号の中心を一致させる。**
- 対応: `getComputedStyle()`と実際のレンダリング(`--scale 3`程度の拡大クロップ)で、`line-height`・`padding`・`display: flex; align-items/justify-content`等の設定を確認し、記号(テキストまたはSVG)が円の幾何学的中心に来るよう調整する。**41-D3で`»`の`font-size`を1.3rem・`font-weight:700`に変更した際に、行の高さの基準がずれていないか**も確認すること(フォントの実際の描画ボックスと`line-height`のズレはこの種のセンタリング崩れの典型例)。

### 43-D6: 技カードの削除ボタンを技カード右上に固定

- 現状: 各技(移動先の技カラム、`.damage-column`)内の削除ボタン(`.damage-column-remove-button`、「×」)は、技名入力欄と同じ行にインラインで配置されている(技名 / ヒット数入力 / 「×」が横並び)。
- 要件: **削除ボタンを技カード(`.damage-column`)の右上に固定配置する**(カード全体の削除ボタン`.damage-row-delete-button`と同じ考え方: `position: absolute; top; right;`)。
- 対応: `.damage-column-remove-button`を技名行から切り離し、`.damage-column`(または適切な相対配置の親要素)を基準に右上へ絶対配置する。技名入力欄がボタン分の余白を確保する必要がなくなるため、入力欄の幅が広がる可能性がある(問題なければそのままでよい)。ホバー時のみ表示にするかどうかは実装者の判断(既存の`.damage-row-delete-button`の表示方式と合わせるとよい)。

### 43-D7: 圧縮展開ボタンの>>を少し細字化する(**41-D3を一部撤回**)

- 前提: ラウンド41(41-D3)で`.damage-row-collapse-toggle-button`の`font-weight`を(未指定→)`700`にした経緯がある。
- 要件: **>>記号(`»`)を少し細く(細字に)する。**
- 対応: `font-weight`を700から下げる(例: 500〜600、実測しながら「太すぎず視認性は保つ」バランスを探す)。41-D3の「小さくて見づらいので拡大・強調する」という目的自体(font-sizeの拡大、色のコントラスト向上)は維持しつつ、太さだけを弱める。**この変更は41-D3の`font-weight`部分のみを対象とする撤回であり、font-sizeやcolorの変更は撤回しない。**

### 43-R1: >>>の文字を少し小さくする(**41-R2を一部撤回**)

- 前提: ラウンド41(41-R2)で右サイド詳細パネルのヘッダー矢印を単一シェブロンから「>>>」(三重シェブロン、`viewBox 0 0 36 24`、CSS幅33px×高さ22px)に変更した。
- 要件: **>>>の文字(SVG)を少し小さくする。**
- 対応: `.damage-detail-selection-arrow`のCSS幅・高さを、現在値(33×22px)から一回り小さい値に調整する(具体的な縮小量は実装者判断。他の要素(名前・矢印・相手アイコン)とのバランスを見ながら決める)。

## 検証手順(実装者が行うこと)

1. `npm run shot`でライト・ダーク両方を撮影し、Read toolで目視確認する。
2. 43-D2(スプライト中央寄せ)・43-D5(丸枠と記号の中心一致)は`getBoundingClientRect()`で実測して確認する(目視だけでは微小なズレが分からない)。
3. 43-D3は累計結果・個別技カードの両方で確3/確4/10発以上のケースを実際に再現し、色を確認する。
4. `npx astro build`成功・`git diff --stat`で担当ファイル以外に差分が無いことを確認する。
5. DBに個体を作った場合、または対戦相手メモを作った場合は必ず元の状態に復元する。
6. `git stash`は使わない。
