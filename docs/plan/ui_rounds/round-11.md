### 11-1. ヘッダー: ニックネーム・保存済み表示を削除

- タイトル(`AppLayout` の `title` prop)は `pageTitle`(ニックネーム優先、なければ種族名。フロントマターで算出)がそのまま出ている。ニックネームをタイトルから外す場合は `pageTitle` の算出ロジック(フロントマター側)を種族名固定に変更する。**ニックネーム入力欄自体(左パネル `#nickname`)は削除しない**(要望はヘッダー表示のみ)。
- 「保存済み」表示は `slot="topbar-status"` に差し込んでいる `#autosave-status`(`[id].astro:90-95`、テキストは `#autosave-status-text`)。`<script>` 側の `el<HTMLElement>("autosave-status")` / `el<HTMLElement>("autosave-status-text")`(`[id].astro:2549-2550`)がこれらのIDに依存して保存状態(saved/saving/error)を書き換えている。**要素ごと削除すると `el()` が例外を投げてスクリプト全体が初期化に失敗する**(`el()` の仕様は `owned-pokemon-form.ts:11-17`)。
  - 対処: 表示は消すが要素は残す(`hidden` にするか、`.app-topbar-status` ごと `display:none` の実要素として残置)。または `<script>` 側の該当参照・更新処理をあわせて削除する(保存状態インジケータ自体を廃止する場合)。**再試行ボタン(`#retry-button`)は保存失敗時の唯一のリカバリ手段なので、テキスト表示だけ消して機能は残すか、ユーザーに要確認。**

### 11-2. 左パネル: アイテム・テラスタルのアイコンをポケモンアイコンの下にまとめる

現状(`[id].astro:1900-1938`): `.top-block-icon` に種族アイコン(`#species-icon-box`、72px)のみが単独で入り、アイテム(`#item-image`)とテラスタイプ(`#tera-image-badge`)は種族アイコンと別ブロックの `.field-grid`(1919行)内で、それぞれの入力欄の隣に小さく表示されている。
- 要望は「アイテム・テラスタルのアイコンを種族アイコンの**下**にまとめて配置」。入力欄(`#item` テキスト入力、`#tera` セレクト)自体は引き続き `.field-grid` に残してよいが、**アイコン画像(`#item-image` / `#tera-image-badge`)は `.top-block-icon` 内、種族アイコンの下に移設**する(横並び2アイコンで良い)。
- 移設後もアイテム名/テラスタイプが変わるたびに更新する `updateItemImage()`(`[id].astro:2604`)/ `updateTeraImage()`(`[id].astro:2628`)は同じ `id` 参照で動くため、**DOMの位置を変えるだけで `<script>` 側の変更は基本不要**(IDを変えないこと)。

### 11-3. 左パネル: 技ボックスを技タイプの色にする

- 技入力欄(`#move-1`〜`#move-4`、`[id].astro:1950-1959` 付近、`.field-with-image.move-input-group`)は現状すべて同じ見た目。技名が確定した時点でその技のタイプ(ほのお/みず等)に応じて枠または背景色を付ける。
- タイプごとの色は既存の `TYPE_COLORS`(`[id].astro` 内、`const TERA_TYPES` の直前コメント「すぐ上のTYPE_COLORSと同じ理由」から存在が確認できる、grep して確認すること)を再利用する。技のタイプは `autocomplete/moves.json` の `type` フィールド(`owned-pokemon-form.ts` の `loadAutocomplete()` が読み込む datalist とは別に、技名→タイプの Map が必要。**新規に `type` 込みで技名をキーにした Map をロードするヘルパーを追加**するか、既存の `loadMultiHitMoveMap()`(`pokemon-master-data.ts:90`)と同じパターンで `loadMoveTypeMap()` を足す)。
- 技名入力(`change`/`input`)のたびにこのMapを引いて `border-color` や `background` をインライン or クラス切り替えで反映する。**未確定の技名(タイポ・入力途中)は色を付けない(通常表示に戻す)。**

### 11-4. 左パネル: 技候補は learnsets にある技を優先表示

- 現状、技のオートコンプリートは `#move-list`(datalist)に **全716技を無条件で** 流し込むだけ(`owned-pokemon-form.ts:29-47` の `fillDatalist`)。種族の覚え技(learnset)による絞り込み・優先表示は一切していない。
- learnset データは `public/master-data/detail/pokemon.json`(ビルド生成物、`scripts/build-master-data/extract_autocomplete.py` の `build_pokemon_detail()` が `learnset: [m for m in data.learnset if _is_real_name(m)]` として全ポケモン分埋め込み済み。**新規データ生成は不要**)に既にある。同ファイルは `pokemon-master-data.ts` の `loadBaseStatsMap()` が既に `fetch("/master-data/detail/pokemon.json")` している(`pokemon-master-data.ts:65`)ので、**同じレスポンスから `learnset` も拾う `loadLearnsetMap(): Promise<Map<string, string[]>>` を追加**するのが最小コスト(`loadMultiHitMoveMap()` と同じキャッシュ済みPromiseパターンで書く。`PokemonDetailEntry` interface に `learnset: string[]` を足す)。
- 「優先表示」の実装方針: `datalist` は `option` の並び順がそのままブラウザの候補表示順に概ね反映される(絶対保証ではないがChromium系は入力文字列にマッチする順に近い挙動)。種族名(`#species-name`)が確定・変更されるたびに `#move-list` の中身を**その種族の learnset を先頭、残りの全技をその後**の順で再構築する関数を用意し、種族名変更イベント(既存の `applyTypeBadge()` や種族アイコン更新と同じフックポイントのはず、grep して既存の「種族名変更時の処理」関数を特定して相乗りすること)に接続する。
  - 初期表示(ページロード時、既存の種族名がある場合)にも適用すること。
  - 種族が未確定/存在しない名前のときは全技リストのみ(現状の挙動)にフォールバック。

### 11-5. ダメージ計算カード: 結果表示(確定数・ダメージ)を1段・横並びに変更

- **ラウンド5で導入し、ラウンド8/10で明示的に維持してきた「結果チップの主役化」(`.damage-column-result` を `flex-direction: column` の2段で `確N` を太字大きく先頭・数値を小さく下段、`[id].astro:1572-1589`)の「縦2段」部分をここで撤回する。** 太字強調(`確N` を目立たせる)という主役化の趣旨自体は維持してよいが、レイアウトを `flex-direction: row`(横並び1段)に変更し、縦サイズを圧縮する。
- 対象は技列フッターの `.damage-column-result`(`[id].astro:4060`、子要素 `.damage-result-verdict` / `.damage-result-detail`。DOM構造は `<script>` 側で組み立てているため、クラス名を変えなければCSSだけの変更で足りるはずだが、`row` にした際に長い数値(例: `254〜299 (165〜195%)`)が折り返す/はみ出す幅を実測して確認すること)。
- **`.damage-row-total-result`(相手ビルド箱側の累計チップ、行レベル)は元々 `grid-template-columns: auto 1fr` の横並びなので対象外。** 変更するのは技列(カード内)側の `.damage-column-result` のみ。
- ラウンド10で导入した「N発目ラベルと技名の同行化」(`.damage-column` の grid化)とは独立した変更であり、干渉しないこと。

### 11-6〜11-9. 右パネル(`#damage-detail-panel` / `renderColumnLevelDetailPanel()` `[id].astro:4371-4479`、`buildSideSection()` `4274-4365`、`buildIconToggleGroup()` `4233-4261`)

opusアドバイザーに実測制約(パネル実質幅は1600px以上のサイドバー常設時が最も狭く**268〜328px**、1600px未満のオーバーレイ時は**368px前後**。従来「350〜360px」と見積もっていたのは誤りで、`.damage-detail-panel-body { padding: 0.9rem 1rem 1.4rem }` 基準で再計算した値が正)を渡して講評を受けた。方針:

**11-6. 表示順を 攻撃側(急所含む)→防御側→場の設定 に変更**
- 現状の描画順は 天候→フィールド→壁→攻撃側→防御側(`renderColumnLevelDetailPanel()` 内、天候ブロックが `buildSideSection` 呼び出しより前)。**この呼び出し順序を入れ替えるだけ**(天候/フィールド/壁のブロックを2回の `buildSideSection()` 呼び出しの後ろに移動)。
- 天候・フィールド・壁の3見出し(「天候」「フィールド」「(自分側/相手側の)壁」)は「場の設定」1見出しに統合する。

**11-7. 能力ランクをスピンボックス化**
- `buildSideSection()` 内の `rankSelect`(`<select>` -6〜+6の13択、`4297-4315`)を `<input type="number" min="-6" max="6" step="1">` に置き換える(ネイティブスピンボックスとして矢印が出るため「サイドバーにする」フォールバックは不要と判断)。
- 実装時の注意(opus助言): `min`/`max` はキー入力を止めないので `input`/`blur` で `[-6, 6]` にclamp必須。矢印クリック・キーボード編集の両方を拾うため `change` だけでなく `input` も購読(既存のdebounce保存に乗せる)。フォーカス中の `wheel` で値が変わる事故を `preventDefault` で防ぐ。`.is-nonzero` の強調スタイルは維持。iOSで矢印が出ないため `inputmode="numeric"` を付与。

**11-8. 状態異常をアイコン選択に変更、ゆめうつつを除外**
- `DAMAGE_AILMENTS`(`2998-3007`)から `ゆめうつつ` を削除(6種+なし)。`buildSideSection()` 内の `ailmentSelect`(`<select>`、`4321-4329`)を `buildIconToggleGroup()` と同じ仕組みのアイコントグルに置き換える(どく/もうどく/まひ/やけど/ねむり/こおりの6種のSVGを、既存の天候/フィールドアイコンと同じ流儀=24x24 viewBox・`stroke-width="1.75"`・18px表示で新規作成。色分けはせず単色維持)。

**11-9. 強天候を削除**
- `DAMAGE_WEATHERS`(`2977-2986`)から `おおひでり` / `おおあめ` / `らんきりゅう` の3エントリを削除(はれ/あめ/すなあらし/ゆきの4種+なしが残る)。**`src/pages/damage-calc/index.astro` の `WEATHERS` と選択肢を同期させる旨のコメント(`2971-2972`)がこのファイルにあるが、damage-calc側は今回の依頼範囲外なので触らない**(コメントの但し書きだけ「個体編集の詳細設定のみ強天候を除外している」旨に更新する)。

**省スペース化(「セクションごとに横並び配置するなど」への回答、opus助言の要点)**
- 攻撃側/防御側セクションを左右2カラムにする案は**不成立**(1カラム約128〜144pxしかなく状態異常アイコンが2列×4行になり縦が縮まらない)。**縦積みのまま維持**し、各セクション内の行内圧縮で稼ぐ。
- 各セクション内: 「見出し+能力ランク」を1行、「テラスタル発動(+急所固定)」チェックを1行、状態異常アイコンを1行(4列×2行目安)、の3行構成に圧縮する。チェックボックスの文言は「テラスタル発動」→「テラスタル」、「急所固定で計算する」→「急所」に短縮し正式名は `title` 属性に残す(**ユーザー可視文言の変更を伴うため、実装エージェントは変更点を報告に明記すること**)。
- 「場の設定」: 天候(4択+なし)・フィールド(5択+なし)はどちらも1行に収まる想定。壁トグルは1行(ヒント文を短縮)。見出しは「場の設定」1つに統合。
- 縦圧縮の主因は `.damage-detail-section-heading` の `margin: 1rem 0 0.4rem` と `.damage-detail-icon-group` の `margin-bottom: 0.9rem`(共に `[id].astro` 内のグローバルスタイル、grepして特定)。ここを詰めるのが最小コストで最大効果。
- 概算(opus試算、実測ではない): 現状 約720px → 本案で約480〜530px。**実装後に1600px/1400px/390pxの3幅で実測し、ラベル折返しが出た場合はラベル短縮・列数調整で微調整すること。**

**実装リスク(opus助言、必ず対応すること)**
1. **既存データの残存値の正規化が必須**: `DAMAGE_WEATHERS`/`DAMAGE_AILMENTS` から選択肢を削除しても、既に保存済みの個体データに `おおひでり`/`ゆめうつつ` 等の値が残っていると、アイコン群は全て非選択(`aria-pressed="false"`)に見えるのにエンジン計算には反映され続けるという不整合が起きる。**描画前に「選択肢配列に存在しない値は空文字に正規化」する処理を追加し、正規化後の値で保存し直すこと。**
2. `buildSideSection()` は `detailPanelBodyEl` に直接 `appendChild` する副作用関数(戻り値なし)。呼び出し順序の入れ替え自体はこのままでも可能だが、レイアウトを弄る過程で扱いにくければ「要素を返す」形に機械的にリファクタしてよい(挙動は変えないこと)。
3. `buildIconToggleGroup()` は現状 `role="radiogroup"` を付けているが子ボタンに `role="radio"` が付いておらず `aria-pressed` と役割が不整合。状態異常アイコン化で選択肢グループが増える今回、余裕があれば `role="group"` + `aria-label` へ修正してよい(必須ではない、時間があれば)。

### 実装順序(推奨、opus助言ベース)
1. `DAMAGE_WEATHERS`/`DAMAGE_AILMENTS` から該当選択肢を削除 + 既存データの正規化処理を追加 → テスト。
2. 能力ランクの `<input type="number">` 化。
3. 状態異常のアイコン化(SVG追加)。
4. 右パネルのセクション順序入れ替え + 見出し統合。
5. 右パネルの行内圧縮・省スペース化(3幅で実測して微調整)。
6. ダメージ計算カードの結果チップを横並び1段に変更。
7. ヘッダーのニックネーム/保存済み表示を削除。
8. 左パネル: アイテム/テラスアイコンの再配置、技ボックスのタイプ色、技候補のlearnset優先表示。

ステップ1〜6は右パネル・ダメージ計算カードに閉じるため1つのsonnetエージェントに、7〜8はヘッダー・左パネルに閉じるため別のsonnetエージェントに担当を分ける(**同じファイルを2体同時に触らせないよう、順番に実行しレビューを挟むこと**)。

### 実施結果: ステップ1〜6(右パネル・ダメージ計算カード、2026-07-26)

sonnetエージェントが実装・検証済み。要点:

- 描画順序を 攻撃側→防御側→場の設定 に変更、天候/フィールド/壁の見出しを「場の設定」1つに統合。

- 積み残し: 状態異常アイコン群の `role="radiogroup"`に対し子要素の`role="radio"`が無い不整合は未対応(必須要件外)。ダークモードのネイティブチェックボックスの見た目は本ラウンドのスコープ外。

## 11-8 の修正(2026-07-26 ユーザー指示 追加)

ユーザーの言葉(そのまま引用): **「状態異常は種類が多く場所をとるのでリストから選択する方式にする」**

**上の「実施結果」で導入したばかりの状態異常アイコン化(`buildIconToggleGroup()`化)を撤回する。** 状態異常は「なし」込み7択(強天候削除と違いラウンド11で個数は変えていない)あり、アイコン+ラベル1個あたりの専有面積が天候・フィールド(なし込み5択、1行に収まる)より広く、複数行に折り返して省スペース化の効果を打ち消していたと判断されたための修正。

### 変更内容
- 攻撃側/防御側それぞれの状態異常ピッカーを、直前の実装(アイコントグル)から**リスト選択方式**に戻す。「リストから選択」という言葉どおり、素朴な `<select>`(ドロップダウン)に戻すのが最も直接的な解釈であり、**選択肢が何個あっても表示は常に1行**という要求(「場所をとる」の解消)に最も強く合致する。カスタムのリストボックス/コンボボックスを新規に作る積極的な理由はないため、**ネイティブ `<select>` への回帰を推奨する**(ラウンド11以前と同じ実装パターン。ただし文言短縮は維持してよい: 「状態異常なし」ではなく短い「なし」等)。
- 今回のアイコン化のために追加した状態異常専用SVG(`ICON_AILMENT_POISON` 等6種)は、選択肢ピッカーとしては使われなくなる。**未使用コードとして削除する**(残すとdead codeになる)。ただし他の用途(例: ダメージ計算カード上での状態異常アイコン表示等、既に別の場所で使っていないか確認すること。使っていなければ削除でよい)。
- **天候・フィールドのアイコントグル化はそのまま維持する**(今回ユーザーが問題視したのは状態異常のみ。「場の設定」の1行圧縮は5択で成立しており対象外)。
