## ラウンド4の要件(2026-07-26 ユーザー指示)

ユーザーから直接出た要件。**アドバイザー講評より優先する**(下記のとおり第3弾の設計判断を明示的に覆すものを含む)。

### ボックス画面 `/box`
- **カードが大きすぎる。現在の1/3くらいの面積で、正方形にする。** 現状 312×401px(=125,000px²)なので、**1辺およそ200pxの正方形**(=40,000px²)が目標。`.box-shell` 1760px なら1行8列前後になる。
- **タイプバッジは不要**(公式絵を見れば分かる)。→ ラウンド2 A-6/B-5/B-7 とラウンド3の該当対応は**撤回**。
- **性格は不要**(ステータス表示(実数値の↑↓)から分かる)。→ ラウンド2 A-5 の「性格・特性のメタ行」のうち**性格は削除**。特性の扱いは実装者判断(200px正方形に収まらないなら落としてよい)。
- 200pxの正方形に何を残すかは実装者の判断。優先順は **公式絵 > 名前 > 実数値6値**。技・持ち物は入らなければ落とすかホバー表示にしてよい。

### 個体編集画面 `/box/[id]` 全体
- **ドロップダウンの見た目が2種類混在している。「ホバーしたときだけ下向き記号が出る」ほうに統一する。** どちらがどれか(ネイティブ `<select>` / datalist付き `<input>` / 自前コンボボックス)は実装者が特定すること。
- **性格の選択UIを廃止する。** 性格はステータス補正にしか影響しないので、**能力値のラベルをクリックして上昇/下降を切り替える**UIにし、性格は**内部で逆算して保存するだけ**にして画面には出さない。
  - 制約: 上昇1つ・下降1つの排他選択。**HPには性格補正が無いのでHPは切り替え対象外**。上昇と下降が同じ能力になる組み合わせは無補正(まじめ等)として扱う。25種の性格 = 5(上昇) × 5(下降) の対応表が必要。
  - **この指示は「個体編集画面 全体的に」の項なので、ダメージ計算カードの相手ビルドにも同様に適用する**(相手ビルド箱にも実数値行があり、性格セレクトを1行まるごと削れるので高さ削減にも効く)。相手ビルド箱の努力値/実数値グリッドのH/A/B/C/D/S見出しをクリック対象にするのが自然。
- **左上のポケモンアイコンとカード内のアイコンが重複している。左上にはアイコンを置かず、代わりに戻るボタンを置く。**(ラウンド3 B-6「ヘッダをテキストのみに」B-13「戻るを左に」と同方向)
- **「この個体を削除」を右上に置く。**(ラウンド3 B-9 の「ヘッダのオーバーフローメニュー」案の具体化)

### 個体編集画面 編集カード(左カラム)
- **ポケモンのアイコンが小さい。**大きくする。
- **技1〜4に個別ラベルを置かず、「わざ」を1つ置くだけにする。**(ラウンド3 A-8 の横並びラベル統一の中で、技だけはグループラベル1つ)
- **技の詳細はリンク(↗ で `/moves/[name]` へ遷移)ではなく、ホバー表示にする。**
- **タイプ画像はアイコン部分だけ丸くトリミングして使う。** 現在のタイプ画像は「アイコン+タイプ名」の横長リボンなので、左のアイコン部分だけを円形に切り出す。

### 個体編集画面 ダメージ計算カード(右カラム)
- **相手ポケモンのアイコンが小さすぎる。**大きくする。
- **下部の「保存済み」表示は削除する。**(ラウンド3 A-4 は「定常時 hidden」だったが、ユーザー指示は削除。DOMはJS/E2E依存があるので残し、視覚的に出さない)
- **相手ビルドの箱と技列の箱を同じ高さにする設計を見直す。** 技列の空きスペースが目立つため。
  - **これは第3弾で確立した「`align-items: stretch` で下端を揃える」設計を明示的に覆す指示。** 計画書 第3弾/ラウンド3の「維持すべき点」に挙がっている下端揃えの構造は**この指示により破棄してよい**。
  - 代替の構成は実装者の判断。例: 技列を縦積みの行(1技=1行のコンパクトな帯)にする / 技列の高さを内容に合わせて縮める / 相手ビルドを上段・技列を下段の2段組にする、など。`DamageCard.png` の構造からは逸脱するが、**ユーザー指示が優先**。
  - ただし `.damage-row` / `.damage-column` / `.damage-row-columns-wrap` / `.damage-row-build` / `.damage-row-body` などのクラス名・要素は引き続き改名・削除しない(JSとE2Eが依存)。

### 実装中に見つかったバグ(UI改修とは別の実バグ)
- `/box`: **テラスバッジのレース条件**。`applyCardTypeBadges()` が非同期なのに `void` で待たず、同期の `appendTeraChip()` が先にDOM挿入されていたため、順序が `[テラス, タイプ1, タイプ2]` になっていた。「タイプ順が図鑑と逆」に見えた症状も同一原因(データ側は正しい順序)。
- `/box`: 空状態の `emptyMessage.hidden` の条件式が誤っており、**本当に0件のときに何も表示されない**状態だった。
- `/box/[id]`: `.damage-row-footer { display: flex }` が `[hidden] { display: none }` に詳細度で勝ち、`hidden = true` にしても隠れていなかった(`.damage-column-hitcount-row` と同じ既知の罠)。
- `/box/[id]`: 性格の上昇/下降が片方だけ選択された不完全な状態を実数値プレビューに反映しており、「クリック直後は補正が見えるのに保存/再読込で消える」不整合があった。`normalizedNatureBoosts()` で正規化してから表示するよう修正。

### ラウンド4の積み残し(次に着手する項目)
1. **タイプ画像の円形トリミングが左カラムに未適用**(要件7の未達)。`.type-badge-img` が `object-fit: fill` / `border-radius: 0` のまま24×24に押し潰され、リボン画像が判読不能になっている。テラスタイプ画像側にだけ `cover / 0% 50% / 50%` が入っている。**左カラムのタイプバッジにも同じ円形トリミングを適用する。**
2. 持ち物欄が長い値(「こだわりハチマキ」)で見切れる。
3. 空欄の `:placeholder-shown` を破線+透明背景にして「空きスロット」を表現(ラウンド3 B-11)。
4. 結果チップの主役化(ラウンド3 C-4): `grid-template-columns: auto 1fr` で左に `確1`(大・太字)、右に数値(小)。JSのテキスト生成変更を伴うため単独ラウンドで扱う。
5. 相手ビルドの性格クリックUIは、未設定の個体で「上昇→下降」の2クリック目まで実数値が変化しない(仕様上は正しいが初回操作のフィードバックが薄い)。
6. 技詳細ツールチップが2〜3行で折り返す。横幅を持たせたい。
7. 390px幅で削除ボタンがタイトル直下に折り返され、視覚的にやや強い。
8. `/box`: テラスタイプを正方形カードから完全に落としてある。公式絵から読み取れない情報なので、戻すか否かは要判断。
