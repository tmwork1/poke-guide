### 22-A コントラストの基底不足(3件・WCAG)

ラウンド21ではページscopedの上書きで個別に是正しただけで、**基底は未達のまま**。

| # | 対象 | 実測 | 基準 |
|---|---|---|---|
| A-1 | `global.css` の `.btn-danger`(背景 `--color-danger` + 白文字) | **ライト 2.82:1** | WCAG AA 4.5:1 |
| A-2 | `global.css` の `.card.is-selected` の `border-color: --color-primary`(`--color-surface-alt` 上) | **ライト 2.50:1** | WCAG 1.4.11 非テキスト 3:1 |
| A-3 | `box/index.astro` の `.delete-button`(`color: --color-danger`) | **ライト 2.82:1** | WCAG AA 4.5:1 |

- **新色は作らない。** ラウンド21で `/box/[id]` の削除ボタンに使った **`--color-danger-strong`(#b23a26、白文字で 5.96:1)** が既にあるので、それを基底でも使う。
- **A-1 を直したら、ラウンド21で `/box/[id]` に入れたページscopedの上書きは不要になる可能性がある。** 重複していたら消すこと(残すと「なぜ2箇所にあるのか」が分からなくなる)。
- **ダークは既に達成している**(`.btn-danger` 7.93:1)。**ダークを壊さないこと。**
- A-2 は border の色なので、`border-color` を濃くするか、`--color-surface-alt` との組み合わせを見直す。**選択状態が「見える」ことが目的で、色そのものを変えるのが目的ではない。**

### 22-C 右パネル(相手ビルド)の特性入力を種族別の選択ボックスに

ラウンド21の 21-L5 で**左パネルだけ**を `<input list>` → 種族別の `<select>` にしたため、**右パネルだけが自由入力+全特性datalistのまま**になっている。同じ「特性を選ぶ」操作なのに画面内で作法が2つある。

- `loadAbilitiesMap()`(`src/lib/pokemon-master-data.ts`、ラウンド21で追加済み)をそのまま使う。
- **相手の種族が未入力のときの挙動**を決めること。左パネルは「種族未選択なら空/disabled」。相手ビルドは種族を自由に打ち替えるので、**同じ扱いで操作を妨げないか実機で確かめる**こと。妨げるなら**現状維持にして理由を報告する**(勝手に妥協しない)。
- **`#ability-list` datalist は消さない**(消すと参照が壊れる)。使われなくなったら、その事実を報告すること。

### 22-E jpoke更新時の回帰検出の穴(3件)

**vendor/jpoke が実際に更新された直後なので、今こそ塞ぐ意味がある。** 出典: round-12.md

| # | 穴 |
|---|---|
| E-1 | `calcStats` / `calcLethalSequence` が**ネイティブ一致確認の対象外**。`tests/e2e/damage-calc.spec.ts` はブラウザの `calc()` とネイティブ `expected.json` を比較するが、この2つは比較していない |
| E-2 | `generate_expected.py` が**古い複製**で `boosts` が未反映。期待値の生成元がアプリの呼び出しと食い違っている |

- **E-3 は「バージョンを1箇所から読む」形にする。** `vendor/jpoke/pyproject.toml` かビルド生成物からバージョンを取り、URLを組み立てる。**ビルド時に解決できるならそれが最善**(実行時fetchを増やさない)。
- **E-1 / E-2 は期待値の再生成が要る。** `vendor/jpoke` は**今回更新されたばかり**なので、**再生成した期待値が現在のvendorと一致することを確認**すること。一致しない場合は**アプリ側のバグの可能性があるので、勝手に期待値を書き換えず報告する。**

### 22-F `/box/[id]` が読み込むだけでDBに `PUT` を飛ばす

出典: round-09.md。「対戦相手メモ1件につき1回、内容は不変」。

- **⚠️ Coordinatorがラウンド21で実測したところ、`PUT /api/owned-pokemon/:id` は0件だった。** 飛んでいるのは **`PUT /api/opponent-notes/:id`** のはず。**まず実測して、本当に飛んでいるか・何件か・内容が不変かを確認すること。** 飛んでいないなら「もう直っている」と報告して終わってよい。
- 飛んでいる場合、**内容が不変なのに書き込んでいる**のが問題。`updated_at` が無意味に更新され、フィクスチャの差分検出も鈍る。**初期描画では保存しない**ようにする。
- **⚠️ 自動保存の仕組みそのものを壊さないこと。** ユーザーが実際に入力したときは従来どおり保存されること、を実機で確認する。
