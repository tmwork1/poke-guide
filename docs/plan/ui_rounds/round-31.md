### 要件(ユーザーの言葉を引用したうえで具体化する)

#### `/box`(ボックス一覧)— 担当ファイル `src/pages/box/index.astro`

- **31-B1** > 「テラスアイコンの位置を少し上げる」
  現在 `.card-tera-badge` は 25×25px / y=249.5。**上へずらす。** 公式絵・持ち物行(y=298)・お気に入り/削除アイコン(y=156.1 / 188.1)と重ならない範囲で、視覚的に「絵の中に収まっている」と読める位置にすること。**ずらした後の実測値を報告すること。**

- **31-B2** > 「ステータス直上の横棒を削除」
  `.card-stat-grid` の `border-top: 1px solid var(--color-border)` を外す。**罫線を消すと技行とステータス行が地続きに見えるので、消したぶんの間隔を確保して区切りを保つこと**(31-L7 と同じ考え方)。カード全体の高さ 257.34px は**変えないこと**(グリッドの正方形が崩れる)。

#### `/box/[id]` ヘッダー

- **指示なし**(ユーザーの箇条書きが空だった。上の注記参照)。**何も変更しない。**

#### `/box/[id]` 左サイド — 担当ファイル `src/pages/box/[id].astro`

- **31-L1** > 「ポケモン画像の背景食を除去。」(原文ママ。「背景色」の誤変換と解釈する)
  公式絵 `.species-sprite-img` を包むコンテナの背景色(角丸の薄い箱)を透明にする。**画像そのものは 144×144 のまま。**

- **31-L2** > 「アイテム画像+文字のサイズを大きくする。ポケモン画像を少し左に移動してよい。」
  `.item-image`(現在20px)と持ち物名テキストを拡大する。**幅が足りなければ公式絵を左にずらしてよい**(27-H1で確定した「中央寄せ」を**この要件の範囲で撤回する**)。**ただしラウンド28で「アイテム画像41px vs 隣の文字13px = 3.2倍」が過大として16→20pxに縮小された経緯(28-L3)があるので、画像と文字の比が1〜1.5倍に収まる範囲で一緒に拡大すること。** 文字は12px下限を割らないこと。

- **31-L3** > 「ポケモン画像の領域にテラスタル画像は不要。」
  `.top-block-tera-image`(20px / (556.6, 228.7))を**表示しない**。**DOMは残してCSSで見せない方針にする**(JSが参照している可能性があるため)。**テラスタル選択欄(`.tera-dropdown-button`)側のアイコンは残すこと**(そちらは 31-L4 の対象)。

- **31-L4** > 「種族名とニックネームの入力欄のY位置をそろえる」
  種族 `select`(y=260.7)とニックネーム `input`(y=264.7)の **4.0pxのズレ**を解消する。あわせて持ち物 `input`(y=374 / h=37.6)と `.tera-dropdown-button`(y=373.5 / h=38.7)の **0.5px・1.1pxのズレ**も解消する(同じ原因の可能性が高い)。**修正後、左列と右列の全行について top と height が一致することを実測して報告すること。**

- **31-L5** > 「テラスタル入力欄も左揃え」
  `.tera-dropdown-button` の中身(テラスアイコン + タイプ名)が中央寄せになっているので、**左揃え**にする。左隣の持ち物入力欄のテキスト開始位置と揃えること。

- **31-L6** > 「種族~テラスタルの入力ボックスのY間隔を詰める」
  種族/ニックネーム行 → 特性/性格行 → 持ち物/テラスタル行 の縦の間隔(現在 **20.8px と 12.8px で不揃い**)を**詰めて、かつ均一にする**。**詰めた結果の gap を実測して報告すること。**

- **31-L7** > 「アイテムと技の入力欄の間の横棒を削除し、代わりに間隔を広げる。技とステータスの間の間隔も同じだけ確保する。」
  (a) `.field-grid.move-fields-grid` の `border-top: 1px` を削除する。
  (b) 持ち物行と技行の間隔(現在 9.6px)を**広げる**。
  (c) 技の最終行と `.stat-table-header` の間隔(現在 8.0px)を **(b) と同じ値**にする。
  **(b) と (c) が同値であることを実測して報告すること。**

- **31-L8** > 「性格補正の三角形のハイライトが見づらいので、塗りつぶしだけでなく、縁取りしてさらに強調表示する。」
  `.stat-nature-up` / `.stat-nature-down` の**選択中**状態に、塗りつぶしに加えて**縁取り**を足す。**新色は作らず既存トークンで行う**(上昇=`--color-danger` 系、下降=`--color-primary` 系の既存の使い分けを維持)。**ライト/ダーク両方で `--scale 3` の拡大クロップを撮り、非選択の ▲▼ と一目で区別できることを目視で確認すること。**

#### `/box/[id]` ダメージ計算 — 担当ファイル `src/pages/box/[id].astro`

- **31-D1** > 「全体カードのホバーハイライトを廃止」
  `.card-damage` の hover 時の浮き上がり(`translateY(-2px)`)・影の変化・背景変化を無効にする。**`.card` 共通の hover 効果を `global.css` 側で消してはいけない**(全ページに波及する)。`.card-damage` にだけ打ち消しを当てること。**選択中(`.is-selected`)の表現は残すこと。**

- **31-D2** > 「カード削除のホバー時の透過を廃止し、ホバー時は赤背景＋文字で表示する」
  ダメージ計算カードの削除ボタンについて、hover 時の `opacity` 変化をやめ、**背景 `--color-danger`(または `--color-danger-strong`)+ その上で読める文字色**にする。**「反転ホバー」のボタン方式に沿った形にすること。** ラウンド23で「削除ボタンhoverの実バグ」を直した経緯があるので、`src/pages/box/[id].astro` 内の既存の削除ボタン hover 実装を読んでから変更すること。

- **31-D3** > 「ポケモン画像の背景色を削除」
  相手ポケモン画像 `.sprite-icon`(112×133.9)を包むコンテナの背景色を透明にする。**31-L1 と同じ処置を相手側にも行う。**

- **31-D4** > 「テラスタル画像は左パネルと同様に選択ボックスの左側に表示し、ポケモン画像の右上の表示を廃止」
  (a) `.damage-type-badge-img`(相手ポケモン画像の右上に重なるテラス画像)を**表示しない**(DOMは残しCSSで見せない)。
  (b) 相手ビルドのテラスタル選択欄の**左側**にテラスアイコンを出す。**左パネルの `.tera-dropdown-button` と同じ形(アイコン + タイプ名の左揃え)に揃えること**(31-L5 の結果と揃える)。

- **31-D5** > 「技カードのN発目の数字を小さくし、領域の幅も狭くする」
  `.damage-column-order-label`(現在 **34×61.4px**)のフォントサイズと確保幅を縮める。**文字は12px下限を割らないこと。** **縮めた後の幅を実測して報告すること。**

- **31-D6** > 「ヒット数は数字2桁が入れば十分。幅を狭くできる。」
  `.damage-column-move-row` 内のヒット数入力の幅を、**2桁(例: `10`)が省略なく入る最小幅**まで狭める。**2桁を入れて省略・はみ出しが起きないことを実際に入力して確認すること**(確認後は必ず元の値に戻す。このページは自動保存が走る)。

#### `/box/[id]` 右サイド — 担当ファイル `src/pages/box/[id].astro`

- **31-R1** > 「最上部のタイトルはパネルor横棒で領域を区切る。文字ではなく、[自分アイコン] <攻撃方向矢印> [相手アイコン] <技名> のように絵的に表現する。」
  現在の `.damage-detail-selection-heading`(「カイリュー — スケイルショット」というテキスト、y=256.9)を、
  **[この個体の公式絵アイコン] → [相手の公式絵アイコン] 技名** という絵的な表現に作り替え、**下側に区切り(`border-bottom` かパネル化)を入れて以下の設定群と領域を分ける**。
  - **矢印の向きは `direction`(攻撃/防御)に追随させること。** この個体が受け側のときは相手→自分の向きになる(→ `00-foundation.md`「攻守切り替え」節: `attacker*` を「常に所持ポケモン」と読んではいけない)。
  - **アイコンサイズは `/box` `/box/[id]` の既存規格(20px または 28px)から選び、新しい規格を作らないこと。**
  - **【重要】この変更は round-29.md の積み残し「選択中カードの見出しが `margin-block: auto` の副作用でパネル縦中央に浮いている(上端固定にするか要ユーザー判断)」を解決するものとして扱う。** 「最上部」というユーザーの言葉に従い、**このタイトル領域はパネル上端に固定する**(現在の上192pxの余白を無くす)。**29-R1 の中央寄せをこの範囲で撤回する。**

- **31-R2** > 「急所も攻撃側の設定に移動」
  現在最上部(y=288.6、見出し直下)にある「急所」チップを、**攻撃側 `.damage-detail-group` の中**へ移す。**28-R1 の「急所を最上部へ」を撤回する。**

- **31-R3** > 「ランク・状態異常・テラスタルは横並びに配置」
  攻撃側・防御側それぞれの `.damage-detail-group`(現在 h=92.6px で**縦積み**)の中で、**ランク / 状態異常 / テラスタル を横並び**にする。
  - **パネル幅は 360px(内側 327px)しかないので、3つを横に並べて省略・はみ出し・折り返しが起きないことを実測すること。** 入らない場合は**幅を広げるのではなく**、ラベルの省略ではなく配置(2段に分けるなど)で解決し、**その判断と実測値を報告すること**(公式用語の短縮でしのぐのは禁止 → 28で3件が差し戻された経緯がある)。
  - 攻撃側にある「じゅうでん」は攻撃側だけの項目なので、横並びの4つ目として扱うか別行にするかは実装者の判断でよい。**判断理由を報告すること。**

- **31-R4** > 「リフレクター・ひかりのかべ -> 壁　に表記変更」
  「リフレクター・ひかりのかべ」→「**壁**」。**これは 28-R6 で「相手の壁」→「リフレクター・ひかりのかべ」に戻した判断を、ユーザー自身が撤回するもの**(→ round-28.md)。ラベルが短くなるので、31-R3 の横並びに使える幅が増える。
