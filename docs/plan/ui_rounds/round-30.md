### 優先度A(必ず直す)

- **A-1 空き枠の「＋ この枠に入れる」が、押した枠に入るという約束を守っていない**(指摘者: UX)
  【問題】4/6のチームは4番と6番が同時に空く。6番の「＋ この枠に入れる」を押しても実装は `searchInput.focus()` + `scrollIntoView()` しかしない(`src/pages/team/[id].astro:716-719`)。その後に選択バーで個体をクリックすると必ず `firstEmptySlot()`(`:631-636`)が返す**最小番号(4番)**に入る(`:897-904`)。`aria-label` も `${slot}番目の枠にポケモンを入れる`(`:706`)と枠を特定すると明言しており、実態と食い違う。
  【提案】選択ルール(常に最小番号)は**受け入れ基準4で確定済みなので変えない**。表示側を実態に合わせる: **空き枠のうち番号が最小の1枠だけ**「＋ この枠に入れる」を残し、それ以外の空き枠は「選択すると若い番号から埋まります」の趣旨の非アクション文言にする。`aria-label` も同じ意味に揃える。

- **A-2 チーム名を打ち替えるとトップバーと入力欄が食い違ったまま残る**(指摘者: UX)【実バグ】
  【問題】トップバーは SSR 時点の `pageTitle`(`:34-46`)で固定され、`#team-name` の `input` イベントで追随する処理が**存在しない**(`.app-topbar-title` への参照が `team/[id].astro` に0件。Coordinatorがgrepで確認)。`/box/[id]` は同じ構造に対し `updateHeaderIdentity()`(`src/pages/box/[id].astro:4239-4257`)で追随させている。結果、リロードするまで画面上部と入力欄に**別々の名前が同時に表示される**。
  【提案】`box/[id].astro:4239-4257` と同じ手法(`document.querySelector<HTMLElement>(".app-topbar-title")` をキャッシュし、`input` イベントで `textContent` を更新。空なら「無題のチーム」)を移植する。**`AppLayout.astro` は編集禁止**(全ページ共通)。

- **A-3 「編成済み」(正常)と「種族が重複」(禁止)が同じ危険色・同じ書式で、選択バー全行が赤くなる**(指摘者: UX + UI)
  【問題】`.select-row-reason` は4種類の理由をすべて `color: var(--color-danger-strong)` + `font-weight: 700` の単一クラスで出す(`:390-394`)。4/6のスクショでは選択バー4行**すべて**が赤字「編成済み」になり、初見で「エラーが起きている」と誤読する。しかも `--color-danger-strong` は自動保存失敗の表示にも使われる色(`:976-980`)で、**正常状態がエラーと同じ色語彙を共有している**。
  さらに `.select-row-reason` と `.select-row-species` は **`font-size: 0.74rem`(=11.84px)で12px下限を割っている**(`:383-391`)。ラウンド20 G3 で `0.64em` を `0.75rem` に是正した前例があるのに、新規ページで同型が再発している。
  【提案】(a) `already-in-team`(「編成済み」)だけ `--color-text-muted` の中立トーンに分け、禁止3種(6体編成済み / 種族が重複 / 持ち物が重複)だけ現状の赤を残す。**実質3値(選べる / もう入っている / 禁止)**であることを色で伝える。(b) 両クラスとも `0.75rem` に引き上げる。新色は作らない。

- **A-4 空き枠を示す罫線がダークテーマでほぼ知覚できない**(指摘者: UI)
  【問題】`/team` の空きサムネ `.card-team-thumb.is-empty`(`src/pages/team/index.astro:285-288`)と `/team/[id]` の `.slot-empty-number`(`:423-434`)は `1px solid var(--color-border)` 一本だけで「空き」を表現している。**ダークで約1.18:1**(実測: `#2d313d` on `#22252f`)。ライトも計算上 約1.19:1 で、背景が明るいぶん辛うじて見えているだけ。**「値がある/ない」を線1本で伝える箇所にこのトークンは使えない。**
  【提案】この2箇所**に限り**罫線色を `--color-text-muted`(ライト `#5b6472` / ダーク `#9aa1b0`、既にAA適合済みの補助色)に転用する。あわせて `.card-team-thumb.is-empty` の線幅を `.add-card-tile` と同じ 2px に揃える。**`--color-border` を使っている他の「弱くてよい罫線」(通常カードの外枠など)まで一緒に強めないこと。** 修正後はライト/ダーク両方で `--scale 2` 以上のクロップを撮って確認する。

- **A-5 同じ6枠リストの中で、埋まった枠と空き枠が「別部品」になっている**(指摘者: UI)
  【問題】番号は埋まり枠が `.slot-number`(プレーンテキスト・幅2.2rem・**カード左端 x=649**)、空き枠が `.slot-empty-number`(円形+1px枠線・32×32・**カード中央 x=1091.1**)。1〜6の通し番号という同じ役割の部品が、状態によって意匠も位置も変わり、リストとして番号を目で追えない。
  加えて **`data-filled` は属性としてセットされているだけで、CSSの出し分けが一切ない**(`:833-841` で `dataset.filled` を設定しているが、`[data-filled]` を使うセレクタは0件。Coordinatorが実測でも背景・罫線が両状態で同一であることを確認済み)。つまり2状態の区別は「中身の有無」と「番号の位置ズレ」という**実装上の副産物**だけに依存している。
  【提案】(a) `.slot-empty-cta` の `justify-content: center` をやめ、埋まり枠と同じ「左端に番号列 → 続けてラベル」の横並びに統一し、**番号のx座標を両状態で揃える**。(b) 番号の意匠もどちらか一方に統一する(円形バッジに揃えるか、プレーンテキストに揃えるか)。(c) 空き状態は `data-filled="false"` に `border-style: dashed` を与えて明示する(A-4の罫線色修正とセットで行う。`/team` 一覧が既に「空き=破線」の文法を採用しているので、そちらに揃える)。

- **A-6 「テラスタイプ未設定」「技0件」が行ごと消え、対戦に出せない未完成状態が「情報が少ないカード」にしか見えない**(指摘者: プレイヤー視点)
  【問題】`:762-775` は `tera_type` が空なら行を作らず、`:792-803` は `move_names.length > 0` のときしか技行を作らない。スクショのディンルーは技0件・テラス未設定、フシギバナ(キョダイ)はテラス未設定だが、画面上は何の痕跡も残らない。
  **「持ち物なし」は合法な対戦状態だが、「テラスタイプ未設定」はゲーム上存在しない。** jpoke 自身も未指定時に `self.tera_type = tera_type or self.base_types[0]` で**第1タイプへ静かにフォールバックする**(出典: `vendor/jpoke/src/jpoke/model/pokemon.py:89`)。ディンルー(あく/じめん)は黙って「テラスあく」、フシギバナ(くさ/どく)は「テラスくさ」として計算される。**ユーザーの意図と無関係に確定する値が、画面では「まだ表示されていないだけ」に見える。**
  これは**「特性なし」が9ラウンド誰にも指摘されず放置され 26-L1 でようやく直された前例と同型**の見落としである。
  【提案】テラス行・技行が空のときも行を消さず、既存のフォールバック語彙(`:616` の `displayName` と同じ「未設定」)に揃えて明示テキストを残す。持ち物は**合法な空**なので同じ扱いにしない(「持ち物なし」は行を出さないままでよい)。強調が要る場合は既存の `--color-danger-strong` を流用し新色は作らない。

- **A-7 「テラス: フェアリー」は公式用語の短縮で、埋める余地があるのに埋めていない**(指摘者: プレイヤー視点)
  【問題】`:772` が `テラス: ${teraType}` を直書き。「テラス」は「テラスタル」(発動)とも「テラスタイプ」(個体に固定された型)とも取れる口語短縮。**ラウンド28で 23-R3 の「テラスタル→テラス」短縮が撤回され公式用語に戻された前例がある**(→ round-28.md)。レビュアーが該当行をクロップして実測し、「タイプ」3文字(約45px)を足しても折り返しは起きないことを確認済み。
  【提案】`テラス: ` → `テラスタイプ: ` に変更する。

- **A-8 特性が既にSSRで届いているのに枠カードに出ていない**(指摘者: プレイヤー視点)
  【問題】`src/lib/team.ts` の `TEAM_MEMBER_SELECT`(:79-84)は `nature` `ability_name` `level` を含む列を既にSELECTしており、`getTeam()` の結果は `initialTeamJson` としてSSR時点でHTMLに埋め込まれている(`team/[id].astro:39-42`)。ところが**クライアント側の型 `OwnedPokemonRecord`(`:553-560`)が `nickname / species_name / item_name / tera_type / move_names` しか宣言しておらず**、実行時に届いている `ability_name` が一切読まれていない。**新規フェッチも新規計算も不要**。
  「この6体で構成として成立しているか」の判断に特性は軽視できない(同一特性の重複、天候・場コントロールの担い手)。現状は1体ずつ「個体を編集」を開かないと分からない。
  なお `/box` の一覧カードで性格名・特性の常時表示が一度撤回されているが(`src/pages/box/index.astro:11-18`)、その理由は「210px前後の正方形に収まらない」という**空間制約固有の判断**で、幅1080pxの横長カードには当てはまらない。**撤回の再提起ではなく別画面の別判断として扱う。**
  【提案】`.slot-meta-row` に「特性: ◯◯」を追加する。アイコンは付けない(特性の画像素材は他画面にも無い)。

- **A-9 一覧カードから「このチームが何のための構成か」が読めない**(指摘者: UX + UI)
  【問題】(a) メモがカードに出ていない(`renderCard()` `src/pages/team/index.astro:483-548` に `memo` 参照なし)。`memo` は `GET /api/teams` のレスポンスに既に含まれており追加のAPI呼び出しは不要。(b) 見出しが11文字で省略されるうえ **`title` 属性が無く(`:507-510`)、省略部分をホバーで読む手段すらない**。(c) 見出し幅155pxの真因は、**`opacity: 0; pointer-events: none` でホバー時しか見えない削除ボタン `.card-team-delete`(`:251-262`)のために `.card-team-header` が常時 `padding-right: 2rem`(32px)を予約している**こと(`:200-206`)＋体数バッジ約35px。「複数の構成案を並べて見比べる」という R-12 の目的に対し、名前が読めず中身も分からないなら結局1件ずつ開くことになる。
  【提案】(a) `nameEl.title = name` を追加。(b) メモを1行(省略表示)でカードに追加。(c) 体数バッジをヘッダから外しサムネ行の直上か右肩へ移す。**レビュアー試算では見出し幅が約195〜200pxまで回復し、17px/文字換算で11〜12文字まで省略なしで収まる**(「レギュレーションH 本命」がちょうど入る水準)。削除ボタン用の32px予約は実測して詰められるなら詰める。

### 優先度B(直せるとよい)

- **B-1 選択バー下端の657pxの空白**(指摘者: UI)。`.team-select-list-wrap`(`:140-151`)は `flex: 1 1 auto; overflow-y: auto` で、中身が4件だと上端に固まる。**29-R1 で右パネルに対して行った対処と全く同型の構造。** 同じ手法(内側ラッパーに `margin-block: auto`。中身がパネルより短い間だけ上下中央へ寄り、個体が多いユーザーでは自然に上端起点のスクロールへ戻る)を適用する。**ただし round-29.md の積み残しで「`margin-block: auto` の副作用で選択中カードの見出しがパネル縦中央に浮いている」という未解決の課題が挙がっているので、同じ副作用が出ないかを実測してから採用すること。**
- **B-2 「枠から外す」が「個体を編集」と同一書式で隣接**(指摘者: UX)。`btn-ghost` のみで色も書式も同じ(`:805-822` / CSS `:527-540`)。クリック位置がわずかにズレると**確認なしで即座に自動保存つきで外れる**(一覧のチーム削除には `window.confirm()` があるのと対照的 → `team/index.astro:572-573`)。**確認ダイアログの追加は操作頻度から見て過剰なので採らない。** 既存の `--color-danger-strong` を「枠から外す」の文字色にだけ当て、遷移(安全)と破壊を視覚的に分ける。
- **B-3 一覧カードのミニサムネに `title` が無い**(指摘者: UX)。`alt=""` のみ(`:529-541`)で、34.5pxの絵だけでは似た配色の種族を見分けにくい。`img.title = 表示名` を足す(レイアウト不変)。
- **B-4 「個体を編集」で `/box/<id>` へ飛ぶと、そのページの「← 戻る」は常に `/box` 固定**(指摘者: UX)。`box/[id].astro:98` の `backHref="/box"`。チーム編集へは画面上の導線で戻れない。`?from=/team/<teamId>` を付けて `box/[id].astro` 側で `backHref` を切り替える最小変更。**ただし `box/[id].astro` は担当ファイルが増えるので、このラウンドでは着手しない(次ラウンドの候補として記録)。**
- **B-5 性格・実数値の見せ方**(指摘者: プレイヤー視点)。`/box` は「性格名だけの表示」を一度撤回し「実数値6値(性格由来の↑↓付き)」を採用している(`box/index.astro:11-18`)。`/team` に性格関連を足すなら生の性格名に逆戻りせず、素早さ実数値のような「効果が一目で分かる」形を優先する。算出は `src/lib/stats.ts`(ラウンド18で統合済み)の再利用が前提でA-8より重いためB。

### 優先度C(好みの範囲・要判断)

- **C-1 一覧カードの比率**(指摘者: UI)。実装 257.3×128px(約2:1)に対しワイヤーフレーム `docs/ui_proposal/チーム.png` は約228×200px(1.14:1)相当。列数上限を足すだけでは高さが変わらず、809.7pxの空白も埋まらない。サムネ行を3×2の2段組にして各セルを大きくする等、**レイアウトの作り直しに近い規模**なので着手はユーザー判断。
- **C-2 チーム名 input の体裁**(指摘者: UI)。24px・幅1080px・白背景+1px枠で「見出しなのか入力欄なのか」が宙ぶらりん。0/6のスクショでは薄いplaceholderが1080pxの白い箱にぽつんと置かれ、装飾の重みに対し中身が空虚。枠線を `transparent` にして `:focus` 時のみ出すか、見出しらしい太字に寄せるか。実害は小さい。
- **C-3 自動保存の可視化ポリシーが `/box/[id]` と割れている**(指摘者: UX)。`/box/[id]` はラウンド11の判断で定常テキストを常時非表示にし失敗時のみ見せる(`box/[id].astro:171-174`)。`/team/[id]` はこの打ち消しCSSが無く「編集中... / 保存中... / 保存済み」が常時可視(`:952-998`)。**文言は一致しており矛盾はないが「見せるか隠すか」の方針が2画面で割れている。** クリック→自動保存が連続するこのページでは常時可視が機能している面もあるため、**ユーザー判断待ちとして記録する。**
- **C-4 メガシンカ種族 + 非対応の持ち物という矛盾がノーヒント**(指摘者: プレイヤー視点)。`resolveMegaStoneItem` は**持ち物が空のときだけ**メガストーンを設定する(`box/[id].astro:3693-3701` / `4356-4368` の `if (itemInput.value.trim() !== "") return;`)。スクショの枠3はメガリザードンX + こだわりハチマキで、`mega-stones.json` 実測の対応石「リザードナイトX」と一致しない。実際のゲームでは**メガシンカできず通常のリザードンのまま**で、カードが示す姿では試合に出せない。照合ロジックの追加は新規バリデーションに近く機能追加の制約に触れるため**今回は変更提案せず記録のみ**(`loadMegaStoneMap()` が既に `box/[id].astro` にあるため実装コスト自体は小さい旨を申し送る)。
