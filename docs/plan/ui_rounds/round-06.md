# UI改善ラウンド 06

[← 索引](../ui_plan.md)

## ラウンド6の計画(2026-07-26 密度の回復)

### 背景と判断
ラウンド5で「技列の空きスペースが目立つ」というユーザー指示に応え、相手ビルドを上段全幅・技列を下段に置く2段組へ作り直した。空きは解消したが、**カード1枚が 303px → 395〜446px に増え、1画面に2枚強しか入らなくなった**(ラウンド3では3枚が1080px内)。「複数体を並べて同時に見る」がこの画面の目的なので後退である。

さらに実測すると、**空きスペースは消えたのではなく移動している**。技列が1つだけのカードでは、下段の「＋」の右側に大きな余白が残る(上段が全幅になったぶん、下段の空白が横方向に伸びた)。

**判断: 横並び構成には戻さない**(戻すと元の空きスペース問題が再発する)。代わりに**上段(相手ビルド)を横方向に詰めて高さを削り**、下段の余白も同時に解消する。密度と余白の両方を解ける方向であり、ユーザー指示のどちらとも矛盾しない。

### やること
1. **上段を1〜2行に圧縮する。** 現在は「相手名+アイコン」「特性/持ち物/テラス(3列)」「努力値/実数値グリッド(2行)」「累計結果チップ」が縦に積まれている。上段は全幅780px近くあるので、**特性/持ち物/テラスを努力値・実数値グリッドと同じ行に横並びで載せる**等で行数を減らす。
2. **下段の余白を使う。** 技列が少ないときに「＋」の右へ余白が伸びる問題を解消する。技列を余白いっぱいに広げる、または上段の要素を下段の空きへ回すなど。
3. **目標: カード1枚 300px以下、3枚が1080px以内。** 実測して報告すること。
4. **フォントサイズを下げて高さを稼がないこと。** ラウンド3の教訓(真因は `min-height` の取りこぼしであってタイポグラフィではなかった)を踏襲する。まず高さの内訳を計算で分解してから削る。

### 壊してはいけないもの(ラウンド5で入れたばかり)
右サイドバーの3カラム構成と選択状態 / 天候・フィールドのアイコン選択 / 壁の単一トグルと物理特殊の自動判定 / 能力ランクの攻守1つずつと後方互換 / ▲▼による性格切替 / 残りポイント表示 / 結果チップの主役化(`確N` を先頭に太字) / タイプアイコンの円形画像 / placeholder方式 / 技列6個での横スクロール無し。

> **この計画は、この形では実行されなかった。** 計画策定後、ユーザーから `docs/ui_proposal/ダメージ計算カード.png`(⚙ボタン廃止・技列縦積み・各技列にON表示、を反映した更新版)が示され、密度回復の手段そのものが「上段(相手ビルドの箱)の圧縮」ではなく「対話設計の作り直し」に変わった。実際に行われた変更はコード上「ラウンド6ユーザー指示」「ラウンド7ユーザー指示(方針転換)」として記録されており、内容は次節「ラウンド6〜7の実施結果」を参照。結果として**カードの高さは相手ビルド302px/技列313pxまで縮み、この計画が掲げた「カード1枚300px以下・3枚が1080px以内」という目標はほぼ達成された**(技列側が313pxで僅かに超過)。達成手段(技列の縦積み・カード全体設定の廃止による技列側の情報量減少)は、この計画時点で想定していた「上段を1〜2行に圧縮する」とは異なる。
