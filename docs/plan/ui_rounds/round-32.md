## 要件(ユーザーの言葉を引用したうえで具体化する)

### `/box`(ボックス一覧)— 担当ファイル `src/pages/box/index.astro`

- **32-B1** > 「ステータスをカードから削除止し、カードを小型化する」(原文ママ。「削除し」の誤字と解釈する)
  `.card-stat-grid`(239.34×32.52)を**カードから消す**。**DOMは残してCSSで見せない方針**(→ `pitfalls.md`「要素を『消す』指示が来ても、DOMは残してCSSで見せない」)。
  消したぶんカードを**小型化する**。**`.card-pokemon` の正方形は維持すること**(グリッドの行が揃わなくなる。257.34px という値自体は今回に限り変更してよいが、**縦横が等しいこと**は守る)。**縮小後の1画面あたりの表示体数を実測して報告すること**(密度は「1画面に何個入るか」で測る → `pitfalls.md`)。

- **32-B2** > 「アイテムアイコンをポケモンアイコンの右側(テラスタル画像の上)に配置」
  `.card-item-badge`(18px、現在は `.card-item-row` の中)を、**公式絵の領域(`.card-art`)の右側**へ移す。**同じ列にテラスバッジ(`.card-tera-badge`)を置き、アイテムアイコンがその上**になるように縦に並べる。
  - **持ち物なし / テラスなしの個体で、空のバッジ枠が出ないこと**(→ `pitfalls.md`「`[hidden]` は詳細度で負ける」。この2クラスは**過去に4回同じ事故を起こしている**)。`42ccb527`(持ち物なし・テラスなし)で必ず確認すること。
  - アイコンが公式絵に**重ならない**こと。カード右上の `.card-actions`(お気に入り/削除)とも重ならないこと。

- **32-B3** > 「特性をアイテムの左側に表示」
  カードに**特性名**を出す(現在カード上には無く、`title` 属性にしか入っていない)。`.card-item-row` を **[特性名] [持ち物名]** の2列**左右振り分け**にする(アイコンは 32-B2 で `.card-art` 側へ移るので、この行はテキスト2つになる)。
  - **特性・持ち物のどちらか一方だけ設定されている個体でも列が崩れないこと**(`42ccb527` = 特性あり・持ち物なし で確認)。
  - **文字12px下限**(20-G3)。1行で省略(`text-overflow: ellipsis`)し、折り返さないこと。

- **32-B4** > 「カードのホバー表示にはステータスやメモなど、カード上に表示されていない情報だけ表示する」
  カードの `title` 属性を作り直す。**現在は「とくせい / 持ち物 / わざ」= 32-B2・32-B3 の後はすべてカード上に見えている情報**なので重複している。
  - **新しい `title` の中身**: **実数値(H/A/B/C/D/S)** と **メモ**。どちらも空なら `title` 自体を出さない。
  - `aria-label`(「◯◯ を編集」)は**変えないこと**(スクリーンリーダーの読み上げが壊れる)。

### `/box/[id]` 左サイド — 担当ファイル `src/pages/box/[id].astro`

- **32-L1** > 「上側とヘッダーの間の余白を少し減らし、~~ポケモン画像を少し大きくする~~」
  **🔴 後半は撤回。ユーザーの追加指示「個体編集の左パネルのポケモンアイコンサイズ変更はなし。上側の余白調整は実施」により、画像サイズは 144px のまま変更しない。**
  `.panel-left` の `padding-top: 24px`(パネル上端 64.7 → `.species-icon-box` 88.7)を**少し減らす**。減らした値と、減らした後の `.species-sprite-img` が **144×144 のままである**ことを実測して報告すること。

- **32-L2** > 「タイプ画像はアイテム表示と同じ位置で左揃えし、2タイプ間の距離を少しあける」
  `.type-badge-img` ×2(現在 x=633 / 655、間隔 **2px**)を、**`.item-image` の x=504.6 に左揃え**する(= 左端を揃える)。あわせて**2つのタイプアイコンの間隔を広げる**(2px → 6px 程度)。
  - **単タイプの個体でも位置が変わらないこと**(左揃えなので1つ目の位置は不変になるはず)。**実測値(2つの x と間隔)を報告すること。**

- **32-L3** > 「アイテム画像＋名前表示のサイズを、種族名などと揃える」
  現在 `.item-image` **24px** + 持ち物名 **18px**。**種族名の入力欄(`.field-control` = 15.04px)に揃える。**
  - **これは 31-L2「アイテム画像+文字を大きくする」を、ユーザー自身が部分的に撤回するもの**(→ round-31.md)。31-L2 が守った「画像と文字の比 1〜1.5倍」(28-L3)は引き続き守ること。
  - 画像は**アイコン規格20px**(28-L1〜L6)に戻すのが自然。**文字は12px下限を割らないこと。**
  - **「こだわりハチマキ」で `scrollWidth === clientWidth`(省略なし)を実測して報告すること。**

- **32-L4** > 「技とステータスの間の間隔をさらに広げて、アイテムと技の間のスペースと揃える」
  **実測では既に 16px / 15.92px でほぼ同値**(31-L7 で揃えた)。**にもかかわらずユーザーには不揃いに見えている。** 原因は、持ち物→技が**入力欄の枠と枠の間**なのに対し、技→ステータスは**入力欄の枠と文字ラベル(`.stat-table-header`、`padding-bottom: 5.6px`)の間**で、**視覚的な余白の見え方が違う**こと。
  - **両方を「さらに広げた」うえで、視覚的に等価に見えるようにすること。** 単に数値を合わせるだけでは 31-L7 の再演になる。
  - **報告には (a) 持ち物→技 (b) 技→ステータス の実測値**に加えて、**`--scale 3` の拡大クロップをライト/ダーク両方で撮って目視確認した結果**を書くこと。
  - **技0件の個体(`f7e594b4`)でも間隔が保たれること**を確認する(31-L7 で確認済みの回帰ポイント)。

- **32-L5** > 「ステータスとメモの間の間隔を広げる」
  `.stat-table` の bottom 780.64 と `.memo-input` の y=780.7 で **gap 0.06px = ほぼ密着**している。**広げる。** 32-L4 で決めた間隔と揃えるか、それより広くする(メモは別の情報ブロックなので、同値以上が妥当)。**実測値を報告すること。**

- **32-L6** > 「特性補正の三角形の縁取りの色は、塗りつぶし色と同系色で強調するデザインにする」
  現在 `.stat-nature-btn[aria-pressed="true"]` の `::before` に `drop-shadow` ×4 で **`rgb(31,36,48)`(黒)** の縁取りが付いている(31-L8)。これを**塗りつぶし色と同系色**に変える。
  - 塗り: 上昇 A▲ = `rgb(201,67,44)`(danger系) / 下降 C▼ = `rgb(29,111,209)`(primary系)。
  - **縁取りはその同系のより濃い/深い既存トークンにする。新色は作らないこと**(→ `pitfalls.md`「配色」)。
  - **これは 31-L8 の「黒縁」を撤回するもの。** ただし 31-L8 の要件「非選択の ▲▼ と一目で区別できること」は**引き続き満たすこと**。**ライト/ダーク両方で `--scale 3` の拡大クロップを撮り、目視で確認して報告すること**(ダークで同系色の縁取りが背景に沈まないか)。

  - **天候・フィールドは攻撃側/防御側のどちらにも属さない「場」の設定**なので、**攻撃側/防御側のグループの中に入れないこと。**
  - **DOMの移動になるため、天候・フィールドのボタンのイベントハンドラ・`aria-pressed` の同期・保存経路が壊れていないこと**を確認する(実際にクリックして確認する場合は、**使い捨て個体で行うか、確認後に必ず元の値へ戻すこと** → `pitfalls.md`)。

- **32-R3** > 「横棒は色付けしない」
  29-R2 で攻撃側=`--color-danger-strong` / 防御側=`--color-primary-strong` に色付けした**区切り線(`border-top`)を、無彩色の `--color-border` に戻す**(`src/pages/box/[id].astro:2824-2840` 付近)。
  - **⚠️ 見出しの文字色(赤/青)と形状マーカー `.damage-detail-side-icon` は残すこと。** 29-R2 は「攻撃側/防御側が色でも判別できるように」という WCAG 1.4.1 対応であり、**線の色だけがユーザーの指示対象**。線まで含めて全部無彩色にすると識別性の要件を壊す。
  - **これは 29-R2 の一部を撤回するもの。**

- **32-R4** > 「攻撃側の2段目は、急所,じゅうでんの順に同じグループとして配置」
  攻撃側 `.damage-detail-group`(現在 h=99.92px)の中で、**じゅうでん → 急所 の順に別段になっている**ものを、**「急所 → じゅうでん」の順で同じ1グループ(同じチップ行)**にまとめる。
  - 1段目は現状どおり ランク / 状態異常 / テラスタル(31-R3)。**2段目が「急所, じゅうでん」**になる。
  - **327px幅に2つが省略・はみ出し・折り返しなしで収まることを実測すること。** 収まらない場合も**公式用語を短縮しないこと**(28で3件差し戻された経緯)。
  - 「急所」は 31-R2 で攻撃側に移したもの。**移動先グループが変わるだけで、攻撃側から出さないこと。**

- **32-R5** > 「防御側は、かべをひらがな表記にし、他の揮発状態と同じグループで配置する。」
  (a) 「**壁**」→「**かべ**」(ひらがな)。**これは 31-R4(「リフレクター・ひかりのかべ」→「壁」)をさらに変更するもの。**
  (b) 「かべ」チップを、**`.damage-detail-group.damage-detail-volatile-wrap`(「その他の状態」= のろい/やどりぎのタネ/しおづけ/バインド/アクアリング/ねをはる/タールショット/ちいさくなる/きょけんとつげき)と同じグループ**に入れる。
  - **`title` 属性の説明文(「リフレクター/ひかりのかべを技の分類に応じて自動選択して壁を張る」)は残すこと**(31-R4 で「可視ラベルが短いぶん補足が要る」と判断済み。ラベルがさらに短くなるので必要性は増している)。
  - **チップの並び順の中でどこに置いたか**と、**そのグループが1行に収まるか(327px)**を報告すること。

### 32-U(共通)UI統一感レビュアーの新設 — ユーザー要求

> 「同じUI領域でもフォント・サイズが微妙に統一されていなかったりする。UIの統一感をレビューする専門のsub agentを立ち上げてレビューさせる」

- **32-U1**: **4人目のレビュアーとして「UI統一感レビュアー」(sonnet)を新設する。** 役割は「**同じ意味・同じ格の要素なのに値が微妙に違っている(規格の揺れ)を、実測値の証拠つきで列挙する**」ことに限定する。見た目の好き嫌い・使いやすさは既存3レビュアーの担当。
- **32-U2**: `.claude/skills/ui/references/agent-prompts.md` に**統一感レビュアーのテンプレートを常設**し、`SKILL.md` の役割分担表・Step 2 を「3レビュアー」から「4レビュアー」に改める。**メタアドバイザー(fable)の提案を踏まえて、既存3レビュアーの観点リストから統一感レビュアーへ移す項目・削る項目も同時に決める**(観点の重複を残すと同じ指摘が多重に上がる)。
- **32-U3**: このラウンドで**実際に統一感レビュアーを走らせ**、その指摘を下の「統一感レビューの指摘」節に記録する。**優先度A(同じ行・同じ視線の中で見比べられる揺れ)は 32-B / 32-L / 32-D / 32-R の実装と同じラウンドで直す。**
