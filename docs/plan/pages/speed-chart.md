## このページが答える問い

**「今このレギュレーションで、自分の育成中の個体はどのポケモンより先に動けるのか。あと何を変えれば抜けるのか」**

## 参照した資料(P1で実際に開いたもの)

- `docs/ui_proposal/すばやさ早見表.png` — **構造の正**。2列(実数値 / ポケモン)の縦長テーブル。1つの実数値行に複数の「振り方バッジ + 種族値ラベル + 補正ラベル」グループが入り、各グループの下にポケモンのアイコン+名前+補正の出どころ(特性名/技名)が並ぶ。
- `docs/ui_proposal/すばやさライン早見表 シーズンM-2(シングルバトル)|バトルデータベース チャンピオンズ.html` — 他者サイト例。ラベルの語彙(`最速` / `準速` / `120族 2倍` / `110族 S+2` / `123族 こだわりスカーフ`)はここに合わせる。**ただし母集団の絞り方は真似しない**(向こうは使用率TOP100 + 採用率10%以上。こちらはレギュレーション全件)。
- `docs/ui_proposal/個体編集.png` / `個体編集_全体レイアウト.png` / `個体編集_右サイド.png` — 遷移元。左パネルのステータス表(H/A/B/C/D/S × 種族値・努力値スライダー・実数値)のS行が入口になる。

## ユーザー確定仕様(2026-08-01 `AskUserQuestion`)

1. **独立ページ + 個体連携パラメータ**。`/speed-chart?owned=<個体id>` を作り、`/box/[id]` 左パネルのS行から遷移する。行クリックで `PUT /api/owned-pokemon/:id` を叩いて保存し、右カラムの表示を即時更新する。サイドバー「育成」にも項目を追加し、個体を持たずに素の早見表としても開ける。
2. **補正の範囲は「持ち物 + 特性 + ランク上昇技」**(参考サイト相当)。
3. **振り方は 最速 / 準速 / 無振り の3種**。

## スコープ内

### A. 早見表本体(左〜中央)

- **レギュレーション選択**。`REGULATIONS`(`src/lib/regulations.ts`)から選ぶ。既定値は「`?reg=` → 連携個体の `regulation` → `REGULATIONS` の末尾(最新)」の順に決める。**レギュレーション未指定は許さない**(「所属するポケモン」が定義できないため)。選択を変えたらURLの `?reg=` を `history.replaceState` で書き換える。
- **母集団**: そのレギュレーションで使える**全フォルム**。
  - 基礎: `vendor/jpoke/src/jpoke/data/regulation/pokemon.csv` で当該列が `1` の種族(M-A 213件 / M-B 235件)
  - メガシンカ: `autocomplete/mega-stones.json` の `species` のうち、対応する `item` が `regulation/item.csv` の当該列で `1` のもの(M-A 60件 / M-B 76件)。アプリはメガを独立した `species_name` として扱う(`src/lib/box-id/shared-core.ts` の `resolveMegaStoneItem`)ため、表でもメガは1フォルム=1行グループとして扱う。
  - 合計 **M-A 273フォルム / M-B 311フォルム**(P1で実測)
- **振り方(3種)**。チャンピオンズルール(IV=31固定・努力値0〜32・Lv50固定)で計算する。計算式は `src/lib/stats.ts` の `calcOtherStat` を**そのまま使う**(再実装しない)。
  | ラベル | 努力値S | 性格補正 |
  |---|---|---|
  | 最速 | 32 | 1.1 |
  | 準速 | 32 | 1.0 |
  | 無振り | 0 | 1.0 |
- **補正(すばやさ上昇要素)**。すべて jpoke のソースを唯一の出典とし、**アプリ側にポケモン名・技名・特性名をハードコードしない**。
  | 種別 | 対象 | 倍率/段階 | 表示ラベル |
  |---|---|---|---|
  | 持ち物 | こだわりスカーフ | `floor(S * 6144 / 4096)` | `こだわりスカーフ` |
  | 特性(倍率) | かるわざ / すいすい / すなかき / ゆきかき / ようりょくそ / サーフテール | 2倍 | `2倍` + 特性名 |
  | 特性(倍率) | はやあし / こだいかっせい / クォークチャージ | `floor(S * 6144 / 4096)` | `1.5倍` + 特性名 |
  | 特性(ランク) | かそく(+1) / いかりのこうら(+1) / びびり(+1) / ふくつのこころ(+1) / くだけるよろい(+2) / じょうききかん(+6) | `floor(S * (2+n)/2)` | `S+n` + 特性名 |
  | 技(ランク) | +2: からをやぶる / ギアチェンジ / こうそくいどう / みをけずる / ロックカット<br>+1: アクアステップ / おかたづけ / オーラウイング / オーラぐるま / くさわけ / しょうりのまい / スケイルショット / ソウルビート / ちょうのまい / ニトロチャージ / はいすいのじん / りゅうのまい | `floor(S * (2+n)/2)` | `S+n` + 技名 |
  - **その特性/技を実際に持てるフォルムにだけ**付ける(`detail/pokemon.json` の `abilities` / `learnset` で判定)。
  - **確率発動の追加効果は除外する**(あやしいかぜ / ぎんいろのかぜ / げんしのちから の10%上昇)。
  - 補正は**重ねがけしない**(スカーフ+りゅうのまいのような組み合わせは行にしない)。参考サイトと同じ。
  - 下降補正(スロースタート・くろいてっきゅう・まひ)は**出さない**。
- **行の構成**: 実数値の降順。同じ実数値に該当する組み合わせは1行にまとめ、行の中で「振り方 + 種族値ラベル + 補正ラベル」のグループに分ける(PNGの構造)。P1実測で **M-B: 3,024エントリ → 271の実数値行**。
- **ポケモン画像**: `autocomplete/pokemon.json` の `imageId`(`dexNo` ではない)。`src/lib/sprite-urls.ts` の既存ヘルパーを使う。

### B. 「この個体」カラム(右、PNGに無い追加要件)

`?owned=<id>` があり、かつログイン中の本人の個体であるときだけ表示する。

- **その個体で実現可能なすばやさ実数値**を列挙する。組み合わせは以下の直積(重ねがけあり):
  - 性格: S上昇(1.1) / 無補正(1.0) / S下降(0.9)
  - S努力値: 0〜32 の全33段階
  - 持ち物: 現在の持ち物 / こだわりスカーフ(そのレギュレーションで使えるとき)
  - **特性・技によるランク上昇は含めない**(その個体の「素の」到達可能値のみを扱う。ランク補正は戦闘中の一時的な状態であり、保存対象の育成内容ではないため)
- 表の各実数値行に対し、**「その値ちょうどに到達できる最小コストの組み合わせ」**を右カラムに出す。同じ実数値に複数の組み合わせがあるときは **S努力値が最小 → 性格補正が現在値と同じ → 持ち物が現在値と同じ** の順で1つに決める。
- 現在の個体のすばやさ実数値の行には `← 現在` を出す(クリック不可)。
- **クリックで適用**: `PUT /api/owned-pokemon/:id`(**全項目上書き**契約)で、その組み合わせの `nature` / `evs[5]` / `item_name` を書いた**全項目ペイロード**を送る。成功したら右カラムの `← 現在` を移動し、上部の個体サマリ(種族・性格・持ち物・S実数値)を更新する。
- **努力値合計はブロックしない**。チャンピオンズルールの合計上限66は入力制限を持たない仕様(`.claude/skills/jpoke/references/ruleset.md`)なので、超過する場合は**警告表示のみ**を出して適用は通す。
- 適用後に `/box/<id>` へ戻れる導線(トップバーの `backHref`)を残す。

### C. 遷移元(`/box/[id]` 左パネル)

- ステータス表の**S行の実数値セルの隣**に、早見表へのリンク(アイコンボタン)を1つ追加する。`href="/speed-chart?owned=<id>"`。
- **これ以外の `/box/[id]` の変更は禁止**(左パネルは8,500行のうちの1領域。ボタン1個の追加に留める)。

### D. マスターデータ生成の拡張(`scripts/build-master-data/extract_autocomplete.py`)

DBマイグレーションは**不要**。代わりに以下を追加する。

1. `autocomplete/pokemon.json` の各要素に `regulations: string[]` を追加(`jpoke.data.pokedex.POKEDEX[name].regulations`)。
2. `autocomplete/items.json` の各要素に `regulations: string[]` を追加(`jpoke.data.item.ITEMS[name].regulations`)。
3. **新規** `detail/speed-modifiers.json` を出力する。jpoke のハンドラ関数を `inspect.getsource()` して抽出する(P1で実行して動作確認済み):
   ```json
   {
     "items":     { "こだわりスカーフ": { "kind": "multiplier", "numerator": 6144, "denominator": 4096 } },
     "abilities": { "かるわざ": { "kind": "multiplier", "numerator": 2, "denominator": 1 },
                    "かそく":   { "kind": "rank", "stages": 1 } },
     "moves":     { "ロックカット": { "kind": "rank", "stages": 2 } }
   }
   ```
   - ランク上昇の抽出: `modify_stats(...{"spe": +n})` / `modify_attacker_stats(..., stats={"spe": n})` を正規表現で拾い、`n > 0` かつハンドラのソースに `chance|random|確率` を含まないものだけ採用する。
   - 倍率の抽出: `ON_CALC_SPEED` ハンドラのソースから `apply_fixed_modifier(value, N)` と `value *= N` を拾う。**下降(N < 4096 / 除算)は出力しない**。
   - **抽出結果が空になったら生成を失敗させる**(jpokeの実装変更でサイレントに空の表になるのを防ぐ)。

## P1で判断して決めたこと(ユーザーに聞かなかった論点と根拠)

- **母集団に使用率フィルタを入れない** — 要件2が「指定したレギュレーションに属するポケモンのすばやさを一覧できる」なので全件が正。実測で271行に収まり、絞らなくても読める。
- **補正を重ねがけしない** — 参考サイトも重ねていない。重ねると行数が1桁増え、「どの1手で抜けるか」という表の目的がぼやける。
- **右カラムでランク上昇を扱わない** — ランク補正は戦闘中の一時状態で、`owned_pokemon` に保存できる育成内容(性格・努力値・持ち物)ではない。「クリックしたらステータスやアイテムが更新される」という要件4の文面とも整合する。
- **努力値合計66超をブロックしない** — チャンピオンズルールは入力制限を持たない仕様(メモリ/`ruleset.md`)。既存の `/box/[id]` も超過を許して警告のみ出している。
- **ページ自体に認証を要求しない** — 表の中身は公開マスターデータのみで個人情報を含まない。`?owned=` の解決だけが認証を要する。
