# 描画安定性(揺れ)ダッシュボード

`stabilize` skill(`/stabilize`)の**唯一の状態保存先**。計測したら該当行を更新する。

計測条件は既定で **`--size 390x844 --theme dark --repeat 3`**(モバイル専用方針・ダーク一本化のため)。対象の一覧と probe コマンドは `.claude/skills/stabilize/references/targets.md`。

## 判定基準(2つ。どちらか一方でも外れたら不合格)

| 指標 | 🟢 | 🟡 | 🔴 |
|---|---|---|---|
| フェーズ合計 `totalAll`(中央値) | < 0.01 | 0.01 〜 0.05 | ≥ 0.05 |
| 個別シフトの最大移動量(px) | < 2 | 2 〜 4 | ≥ 4 |

**スコアだけで判定しない。** 小さい要素が起こす揺れは `value` が 0.00 と出るのに目にははっきり見える(例: 技タイプバーが技名を6px押す)。移動量が 4px 以上なら🔴。

## 既知の課題・対応履歴

### 対応済み

- **技タイプ色バーが後から出て技名が3〜6px右へずれる**(2026-09-10、パターンA)。`[hidden] { display: none }` で幅0→3pxになっていたのをやめ、常に幅を占めさせて `background-color: transparent` で未解決を表す。box一覧カード・プレビュー・チームカード・ダメージ計算カード・候補・詳細パネル・上位チームカードの7箇所。**CLSスコアでは 0.00 と出るのに目にははっきり見える**典型例
- **チーム編成の「登録中…」がボタンの中身を丸ごと差し替えて幅を変える**(2026-09-10、パターンB)。文言差し替えを廃止し `disabled` だけにした
- **上位チームカードの技タイプ画像に表示寸法が無く、読み込み完了まで高さが確定しない**(2026-09-10、パターンD)
- **`/box/<id>` の保存状態(`#autosave-status`)をJSが `#mobile-edit-actions` へDOMごと移設していた**(2026-09-10、パターンF)。移設をやめ、最終表示位置にSSRするようにした。CLS 0.17→0.07
- **`/box/<id>` の実数値・残り努力値が空→数値で幅が伸びる**(2026-09-10、パターンC)。桁数ぶんの `min-width` と `tabular-nums` で予約
- **`/box/<id>` 編集パネルの画像が全部SSRで `src` 無し・`display:none` で出ていた**(2026-09-10、パターンC)。立ち絵・タイプバッジ・もちもの・テラスの `<img>` は、クライアントJSが起動して `src` を入れ、さらに画像の `onload` が発火してはじめて箱が出る作りだった。そのため「バッジの枠だけがあって中身が無い」時間帯が生まれ、読み終わった瞬間に `#item-dropdown-placeholder` が **25.6px** 横へ飛んでいた。`PokemonEditPanel.astro` で `MobilePokemonPreview.astro` と同じview modelを使って `src` をSSR出力し、`shared-core.ts` の `applySprite`/`applyTeraImage`/`applyItemImage` を「読み込み中は箱を消す」から「箱は常に確保し、空・失敗のときだけ隠す」方式へ変えた。**本番ビルドでも起きていた本物のシフト。**
  ⚠️ フォールバック(頭文字バッジ・色ボックス)は表示のたびにインラインの `display` を書き込むため、隠すときに `hidden` を立てるだけでは消えない(インライン指定が `[hidden]` に勝つ)。`hideFallback()` で両方戻す。
  ⚠️ `#species-type-badge .type-badge-fallback` は `box-damage-card.css` がID詳細度で `display:none` を当てているので、こちらも `hidden` だけでは出てこない。
- **`/team/<id>` のポケモンカードの実数値18セルを非同期計算の完了後に追加していた**(2026-09-10、パターンC)。セルを先に置き、計算待ちは `visibility: hidden` にした。技一覧が41px上へ動く揺れが消えた

- **`/damage-calc` の固定領域の初期値が実際の描画と 47px ずれていた**(2026-09-10、パターンC)。`.damage-calc-shell` / 相手選択レールは `position: fixed` で、上端を `--damage-calc-content-top`、下端を `--damage-calc-control-bar-height` から決めている。どちらもJS(`control-panel.ts` の `syncContentTop` / `syncControlBarHeight`)が実測値を書き戻すまでのフォールバックが実際とずれていた: 下端の初期値が `0px` なのに実寸は `43px`、上端のフォールバックが `--second-header-height`(52px)なのにこの画面のセカンドヘッダーは内容が折り返して `56.0625px`。合計 47.06px ぶん、JSが走った瞬間に跳ねていた。CSS側の初期値を実測値(320〜768pxのどの幅でも一定)に合わせて解消。**スクリーンショットはバイト単位で同一。**

- **Webフォント `M PLUS Rounded 1c` の差し替えで、ほぼ全ページのテキストが 4.5〜7.2px 横へ動いていた**(2026-09-10 の総点検で実測。当時の最大の課題)。
  観測箇所: `/box/<id>` `.stat-row-real` 3.9〜5.8px / `/box/<id>?tab=damage` `.damage-result-detail` 6.9px /
  `/data/speed-chart` `.speed-chart-spread-badge` 6.3px / `/team/<id>?tab=data` `.card-team-name` 6.8px /
  `/data` `/box/data` `.trend-rank-rate` 5.8〜7.2px / `/box/ranked` 6.0px / `/box/matchup` 4.3px。
  `npm run probe -- --block fonts.gstatic.com` でフォントを落とすとこれらのシフトが1件残らず消えることから、原因をWebフォントと断定した。
  dx だけが動く横ズレで、遅れて届くデータが無い静的なページでも起きる(= 内容ではなく文字の送り幅が変わっている)。
  `ch` 指定の予約幅(`.stat-row-real` の `min-width: 3ch`)もフォントの文字送りで決まるため一緒に変わる。

  **解決までに3段階かかっている。前半2つは単体では効かなかったので、経緯を残す。**

  1. **自前配信へ移行(628b736)— 早くなるだけで消えなかった。**
     Google Fonts はCSS→woff2で2往復かかり、フォントが届くのは必ず初回描画のあと。同一オリジンにして
     woff2 の取得開始は 330ms→94ms、完了が初回描画(124ms)とほぼ同時になったが、
     **シフトは 446.7ms→322.1ms と早まるだけで移動量は 6.33px のまま。**
     日本語フォントは unicode-range で126サブセット×3ウェイトに分割されており、初回描画のあとに
     必要になったサブセットが遅れて届くたびに字幅が変わるため。
  2. **フォールバック側の `size-adjust` 調整 — 不可と判断。**
     Windows実測で必要なスケールが数字1.150 / ラテン0.994 / かな1.000とバラバラで、単一の値では合わせられない。
     iOS(SF/ヒラギノ)の比率はこの開発機からは測定できず、片方の環境に合わせた値は他方を悪化させる。
  3. **コアサブセットの生成 + preload(今回)— これで解決。**
     `scripts/fonts/build-core-subset.mjs` が `public/master-data/` の全JSONと `src/` の全ソースから
     文字を集め(異なり2,253字)、full TTF を1ウェイト1ファイルにサブセットして
     `public/fonts/m-plus-rounded-1c-core/` へ出力する。`AppLayout.astro` でこの3ファイルを preload する。
     **本番ビルド実測で `/data` `/data/speed-chart` `/damage-calc` いずれも totalAll 0 / シフト0件。**
     `document.fonts` を見ると読み込まれるのはコア3ファイルだけで、分割版は1つも引かれていない。

  **二段構えにしてある。** コア側の `@font-face` には実際の文字集合から作った `unicode-range`(825レンジ)を
  明示し、`global.css` で分割版の**後**に `@import` して優先させている。コアに入っていない文字
  (ユーザーが自由入力するメモの稀な漢字など)だけが従来の126分割サブセットへ落ちる。
  実測でも、コア外の漢字を後からDOMに足すと分割サブセットが4件だけ追加取得された。

  **転送量のトレードオフ。** コアは3ウェイト合計 651KB(400: 216KB / 500: 219KB / 700: 232KB、各1,781グリフ)。
  従来の分割方式が1ページあたりに引いていたのは `/data` 161KB・`/data/speed-chart` 268KB・`/damage-calc` 275KB
  だったので、**初回表示は 380〜490KB ぶん重くなる**。ただしコアは全ページ共通で、`/fonts/*` を
  `immutable` 1年でキャッシュしているため2ページ目以降のフォント転送は0になる。分割方式はページを
  移るたびに新しいサブセットを引き続けるので、サイト全体を回れば逆転する。揺れを消すことを優先して受け入れた。
  ファイル名に内容ハッシュを入れてあるので、再生成しても `immutable` の古いキャッシュが配られることはない。

  **`font-display: optional` は採らなかった。** 揺れは0になるが、初回訪問では丸ゴシックが当たらず
  素のゴシックで表示される(スクリーンショットで確認済み。フォント到達が約130msで optional の
  ブロック期間に間に合わないため)。コアサブセットなら初回から丸ゴシックのまま揺れも消える。

  **iOS標準の「ヒラギノ丸ゴ ProN」をフォールバックに使う案は不採用。** iOSではWebフォント自体が
  不要になり0バイトで揺れも消えるが、W4の1ウェイトしか無いため medium/semibold/bold の3段階が
  合成太字1段階に潰れる。OS依存の見た目差を避ける方針で見送った。

### 対応できない・許容している揺れ

- **`npm run dev` で残る揺れは、ほぼ全部 Vite の dev client が作っている偽物**(2026-09-10に特定)。
  該当: `/box/<id>` の `.edit-layout-training` ±52.6px(0.07)、`/box/new` の ±28.2px(0.04)、
  `/team/<id>` の `.panel-content` 8px(0.02)。

  根拠:
  1. `--no-js` で開くと**どれも CLS 0**
  2. `--rect` の最終レイアウトが **JS有無で完全に一致**(`.pokemon-preview` y=41 h=177 等)
  3. `--watch ".pokemon-preview"` を見ても、シフトの時刻に**プレビュー内のDOM変更が1件も無い**
  4. `--watch "head"` を見ると、シフトの直前に **`<style>` の中身が一斉に入れ替わっている**
     (`/box/<id>`: 397〜400ms に24件 → シフト443ms / `/team/<id>`: 771〜774ms に17件 → シフト799ms)

  Astro dev はCSSを `<style>` でHTMLに埋め込むが、JS起動後に Vite の dev client がその中身を
  入れ替えるため一度リフローする。**本番ビルドではCSSは `<link>` で配られるので起きない。**

  ⚠️ この切り分けを飛ばしてサブエージェントに「プレビューの作り直しを止めろ」と投げたが、
  当然ながらCLSは 0.09→0.09 で変わらなかった(1ラウンド分の無駄)。**dev で測った揺れは
  まず `--no-js` と `--watch "head"` で偽物を除いてから原因を追うこと。**

## 計測時の注意

- **1回目の計測は dev server の初回コンパイルで極端に悪く出る。** 必ず `--repeat 3` の中央値で判定する
- **OP.GG使用率は dev では空になる**(→ `project_opgg_usage_dev_server_stall`)。使用率が絡む揺れは `npm run preview` で測る
- **dev server は認証をバイパスする。** 未ログイン/ゲストの揺れは `npm run preview` か `--guest` で測る
- **`--click` 等の操作オプションは自動保存を誘発して実データを壊しうる。** `.claude/skills/ui/references/pitfalls.md` を読んでから使う
