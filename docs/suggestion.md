# サジェスト候補の選定仕様

この文書は、画面に出る「候補」「人気」「おすすめ」「類似構築」が**どう選ばれ、どの順になるか**を定義する。データ取得方法や実装基盤の説明は扱わない。

変更依頼では、各節の「候補プール」「順位」「除外・フォールバック」のどれを変えるかを指定する。

## 用語と共通ルール

- **個人ボックス**: ユーザーが登録した個体。匿名集計を拒否中の個体は集計に入れない。
- **上位チーム**: 収録済みの `ranked_team_members`。人気育成の集計では個人ボックスと同じく1個体を1票として扱う。上位順位による加重はしない。
- **全体**: 上位チームは全シーズン、個人ボックスはレギュレーションに紐付けずに混ぜた集計。現在の育成欄の人気順は、この全体集計を使う。
- **サンプル不足**: 集計単位の母数が5未満なら候補を作らない。条件を満たさないときは、空の候補枠を表示しない。

## 1. `/box/[id]` — 育成項目の人気順

### 対象と候補プール

対象は性格、持ち物、テラスタイプ、特性、技である。各項目は、同じ種族の個人ボックスと上位チームから値を数え、採用数の多い順に候補化する。同数なら名前順とする。

- 性格・持ち物・テラスタイプ・特性: 1個体につき1票。
- 技: 1個体が覚えている各技に1票。1個体の4技はそれぞれ独立に数える。
- 表示する上限: 性格・持ち物・テラスタイプ・特性は5件、技は20件。
- 各候補に表示する採用率は `その値の票数 / その項目を持つ同種族の個体数`。

### 型を考慮する技候補

技だけは、種族・持ち物・役割から求めた現在の型に一致する候補を優先する。型候補も個人ボックスと上位チームを同じ重みで集計する。候補を探す順序は次の通り。

1. 同じ型の全体
2. 同じ種族の全体

型候補も、各型の母数が5未満なら存在しないものとして次へ進む。

### 実際の並び

- 性格・テラスタイプは、上記の集計順位で選択肢を並べる。
- 持ち物・特性・技は、OP.GG の使用率が利用できるときはその順位を最優先する。OP.GG に対象種族の値がないときだけ、上記の集計順位を使う。
- 集計または OP.GG にない値は、元の候補順を維持して人気候補の後ろに置く。
- 技の元の候補順は「その種族が覚える技を優先」。入力文字列と前方一致する候補、次に部分一致する候補を前に寄せる。同じ区分内の順序は維持する。

## 2. `/box/[id]` — ダメージ計算の入力候補

ダメージ計算に追加する相手・技・特性・持ち物の初期候補は、育成欄とは別に次の規則で選ぶ。

### 攻撃側の技

自分が攻撃する行では、変化技を除く。

1. 現在の個体が設定している4つの技を、入力欄の順に並べる。
2. 同じ技を重複させず、その後ろに種族の習得技を足す。
3. 新しい技列を増やすと、1列目は1位、2列目は2位……を初期値にする。該当順位がなければ1位を使う。

### 防御側の技

相手が攻撃する行では、変化技を除く。同じ種族の全体技採用率順に並べる。採用率がない技と同率の技は、種族の習得技としての元の順序を保つ。新しい技列の初期値は攻撃側と同様に1位、2位……とする。

### 相手の特性・持ち物

- 特性: その種族が取り得る特性だけを候補にする。既存値が候補内なら維持する。既存値がないときは、人気特性の最上位を選び、人気値がなければ候補の先頭を選ぶ。
- 持ち物: 全持ち物を候補に残したまま、同種族の持ち物採用率順へ並べる。
- メガシンカ種族は対応するメガストーンを自動で選び、持ち物を変更できない。

## 3. `/box/[id]` — 「人気の計算」

表示対象は、現在の個体でよく登録されたダメージ計算である。1件は「攻撃/防御の向き・相手種族・技・相手の代表的な育成」から成る。

### 集計と順位

1. 個体ごとに、同じ「向き・相手種族・技」は1票にまとめる。
2. 現在の型に一致する計算を先に候補にする。型の候補がなければ、同じ種族の計算を候補にする。
3. 候補は票数の多い順、同数なら相手種族名・技名順にする。集計時は最大12件を残す。
4. 相手の性格・特性・持ち物・テラスタイプ・努力値は、その候補に含まれる記録の最頻値を代表値にする。

### 表示時の除外

現在すでに追加されている「向き・相手種族・技」と同じ候補は除外し、残りの先頭6件だけを表示する。候補を押して追加すると、その候補はただちに表示対象から外れる。

## 4. `/box/ranked` — 個体に近い上位チーム

選択中の個体と同じ種族を含む、最新シーズンの上位チームを候補にする。チーム内の同種族メンバーとの育成一致度を次で計算する。

| 一致条件 | 加点 |
| --- | ---: |
| 特性が一致 | 1 |
| 持ち物が一致 | 1 |
| 技が一致 | 1技につき 0.25 |

候補は一致度の降順、同点なら上位チーム順位の昇順で並べる。一致度が1点以上の候補が一つでもあればそれだけを表示する。なければ、同じ種族を含む全候補を上位チーム順位順で表示する。

## 5. `/box/matchup` とチームの「相性」— 比較相手候補

比較する相手種族は、全体使用数の多い順に32種選ぶ。全体使用数は上位チームの実チーム数と、アプリ内で編成済みの個体数を6で割ったチーム相当数を合算したものを基準にする。

相手が使う技は、その種族の技採用率から次を満たす技をすべて選ぶ。

- 採用率が20%以上
- 攻撃技（変化技は除外）
- 同名技は1本に統合

攻撃面は自分側の設定済み攻撃技、耐久面は上記の相手技で最大ダメージを計算する。複数メンバーのチームでは各メンバーのダメージ割合の平均を使う。攻撃・耐久のうち不利な方を、その相手への不利度として色付けに使う。候補種族の順番自体は使用数順から変えない。

## 6. `/team/[id]` — 「おすすめポケモン」

現在編成に入っている種族と一緒に採用されやすい種族を選び、その種族で最も合う型を付けて提示する。

### 種族の候補と順位

候補プールは上位チームとアプリ内で編成済みのチームの合算である。各編成中の種族を起点に、候補種族ごとに次の値を計算して合計する。

`log(実際の共起数 / 独立なら期待される共起数) × 共起数 / (共起数 + 5)`

これは、たまたま採用数が多いだけの種族よりも、起点種族と組まれる割合が特に高い種族を上げるための値である。候補種族は合計値の降順、同点なら候補種族の採用数が多い順にする。説明文には、最も結びつきが強かった起点種族を表示する。

共起データが得られない場合、またはチームが空の場合は、全体採用率順に切り替える。

### 除外と表示数

- 現在の編成と同じ図鑑番号の種族は除外する。フォルム違い・メガシンカ違いも重複として扱う。
- 上位12種族まで型選定の対象にし、その先頭から最大6種族を返す。
- メガシンカ種族は「メガを含める」がオフなら画面上で除外する。モバイルのアイコンも先頭6件まで同じ順序で出す。

### 型の選び方

候補種族の型は、全体での採用率、現在編成の種族と同居したときの採用率、現在編成の型と同居したときの採用率を混ぜて順位付けする。後者2つは標本が少ないほど全体採用率へ寄せる。

現在の型との近さは、同じ種族であることを前提に、持ち物が異なると距離0.7、役割が物理/特殊間で異なると0.45、攻撃型と受け型の間で異なると0.9を足し、`exp(-距離)` を重みとする。型を判定できない自分のメンバーは、その種族の全型を等しく扱う。

持ち物が既存メンバーと重なる型は、重複しない次点の型を優先する。すべて重複する場合だけ最上位型を残し、持ち物重複として表示する。

## 7. `/team/[id]` — 「類似構築」の上位チーム

最新シーズンの上位チームをすべて候補にし、現在チームの各メンバーについて同種族のメンバーが上位チームにいれば、種族一致で1点に加え、特性・持ち物・技の一致度を加える。

育成の一致度は「特性一致 1点 + 持ち物一致 1点 + 技一致数 × 0.25点」。チーム一致度は、各メンバーの得点の合計である。候補はこの合計の降順、同点なら上位チーム順位の昇順で並べる。

育成内容まで一致する候補が一つもない場合は、少なくとも1種族が一致する上位チームへ条件を緩め、上位チーム順位順で表示する。

## 8. 入力補完

種族・持ち物・特性・技は入力可能な名称を候補にする。

- 種族: 選択中レギュレーションでの使用数が多い順。使用数が同じ、または使用数がない種族はマスターの順。
- 持ち物・特性: マスターの順。
- 技: 選択種族の習得技を先頭に置き、残りの技を続ける。
- 入力中は、完全一致、前方一致、部分一致、それ以外の順に寄せる。同じ区分内の並びは前項の順を維持する。

## 変更指示の書き方

変更範囲を誤らないため、次のように指定する。

- 「`/box/ranked` は持ち物一致を2点、技一致を0.5点にする」
- 「チームおすすめで、共起スコアではなく全体採用率を常に使う」
- 「防御側の技候補は採用率10%以上に絞る」
- 「人気の計算は既存行と同じ候補も表示し、表示上限を10件にする」
- 「上位チームを人気育成の集計から外し、個人ボックスだけで集計する」
